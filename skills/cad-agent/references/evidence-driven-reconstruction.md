# 从稀疏证据重建形态与机构

适用于从照片、视频、专利图文、产品样本或残缺 CAD 推断外形、零件关系和工作原理，再建立可检查的设计候选。目标可以是复现可见形态、实现相同功能，也可以是研究原设备；这三种主张必须分别写明。项目媒体、图纸、尺寸和特定结构留在项目证据中；本页只给可迁移的工程方法。

## 五层主张，不能跳层

| 层次 | 可回答的问题 | 典型证据和边界 |
| --- | --- | --- |
| 直接观察 | 哪个轮廓、标记、部件或动作在什么视角/时刻可见？ | 原媒体版本、页/帧/区域；遮挡处仍未知 |
| 机理假设 | 哪种连接、运动副、传力或材料行为可能解释观察？ | 可同时保留多种拓扑；相似外观不证明内部相同 |
| 原理推导 | 物理、机构学和数学排除了什么，给出什么条件或范围？ | 方程、输入、单位、假设、适用域和反例；条件结论不是直接观察 |
| 可实施候选 | 候选零件、接口、轨迹和制造路径是否在规定配置下自洽？ | 原生 CAD 回读、运动/干涉、力学和工艺检查；只是本方方案 |
| 原物或实物结论 | 原设备是否确实如此构造、样机是否达到性能？ | 独立实物/厂家/测量证据；仅靠逆向模型无法升级 |

来源权威按问题划分：用户需求决定要实现什么；带定位的原图或录像证明可见内容；专利的权利要求、附图和实施例各有自己的表达范围，不能自动认定对应某一视频机器；原生 CAD 证明当前候选模型；物理定律约束可能性。多份材料若来自同一次拍摄或同一宣传稿，不按多项独立佐证计数。OCR、字幕、ASR 和图生三维是派生解释，必须回原页/原帧复核。

## 从外观走向结构

先列功能和状态，再画有身份的结构关系图：零件定义与实例、坐标基准、可见区域、可能的刚性连接、运动副、接触/夹持界面、驱动、传感、能量/载荷路径及装拆路径。视频中的“先后发生”与机械因果不同；一个零件随另一个移动，可以由刚连、闭环、控制同步或接触拖动造成。尤其不要由功能自由度直接推断电机数。

对外形，分开轮廓、体量、尺度、局部特征、材质和相机/光照。先检查候选生成模型是否能表达所见形态，再调参数；单视图的背面和深度是候选补全，不是测量。若对象由有限零件库拼成，目标形状、可用件、连接接口、安装顺序和稳定性须同时优化；对近似目标的体素覆盖不等于对原图或实物的形似度。装入路径、逐步支撑和承载能力另按[装配/力学判断](assembly-and-physics-kernel.md)核对。

## 用第一性原理补信息

对每个缺口先问：**哪个不变量、守恒关系或几何约束能改变判断？** 选择足够简单的模型，写出变量、单位、坐标系、输入来源、边界条件和适用工况，再计算。常见入口如下：

| 缺口 | 可用的原理约束 | 能得到什么，得不到什么 |
| --- | --- | --- |
| 隐藏传动或运动副 | 刚体变换、闭环约束、自由度/雅可比秩、极限位置与运动包络 | 必需的相对运动与不可行拓扑；通常得不到唯一的齿轮、导轨或电机布局 |
| 部件为何支承、夹持或释放 | 每个状态的自由体、力/矩平衡、接触法向、摩擦和能量流 | 所需载荷路径及条件性力界；未知预紧、摩擦或材料时得不到真实容量 |
| 形态和尺度缺失 | 投影几何、多视角配准、刚体/材料不变量、尺寸链与公差 | 有依据的比例、区间或等价形状族；单图像通常得不到绝对深度和实物尺寸 |
| 柔性、热或流体作用 | 本构、质量/能量守恒和相应边界 | 在参数区间内的响应和敏感性；未测物性/接触律不能由求解器自动补出 |

把“可由原理推出”分为三种：在当前假设下有唯一值；只有上下界或参数族；现有观察对多个候选不可辨识。对第三种保留并列候选，设计能区分它们的下一帧观察、尺寸测量、空载动作、局部试验或原生 CAD 检查。不要给未知量填一个最顺眼的数。一个能工作的替代机构可以满足本方设计目标，却不证明它就是原厂机构。

推导必须能被挑战：量纲是否一致；极限/零输入是否合理；换一组可容许参数是否翻转结论；去掉某连接或外部支撑后结果如何；是否有其他拓扑给出相同可见轨迹。数学闭环只证模型内部自洽。数值求解还要单独检查残差、离散误差和参数敏感性；动画只展示规定运动，不能代替力、接触或实物证据。

例如，两处接触区在录像中间距变化，直接可记录的是它们的相对位姿变化。机构学可推出至少存在实现该相对变化的自由度或顺应机制，并可排除把二者视为全程刚连的候选；它不能推出“恰好两台电机”。比较多时刻轨迹、同步误差和断电/空载响应，才可能进一步区分导轨、连杆、耦合传动和受控同步。这里没有指定任何产品的真实隐藏结构。

## 可执行证据交接

用[通用 CAD 证据合同](../contracts/cad-evidence.v1.schema.json)保存同版项目配置。原图/录像可登记为 `reference_media`，专利原件为 `patent_document`，独立推导记录为 `analysis_record`；每个来源锁定文件哈希。视频帧/时间、专利页/图和可见区域放在 `source_locator`，并由相应审阅者核对；完整性工具只验证文件和引用，不能自动看懂图像。

`visual_review`、`patent_review` 表示“我在该资料中看到/读到此内容”，其陈述范围不得越过可见内容。隐藏连接和原厂内部原理用 `engineering_inference`，关系保持 `candidate`。把可复算的数学结果存为符合[推导记录合同](../contracts/analysis-record.v1.schema.json)的 JSON `analysis_record`，写明来源哈希、方程或约束、输入的单位与身份、假设、计算方法、适用域、结果、其他解释及反证试验。数值计算还须绑定实现代码来源。用 `analytic_derivation` 和 JSON Pointer/`expected` 指向确切结果；候选主张写 `depends_on_ids`、反例写 `challenge_source_ids`，未辨识量进入开放问题。变更来源、几何或假设后，用 `cad_evidence.py --previous-packet` 找需重审的下游主张。

该工具的通过只表示来源、身份和引用完整，数学正确性须由独立计算/复核，工程性能须由对应 CAD/仿真/实测验证。项目 ABox 交给父级绑定的 Semantica 做正式语义审查；本页和证据适配器不建立第二套 TBox、CQ 或 SHACL。工艺依赖某个逆推界面、装配关系或性能假设时，经[CAD／工艺交接](cad-process-integration.md)显式传递，并在候选拓扑改变时重审。

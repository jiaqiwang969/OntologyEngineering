# 完整范围与当前执行证据的关联

`versions code-associations --input REQUEST.json` 使用原 `CodeArtifactEligibilityRequest`，由现有 `CodeArtifactEligibilityExecutor` 执行新的 `CodeScopeAssociationPort`。原 `versions code-eligibility`、注册、选择和恢复入口继续承担各自职责。

工程本体规定原对象、条件、来源和验收含义；本项规范经真实 ggen 生成共享合同，Rust 沿原资格 owner、固定独立 driver 和 evaluator 运行比较，再把实际观察接回原范围。这是后续 RRSI 版本评估所需的关联依据，不能自行批准候选。

调用需要现有 POLICY 选定的完整范围上下文及其来源、assurance 和冻结实验。没有连接时仍返回未连接；缺完整范围请求、来源变化、原件损坏或执行失败时，不产生可接受的完整关联。调用者不能提交一份自称通过的索引代替真实派发。

结果 `oev2.code-scope-association-result/1` 返回原资格结论，以及可选的私有索引引用。索引保存全部 13494 个原始身份、候选源码清单、候选自己的声明映射及源码摘要、原 owner 已核验的观察用例和 witness 引用。声明路径缺文件时明确标为 `declared_source_missing`；有文件和摘要只表示声明所指的源码存在。不会把父项、模块或导出项的通过自动传播给其他条目。

实现关系取自实验中的候选根。owner 根保存上下文、assurance 和关联回执；driver 根保存其真实进程及原始流。各引用继续按原角色解析，不把同名相对路径视作同一原件。最终关联回执发布前，先重新核候选快照，再沿原 owner 复核当前策略、上下文、工具和执行原件。

索引以独占创建方式保存，限 16 MiB，不截断条目。后续检查或写入失败时，已取得的原始执行记录或诊断索引可能保留；它们不能冒充成功的最终回执，也不宣称整个文件系统操作具备事务回滚。

原固定六例与十九项协议的边界不因新增索引改变：有限匹配可追溯到其实际原 API，全部条目的行为结论与整体资格仍保留原 `unknown`。新规则元数据、命名图和分组空值候选须经另行冻结的当前执行证据接入，不能继承旧六例资格。完整 Semantica、实际版本启用、使用反馈、恢复及工程采用继续分别验收。

正本为 `specs/modules/code-scope-association.toml`。正常结构测试与依赖原固定工具的显式集成测试分别记录；测试被忽略或资产缺失时不能计作已运行通过。同一正例若 driver 与候选清单相同，只能证明这一实际输入的关联，不能声称已覆盖两个根内容不同的反例。


## 保留历史清单的原身份

原固定实验使用 `oev2.code-public-manifest/1` 的七字段格式；当前同 schema 的清单另含固定的 `resource_profile` 和 `file_byte_limits` 两字段。原文件未变也会产生不同摘要，因此核历史输入时必须辨认原摘要域，不能把当前格式的摘要冒充旧身份。

已有来源 owner 只接纳这两种精确已知格式。完整 `CodeSourceArtifact.manifest` 先核字段、固定含义、计数与资源声明，再按对应规则完整读取当前文件并逐值核对。只有摘要的 `CodeBinaryRef` 先核程序原字节，再核当前域；摘要不同时只尝试已知原域的全新有界读取。旧记录及其 SHA 保持不变，不删字段放行、不重新签写原固定实验，也不信任调用者扩大后的资源数值。

原域实际保持所有文件最多 16 MiB；当前域仅规范路径 `generated/model.ttl` 可到 32 MiB。两者都保持总量 256 MiB、最多 10000 文件、符号链接拒绝、完整成员/模式/摘要及前后复核；中间文件复核也使用同一所选上限。新 `public_manifest`、二进制引用和构建捕获仍默认产生当前域。历史兼容仅用于本轮二进制/源码资产核验及其候选关联，其他原生生命周期的 current→current 快照不因此自动接纳旧格式。

首轮真实固定实验因清单摘要域变化在派发前拒绝，是本项缺陷的复现证据。修复后的真实 Rust 测试、原固定 driver 再执行及 CLI 接收须分别留存新原件；源码草稿、历史文件存在或资源测试通过，都不算原六例已经重新运行。

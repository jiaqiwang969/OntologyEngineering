# SDK4 selected library content

Engineering ontology defines what a selected logical library, original argument
occurrence, raw alias edge, regular target and declared TAPI dependency mean.
The SDK4 suffix in `specs/engineering.toml` is the source of five shared types,
29 fields and `CodeNativeSdkInspect4Port`; official ggen derives the contracts.
`oe-evolution::native_sdk4` implements them through the existing SDK owner and
core file/path readers. Source-bound native feedback motivates this explicit
version. The old SDK3 and native3 contracts and refusals retain their meaning.

`inspect_sdk4(root, reference)` reads a private exact artifact and checks the
canonical SDK root, four regular files and six raw leaf aliases twice. System,
c, m and proc resolve to System.B; proc/c/m retain the intermediate System alias.
Iconv and charset have distinct regular targets. Every link text, hash, mode,
path, declared intermediate edge and terminal full-file identity is checked.
Only the exact known SDK4 layout is admitted; unrelated SDK layouts/platforms
remain outside this version's domain.

`inspect_tbd_metadata4(layout)` derives complete original tagged TAPI4 documents
using the already locked Rust YAML parser. Its results bind the full source and
each exact contiguous raw byte range/hash. Complete parsed document fields and
ordered targets/exports/reexports are retained. Original arm64e strings remain
arm64e. The System file's kernel subdocument declares the observed proc symbols;
iconv declares a reexport of independent charset. These are source declarations,
not ABI execution or actual runtime loading observations.

`bind_selected_libraries4(layout, expanded_arguments)` returns one generated
`CodeNativeSdkSelectedLibrary4` for each actual short-form selected `-l` flag,
preserving original ordinal, order and duplicates. It binds logical path,
regular target and ordered alias roles. Iconv's `tbd_dependencies` binds the
separate charset file; it does not invent an explicit `-lcharset` occurrence.
The original R5 fifth finite link used only `-liconv` and observed charset as a
reexport. Forwarded/unknown library syntax is rejected by this finite binding
domain. Other actual argument semantics remain the native executor's obligation.

`check_library_search_paths4(directories)` rejects `.a`, `.dylib` and `.tbd`
shadows of System/c/m/proc/iconv/charset, including dangling symlinks. The existing
native owner must separately admit directories and repeat current source/search
checks around actual execution. This function grants no search-root permission.

Typed JSON content and parser results grant no native execution, generation,
SDK closure, loaded-image, compilation-origin, actor, Project, version-selection
or engineering adoption authority. The same existing registry/process/budget
owners remain responsible for those operations. Actual native6 integration,
full debug/signature evidence, two fresh image builds, full original scope and
other platforms still require their own current evidence. The local tests read
current original SDK bytes and preserved R5 command inputs, execute finite
synthetic negatives, and rerun original SDK3/regular-profile assertions. They
do not rerun compiler versions or the five original finite native links.

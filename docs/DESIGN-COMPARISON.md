# Controlled design comparisons in one Project

Engineering ontology fixes the parent goal, objects, conditions and evidence meaning; actual ggen generates the shared comparison contracts; the existing Rust owners execute; the existing learning owner compares the results. This is a bounded design comparison, not model training, a second Project, or automatic method promotion.

`project design-comparison freeze --input var/comparison.json --output var/new-freeze` freezes an `oev2.design-comparison/1` request, its complete parent work/3 and Project, both original design-attempt-record/1 requests, existing attempt preparations, independent intents and referenced artifacts. `verify --frozen var/new-freeze/completed.json` rechecks the current source closure without running work. `evaluate --frozen ... --output var/new-evaluation` actually executes both existing design-attempt owners into separate directories and invokes `oe-kernel::learning::design_comparison`. No browser, CAD or model is launched implicitly.

Two designs may have different objects, condition scopes and work inputs within the same exact Project. Each child must have its own original engineering-basis/2 parent-goal support, verified by the existing goal-support owner against the same frozen parent object. Its full acceptance equals the parent's full acceptance. Using two valid child objects avoids pretending that one condition snapshot has two conflicting values for the same design property. The identical-object case can be compared without inventing children. Parent facts must remain unchanged on each side; all other child facts are equal except explicitly permitted design variables. Source versions, exposure, required functions, physical mechanisms, gaps and source requests remain fixed in this profile.

Every parent acceptance has at least one frozen rule and remains in the result. A `calculated_model` rule selects original child-work calculation IDs and fixes output symbol, unit, favorable direction, nonnegative improvement threshold and design-variable bounds before execution. The current bounded variable domains are beam `second_moment`, solid-round `diameter`, and Coulomb `normal_force`. External loads, speeds and friction coefficients cannot silently become freely chosen design variables. Both calculations must use the same model, assumptions, validity conditions, failure conditions and source IDs. Their other inputs remain equal. The original `calculation_check` checks each design against its own current basis; the original calculator recomputes both results. Imported success flags or a second copy of an existing report cannot supply a score.

For example, an independently frozen model-only task can keep 10 N, 100 mm and 200000 MPa fixed while comparing I=1000 and I=2000 mm4. The existing cantilever owner yields 1/60 and 1/120 mm. A result of `improved` means this declared model's metric improved within the fixed scope. It does not prove that the new section fits, is manufacturable, meets fatigue/lifetime requirements, costs less, or improves the complete design method. Those obligations must remain in the actual engineering task.

Rules without an implemented evidence evaluator use `not_implemented`; other rule fields must be empty. Missing calculations, failed work, unsupported conditions and unknown results remain rows in the fixed denominator. Neither side is assigned an invented zero. A regression remains `regressed`; unresolved rows make the overall result `inconclusive`, retaining any separately observed model improvements. Complete comparable unchanged results yield `no_delta`. Only complete comparable results without regression and with a gain above the frozen threshold yield `improved`. Structural, source, goal, exposure or forbidden-variable changes are refused; no completed evaluation is published for that input. Cost remains `unknown`, and `candidate_is_cheaper=false` does not claim an equal cost.

The evaluator records full owner output and all remaining acceptance. `design_complete=false`, `adopted=false`, and engineering conclusion `unknown` remain separate from metric comparison. The input may contain already produced independent artifacts; their planning and reasoning can happen in parallel. This implementation executes its two actual recording operations sequentially. Native CAD writers continue to obey their existing ownership and serialization rules.

`feedback.json` binds the actual comparison result. `candidate-feedback-record-request.json` is a current existing design-attempt record request with that feedback attached to the original feedback step, ready for the same owner to retain it in another record. Freeze requires at most 31 original candidate artifacts, reserving one of the original owner's 32 slots for this feedback. A candidate already containing 32 artifacts is explicitly refused before a frozen terminal is published; no original artifact is dropped and the original owner's limit remains unchanged. This reserve does not lower the baseline's original 32-artifact allowance. It does not create another experience registry or promote a plan. The existing retrieval-order `knowledge experience` protocols keep their original scope; broader method trial requires a separately frozen hypothesis, evaluator, exposure/cost evidence and independent tasks. Current collected inCAD cases stay `development_replay`.

The private profile uses 16 MiB per file and 64 MiB per selected input or top-level output inventory, at most 256 source files, 64 rules and eight variables per rule. Output attempts retain their existing individual bounds. Full selected original bytes and hashes are kept, not truncated. The current executable is pinned in the freeze, and CLI outer completion uses the same start/end source-binding owner as design attempts. Library terminal and CLI terminal keep distinct meanings. The derived model's explicit 32 MiB generation resource profile is unchanged.

Actual generation, independent tests, real supplier-part model use, receiver validation and formal installation require their own current receipts. Full native CAD, complete inCAD migration, manufacturing drawings, physical acceptance, full Semantica and general RRSI benefit remain separate required work. The [conditional traction models](TRACTION-MODELS.md) explicitly retain the unresolved meanings of the original supplier forces.

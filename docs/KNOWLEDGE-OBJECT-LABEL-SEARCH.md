# 名称分题与完整查询

`oe-knowledge::query::run` 保留原名称、Project/context、用户问题、验收、来源和未知。构造内部名称分题时，用现有 `text::match_expression` 排除无法形成检索词的片段；排除发生在六项额度之前，后续有效名称词仍进入原查询池。数值加单位等能够形成词的原片段不被统一删除。

这修复了合法的纯数字零件名称先形成空 `Body` 请求、进而阻断有效用户问题的错误。外部 `Provider::retrieve_body` 的双空词拒绝保持。原用户查询、主题/章节池、检索顺序、必要审查和采用边界均保留；本地查询不调用模型，来源命中仍需原页和工程适用性判断。

`query_e2e` 保留四种名称及原值，核实际 replay 有有效名称池、无纯数字/符号池，包含前七个数字后有效名称的额度反例；另核外部双空词仍拒绝。当前验证限本地macOS；Windows执行和工程采用另验。该纯数字名称的原失败及空名称诊断控制保留，交付回放使用完整原名称。

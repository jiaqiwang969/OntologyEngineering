# 工程迭代与本轮目标

默认先根据背景提出本轮目标，与用户对齐后推进。用户已明确说明要完成的工作时，直接将其作为已对齐
目标；普通执行步骤不重复请求确认。尚在讨论方向时，先形成具体目标提案，继续独立的资料读取和分析。

目标提案用日常语言说明：要解决的待决问题、交付物、怎样验收、当前范围和必须保留的未知。
按任务需要补充资源边界。用户不需填写技术字段。不能把一句“继续”自动升级为整机定型、采购或生产发布。

## 多种循环共享目标、对象和证据

| 工作 | 循环应推进什么 | 局部结束条件示例 |
|---|---|---|
| 需求与功能 | 把背景转为可检验要求，澄清会改变方案的歧义 | 本轮要求和验收口径已对齐；未决项有范围 |
| 方案与机理 | 比较候选，沿物理条件与反证调整结构或工艺 | 能支持本轮方案决定，或形成明确的下一验证计划 |
| CAD 与制造 | 围绕接口、包络、公差、装夹和成本迭代 | 声明范围的原生与制造检查满足，不外推未检查的实物功能 |
| 测量与验证 | 判断证据有效性和适用性，选择能区分候选的下一活动 | 本轮主张得到足够支持、被反驳，或缺口及恢复条件已明确 |
| 工具任务 | 完成网页、文件或计算子任务并回传实际结果 | 任务专用检查满足，或返回有边界的未完成原因 |
| 经验整理 | 从成功、失败及用户纠正中形成可查阅的有条件指导，并反馈采用结果 | 指导接入任务入口并经决策回放核对，或明确无新增经验/待验证 |
| 本体学习 | 提炼确认的可复用表达缺口，保留反例和适用域 | `no_delta`，或进入已有候选治理；不自动晋升 |

这些循环不是每次必跑的固定管线。根入口按本轮目标选择；一个分支缺少条件，只限制依赖它的工作。
工具子任务完成不自动关闭父目标。正式语义仍由 Semantica 执行，经验留在项目或治理流程的相应层次。

工作检查点按[经验复盘与做梦式整理](practice-consolidation.md)决定是否整理新经验。
学习循环可以在任务未完全成功时完成一次有范围的复盘；写入笔记后还需检查下一任务
是否实际读到并采用。它不能把未完成的工程目标改成已完成。

## Jev 的作用

现有 Jev 接口负责能力候选；新增的 [浏览器工具](jev-browser-tool.md) 在网页子任务中多轮选择操作。
需要组织工程迭代时，主 agent 从当前差距、来源与依赖形成具体后续动作，再让 Jev 参与有范围的选择。
目标、验收与用户范围约束其选择，置信度不增加权限或替代证据。已确定的步骤无需额外模型调用。

每轮应说明哪项问题仍未解决、下一动作会取得什么、不同结果如何影响决定；执行后读取真实结果再更新。
反证、发现错误指标和查明作业状态都可能构成进展。单纯改写报告、页面变化或提高模型置信度不构成验收。

依既定证据结束已满足的子目标；依新事实调整方案；依明确事件等待外部条件。超时但结果未知时先核对
原作业，不直接重复写入。没有有效下一步或资源达到约定界限时保存断点，说明未完成项和恢复条件。

若要实质改变已对齐目标、验收标准或授权范围，先提出变更并与用户对齐；一般参数探索和已授权步骤
在原目标内自主推进。循环中不能静默放宽验收，或把未知的材料/参数写成已确认事实。

当前这是工作方法与目标对齐合同；尚未交付覆盖全工程领域的独立持久化循环调度器。

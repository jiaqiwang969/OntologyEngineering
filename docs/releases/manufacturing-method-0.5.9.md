# 工程本体 0.5.9：情景协同与预写 Jev instruct

调用工程本体后，助手现在默认续接情景，通过 Jev 判断必要能力，复核结果并组织
实际工作。完整版和核心版携带同一套路由实现、能力说明及预写 instruct，接收者使用
根 skill 即可进入，无需另行安装路由 skill。日常示例见[使用说明](../USAGE.md)。

## 相比 0.5.8

- 工程本体方法进入实际 Jev 请求：意图与 CQ、对象身份、功能机理、条件与证据、
  ABox/TBox、变化影响和交接依赖共同约束能力选择。
- 多项能力分别保留需要、不需要和信息不足；主 agent 读取结果、修正误选或漏选，
  再组织 CAD、制造、证据、本体建模、语义接入或外部协作。
- `build-engineering-project` 的候选比较、取证活动、资源、预算和进度方法融入既有
  工程内环与记录。旧 skill 和本地语义执行器不随包复活；历史项目按来源快照续接。
- 路由只依赖 Python 标准库，不被 Semantica 的提前导入阻断。每次记录精确模型、
  instruct/配置/代码摘要、实际请求响应和用量，部分失败只重试未答问题。
- 核心分发补齐共用合同、项目方法、本体治理及编书入口；分发模板存为 `SKILL.md.in`，
  在打包时恢复目标名，避免作者侧被发现为另一个活动根 skill。

分发版本为 `0.5.9`；Jev instruct 为 `1.0.0`，模型为 `jev-1.13.0`。Jev transport
仍为 `1.1.0`，Semantica 为 `0.6.5+oe.6`，冻结语义包与 CAD 运行组件沿用公开基线。
本轮语义学习为 `no_delta`，没有新增正式语义包或扩大物理验证结论。

## 验证与边界

独立试跑验证了从根 skill 进入后的真实 Jev 调用和结果消费，也观察到模型漏选。
同组 8 个合成情景加入 instruct 前后，与预先冻结的 agent 参考一致的维度从 63/70
变为 66/70；另一组 6 个新情景为 46/52。参考不是人工独立真值，不能将这些数字当作
真实项目准确率。完整 instruct 增加输入用量，实际成本和工程收益仍需项目实测。

本版本的文件闭合、隐私、后端、测试、新目录安装和真实路由验证由同页 Release 的
验证记录及 SHA256SUMS 绑定到具体 ZIP。此前书源与 Semantica 的绑定检查有 46/238
项未通过；本次未修改书稿或该执行实现，仍不宣称两卷书语义发布验证全部通过。

普通源码和 ZIP 不含凭据。接收者配置自己的 Jev 凭据；已有可选体验包装的来源和
绑定规则见[历史体验包说明](../JEV-TRIAL.md)。新版本不会自动继承旧包的凭据声明。
客户资料、项目本体、实际报价和会话不随通用 skill 分发。

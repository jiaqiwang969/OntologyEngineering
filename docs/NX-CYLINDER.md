# NX 受控圆柱：设计意图、原生执行与重开

本能力沿工程本体规定含义、ggen 生成共享合同、v2 Rust 执行和实际证据检查的现有流程工作。用户提出工程目的和条件，agent 整理设计意图、来源和执行映射。原生软件资格、项目设计审查和工程采用分别判断。

当前范围是一个新建实心圆柱：毫米、零件绝对 Cartesian 坐标、明确的 +Z 轴向、底面中心、直径和长度。圆柱作为滚轮和轴类零件的基础几何；阶梯、孔槽、任意轴、装配、运动副、材料、制造图和强度不由该动作完成。

## 同一执行链

`specs/modules/nx-rotating-part.toml` 为本项规范正本，共享意图和参数由锁定 ggen 生成。手写几何算法在 `oe-nx-worker::geometry::rotating_part`，本地准备沿 `oe-cad`，原生执行沿原 NX controller/worker。没有额外 CAD 调度器或语义决定来源。

`oev2 cad nx worker cylinder-plan` 读取实际意图文件，输出源绑定的参数及 input mapping；它不连接远端，也不操作 CAD。agent 将该映射交给原 `cad nx prepare → stage → run/status → fetch`。执行前必须核当前 worker manifest 的动作声明、完整文件、构建来源和原生依赖；包完整性检查本身不证明实机可用。

创建与回读使用显式新动作 `create_cylinder_solid`、`inspect_cylinder_solid` 及 `oev2.nx-rotating-part-params/1`。原创建、孔加工、参考导入和装配 fixture 的协议及用途保持。原 cad-agent 的脚本、环境、MCP、Journal runner 和旧默认配置不能作为当前入口或失败备用。

## 意图与来源

`NxCylinderIntent` 声明对象、修订、条件范围、来源摘要、特征 ID、坐标、尺寸和来源角色。`independent_software_fixture` 表示软件验证样件；`independent_design_declaration` 仍是设计声明，须通过同一 Project 的条件、来源及正式审查才能支持工程采用。原生 feature tag 只在本进程中有效，不等于跨版本的设计特征身份。

参数中的意图引用须指向 Job 已登记的实际输入文件。worker 检查文件字节 SHA、严格 JSON、意图字段和有限范围，再开始创建零件；仅回显参数中的摘要不能代替读源。执行后再次检查意图字节。`intent.path` 使用 worker 相对路径，Job 成员由执行器加 `inputs/`，不能重复加前缀。旧项目意图转换到本合同须另存派生件，保留原文件及逐项映射。

## 原生几何与保存

新实体使用安装 SDK 声明的 `UF_MODL_create_cyl1` 和 `UF_NULLSIGN`。SDK 中的 `UF_POSITIVE` 表示与已有体求并集，不能代替新体语义。

几何检查要求单个实心体、正确单位及受控模型表示，并核对真实圆柱侧面的半径与轴线、完整的三面清单、两端平面和两个完整圆边。圆边沿用现有 `model_edges` 的所属对象、完整清单、查询返回码和坐标检查；包围盒从原生返回的坐标框架重新计算，不能只信序列化的派生数值。

体积由现有 `UF_MODL_ask_mass_props_3d` 实际读取。保留返回码、体标签、单位选择、原 47 项结果、统计和实际体积摘要；摘要须与原数组一致。单位选择 4 的体积为 m³，比较时换算为 mm³。独立预期使用 π(D/2)²L，比较阈值为 `max(1e-5 mm³, 1e-6 × 预期体积)`。中心/半径/端位/界限采用固定1e-6mm，轴/平面方向采用1e-9；端圆选择保原linear1e-6mm/angular1e-8rad。整体原生body周期枚举拒未知type/subtype/bodykind、foreign/occ及sheet，完整面与边清单不能由bbox替代。这些是软件几何核对阈值，不是制造公差或计量不确定度；密度、材料和强度未据此认证。

创建动作在保存前后分别核对，并登记真实保存文件的字节身份。独立重开须在另一 worker 进程读取该文件的原字节，使用同一意图重复检查。`inspect_cylinder_solid` 不请求保存输入。两份结果必须由上层核对实际文件、Job、程序、进程及创建时间；同一进程的再次查询不能算独立重开。

## 验证范围与继续使用

本项以两个预先独立规定尺寸和非零原点的样件检验几何、来源、保存与重开，并保留缺面、错尺寸、错坐标、源漂移、不完整回读等反例。代码测试不宣称实际 NX 成功；各次当前构建、实际原生执行和正式安装情况从 `var/maintenance/status.json` 定位，不继承旧 worker 的通过记录。

这项软件能力可以用于准备新的滚轮或轴设计。实际项目仍需明确载荷、支承、摩擦、材料、配合和制造检验要求，形成有来源的设计输入，再接装配、图纸、BOM、计算和实测。既有实际零件的原要求及未知条件、实际项目的最终精度测量要求不会因单个圆柱验收而关闭。运行中的失败与修正回到现有维护和经验流程；未证实的收益保持未证实，不另建经验账本。

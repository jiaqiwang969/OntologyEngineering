# 有证据的自进化：避免目标、语义与验收失真

用于修改 skill、规范、模板、Rust 实现、工具编排或经验机制。用户以自然语言表达目标；agent 整理候选、来源和验证。整体仍为重构中：Rust 已实现有界操作计划的实际候选流程，统计校准、任意代码演化和独立迁移能力尚未验收。

## 方法、候选表达与实际评估范围

RRSI 根据真实反馈检验有限改进。先回到原目标和过程，辨认问题发生在概念理解、任务解释、规范表达、实现还是实际使用，再提出可检验假设；已有方法足够时修正实例或记录 `no_delta`。工程本体论对含义和依据的判断、ggen 的表达与生成、Rust 的实际行为以及工程结果各自保留范围，改进结论需要说明具体改善了什么。

| 层次 | 本文的作用与边界 |
|---|---|
| 方法原则 | 用真实过程、固定目标、独立预期、失败与反馈组织候选比较，可指导 Skill、规范和实现改进的研究。原则本身不构成收益证据。 |
| 候选表达 | 下文设计模板说明目的、假设、改动、评估、范围和恢复；其表达范围大于已经实现的协议，字段存在不表示评估器能执行对应试验。 |
| 实际评估 | 本文检索计划协议 `/2` 的有限变化是 `retrieval_order: context_first \| query_first`；`/3` 区分原来源与派生 RDF 的评估绑定，不把它扩大为任意方法评估。操作、重试、恢复及其他边界以各节原合同为准。显式探索另按 [Project/work/Harness 的可判别验证](../docs/ENGINEERING-EXPLORATION.md) 的实际支持范围使用。 |

以下概念辨析评价方法用于设计候选试验，未新增执行协议，也不表示现有评估器已经能自动评价这些能力。具体执行前还需核对评估方法、工具与判据是否具备。

## 用可观察选择检验概念辨析

评价 [设计方法](design-method.md) 的改进时，观察 Agent 对任务、依据与下一步行动的选择，以及条件变化后的修正。保留简短的判断依据和实际结果；无需披露内部推理过程，也不按复述术语或填写表格评分。可预先准备名称改变但关系相同、同一产物角色变化、新条件使原依据失效、局部已有依据而总体未完成，以及需要探索才能获得依据等情况，检查判断是否与来源和目标相符。

候选冻结后，在相同模型、工具、任务原件、预算及上下文条件下比较；独立评审依据原件预定可接受行为，允许多条合理路径并保留歧义。已用于提出或修改候选的案例属于开发材料，独立任务及来源族另行保留。记录所读来源、选择、实际动作、修正、完成范围、错误和成本；失败、超时与未完成保留在分母。变更判据或取得方式时另建可比较基线，不将文档更短、来源匹配或单次成功直接解释为方法收益。小规模重复可以提供诊断，泛化结论按实际覆盖限定。

## 借鉴来源与适用边界

核对来源：[RRSI 论文 v2](https://arxiv.org/html/2609.24972v2)，官方源码固定到 [be50316e1db05914068a973f322770ef08ed7ba1](https://github.com/google-research/rrsi/tree/be50316e1db05914068a973f322770ef08ed7ba1)，2026-09-23 的提交。研究副本和执行记录放在 `var/`，不进入分发。借鉴方法，正式执行继续使用本项目 Rust；没有引入上游 Python、模型账号或基准运行依赖。

RRSI 研究冻结模型外的 Harness 演化：保持组件可改，约束提出与选择候选的过程。以下对照将上游机制与本项目要求分开。

| 上游机制与源码 | 本项目采用方式 |
|---|---|
| [schedule.py](https://github.com/google-research/rrsi/blob/be50316e1db05914068a973f322770ef08ed7ba1/rrsi/schedule.py)：逐轮减少独立改动数量 | 候选围绕可检验假设组织，逐项说明机制和影响。一次机制可以跨多个文件；不要按行数或文件数计数。仅有预先定义的轮次实验才采用退火预算 |
| [history.py](https://github.com/google-research/rrsi/blob/be50316e1db05914068a973f322770ef08ed7ba1/rrsi/history.py)：记录假设、改动、测量与结局；停滞时探索未尝试组件 | 读取包括失败和拒绝在内的历史；重新尝试须说明新证据或条件。批量候选的收益归属于整体，不能给每个组件伪造独立贡献 |
| [critic.py](https://github.com/google-research/rrsi/blob/be50316e1db05914068a973f322770ef08ed7ba1/rrsi/critic.py)：评估前查任务泄漏与取巧 | 检查共享实现是否硬编码案例答案、探测评估器、读取保留答案或改成功判据。静态线索和模型意见分别登记，不能作为无泄漏证明 |
| [selection.py](https://github.com/google-research/rrsi/blob/be50316e1db05914068a973f322770ef08ed7ba1/rrsi/selection.py)：历史最好分数的噪声下限与成本规则 | 随机能力用重复基线校准，在同一评估合同下比较；工程硬约束先逐条满足。确定性缺陷用固定反例和独立预期验收，不拿统计噪声放宽单位、公差或身份要求 |
| [evaluate.py](https://github.com/google-research/rrsi/blob/be50316e1db05914068a973f322770ef08ed7ba1/rrsi/evaluate.py)、[eng/adapter.py](https://github.com/google-research/rrsi/blob/be50316e1db05914068a973f322770ef08ed7ba1/domains/eng/adapter.py)：预定任务/重复次数，工程适配器补齐缺失槽位 | 固定任务和来源族清单、重复次数、分母及权重；失败/超时/未执行保留状态与原因，不因删槽位提高成功率。统计上的零贡献不改写工程 unknown 为已执行失败 |
| [gitops.py](https://github.com/google-research/rrsi/blob/be50316e1db05914068a973f322770ef08ed7ba1/rrsi/gitops.py)：隔离候选，只保留获选版本 | 在独立候选根或真实 Git worktree 运行，按既有发布合同接收获选版本，失败保留上一个工作版本。记录实际提交、脏文件及来源清单；普通接收副本不冒称 Git worktree |

上游规则不能原样充当工程验收：`selection.py` 的噪声区间分支允许成本或新颖性参与接纳；`evaluate.py::relative_cost_change` 在任一成本缺失/零值时返回 0。本项目缺成本仍为未知，新结构只能支持探索，不能证明已改进。上游工程 guard 针对有效输出率/无提交率，未证明本项目的单位、来源、版本或工程采用条件。RRSI 提供减少过拟合的经验方法，不能保证未来升级永不失真。

## 每轮需要保持什么

先绑定目标、适用条件、术语与单位、必要功能、接口、来源、独立预期及评估规则的版本。一般实现选择可自主处理；改变用户目标、范围或验收口径时说明并对齐，建立新基线，不把规则调整混成旧规则下的实现提升。

以下条件不能由其他案例更高的分数抵消：对象/字段含义一致；单位和精度正确；版本/来源/条件与当前执行相符；失败、部分和未知如实表达；必要反例与既有功能保留；副作用和治理权限有效。删减候选也须接受这些条件，不能因最近无评分收益删除来源、恢复、预算或错误处理机制。

共享经验记录可复用机制、适用边界、反例和来源。真实项目可以保存项目记忆，但要绑定该项目身份与条件，不能把案例答案、私有事实或一次模型判断写成跨项目默认事实。这比禁止一切记忆更适合持续工程工作。

## Agent 填写的候选设计模板

这是 agent 从自然语言整理的设计说明。`specs/engineering.toml` 已定义 `ExperienceCandidate`、`EvolutionAssessment` 与 `ExperienceState`，经 Rust → RDF → 锁定的真实 ggen 生成；复杂选择逻辑在 `oe-kernel::learning`。冻结/评估合同是有界内部 JSON 协议，命令见 [实际入口](../docs/USAGE.md)。用户不手填合同。本表的完整版本演化范围大于当前操作计划协议，未实现项不能由字段存在代替。

| 字段注释 | 含义、填写要求与验收 | 拟定 Rust 映射 |
|---|---|---|
| `@field goal_binding @required @format sha256` | 用户目的、范围与不变条件的版本；链接原需求。修改目标须形成新基线 | 摘要身份及来源引用 |
| `@field baseline/candidate @required` | 旧工作版本、候选源码、规范、模板、锁和产物的身份；不能只用版本字符串 | 有界清单与摘要 |
| `@field compiled_binding @required` | 执行文件及其编译来源、目标、feature、适用状态和未覆盖项。磁盘 source-map 不能代替编译来源 | matched/mismatch/incomplete/not_applicable；后两者不等于通过 |
| `@field hypothesis/edits @required @write agent` | 复现、预期机制、独立改动、涉及功能/模块/条件及被历史否定的假设 | 候选和原子改动记录 |
| `@field evaluation_binding @required` | 案例/原预期/来源族分组、重复次数、权重、分母、评估器、平台与预算的冻结身份 | 有界槽位清单；拒绝重复、缺绑定或不相容比较 |
| `@field evidence @required` | 逐槽执行、结论、覆盖、失败原因、输入/产物/回执摘要；硬条件逐条有证据 | 复用正式语义、测试、工具与治理回执；不接受自声明 passed |
| `@field gain/noise/cost @format explicit-units` | 收益、重复基线的噪声估计、token/时间/内存/调用成本分别度量；方法及单位不省略 | 有限数值与显式 unknown；不跨指标直接相加 |
| `@field transfer @required` | 开发回归、保留案例、跨来源/条件验证分别记录；未验证保持未知 | 分组验证记录和证明范围 |
| `@field verdict @required` | rejected/inconclusive/exploration/admissible，与执行成功、治理晋升及工程采用分开 | 显式状态；任一必要项 unknown 时不得正式晋升 |
| `@field lineage/recovery @required` | 前驱、拒绝理由、规则调整/实现修复、恢复办法和下一轮反馈 | 新事件关联旧事件；重审增加新记录，旧结论保留 |

流程：复现与影响 → 隔离候选 → 泄漏/目标/身份检查 → 真实生成、编译与行为 → 覆盖及硬条件 → 收益、成本与泛化 → 选择或保持旧版本 → 新版本记录 → 实际反馈。探索候选可继续调查，但不自动替换工作版本。

## 当前 Rust 候选协议

`knowledge experience freeze` 将目标、真实基线/候选计划、来源和新依据、原始及重定位评估合同、同一 Project/Binding/证据、规则包、评估器源码和实际执行文件保存到独立 `var/candidates/<id>/`，最后写冻结清单。源与冻结字节变化会被拒绝。拒绝假设再试须引用原拒绝和新依据；改变输入格式也建立新基线，不改旧冻结内容。

新 `/2` 允许无收益拒绝后的显式基线恢复：复制冻结基线原字节、追加 Restore，再运行该基线取得反馈。拒绝事件始终保留，恢复不改接受判据，也不自动重试；旧 `/1` 仍保留原来的 active-trial 恢复边界。

旧 `/1` 计划的两种模式和原执行器保留历史身份，不能作为当前有效方法基线。新 `experience-freeze/2` 使用生成的 `MethodPlan`、`RetryIdentity`、`ProjectReviewContext`；双方计划 `/2` 都保留 `required_semantic_review`，仅支持 `retrieval_order: context_first | query_first` 这一有限改动。不能在计划里嵌入答案、改单位、换判据或自报分数。固定执行器为本次编译的 `oev2.rust-semantic-kernel@<包版本>`，同时冻结实际执行文件和评估器字节；1–5 次重复、最多 16 案例和 256 个顶层检查。目标、必要检查、精确规则与执行器字节相同才可比较；没有独立暴露证明时只接受 `development_replay`。

评估复用现有 Project 和 `SemanticReviewPort`，逐项核对对象/修订/条件/来源与必查项。`/2` 案例为当前使用，双方须通过当前 Project 内容绑定和 RDF 条件声明检查；历史范围/条件名不能替代当前内容一致。原物理条件缺项仍为 unknown，不被内容检查改写。检索计划消费同一实际来源池、索引摘要和名额，在独立冻结的必要引用/不适用页清单下比较；检索收益不能抵消必要审查或当前身份缺口。失败槽位保留在分母，缺成本为 unknown；墙钟纳秒、顶层检查数和选择回放的零模型调用仅覆盖本次 Rust 检查/选择，不能推断整项工程费用或模型效率。

有诊断收益且保持硬条件才能 `accept-trial`；无收益返回 `no_delta`，取巧计划拒绝。决定时重新评估并核对稳定字段；只排除墙钟测量波动，结论、输入、失败和规则不得变化。`apply` 保存另一任务的实际输入和新回执，`recover` 恢复冻结基线原字节；再次 `apply` 运行的是恢复后的基线。状态事件追加到 `var/state/knowledge/experience-events/`，使用生成状态机与摘要前驱。

操作方法改进可获私有诊断试用；行业本体候选已有表达足够时 `no_delta`，非空语义变化沿既有治理验收；实现修复需要独立复现和源码/编译/原回归证据，当前方法评估器不宣称能评价任意代码修复。评估器或规则变更先单独建立基线。候选试用不切换整个 skill，不授予行业晋升或公开发布。当前事件锁是 Unix 后端，Windows 候选流程未验。

`/2` 重试先登记不可覆盖的实验：项目、对象、适用范围、目标与稳定假设 ID/内容。在同一知识事件历史中保守关联相同项目/对象/范围/种类的拒绝及相同假设内容；完整引用真实原 ledger 事件，新增依据必须可读取、摘要匹配且不同于此前来源与新依据。遗漏、伪造、复制事件冒充原记录、重复旧依据、改假设文字均拒绝。完整引用与新增字节仅允许建立新候选，不授予改善结论；不同实验的自然语言机理等价尚无自动判定。原 `/1` 候选、失败、执行器和冻结字节不迁改。

## 原来源与派生模型的评估基线 `/3`

`experience-freeze/2` 的重试历史合同保持不变；新评估可明确选 `experience-evaluation/3`。它分别绑定原来源字节与派生 RDF 字节，沿正式 Rust port 的 `sourceSha256` 关系核对焦点；不能把合法规范化产物要求成与原件同一摘要。Project 必须登记原来源，冻结的 RDF 仍逐字节核验。原 `/1`、`/2` 的输入、判据与历史执行不改写；协议变化建立新的冻结评估基线，不能继承旧提升结论。

`/3` 的必要检查是精确规则查询/形状、`bound_focus_context`、当前 Project/条件内容以及当前对象的全部工程检查。缺一项、额外改判据或超完整检查预算均拒绝；双方仍保留必要审查。数值超限、当前条件冲突、承托/时基未知等沿同一个 kernel 保持具体原因和下游影响。执行完成与原页相关性、模型可用、工程采用分别取证。没有检索对照、实物证据或独立任务时，局部诊断保持 `no_delta`/unknown，不宣称方法或泛化改善。

## 泛化和防自我改题

已有 452 原场景和开发期间查看过的反例是回归依据，不能称保留集。按来源族分组，避免同一书页、供应商模板、派生对象或重复内容分别落入开发/保留两边；未知的来源关系单独报告。跨单位、条件、对象和平台的验证各按实际覆盖声明。

保留案例不参与调参数或选当轮赢家；仅在冻结候选上按预定方案验证，拒绝暴露的候选后不得把同一已公开反馈继续称为未见验证。记录暴露历史，转入开发回归并建立新的独立保留依据。同一 agent 再看自己的答案不构成独立预期。

评估器、oracle、权重、案例族或目标的调整作为单独候选建立版本；原预期和反例保留，不与被评实现一同修改来提高分数。共同错误仍可能发生，所以生成一致性还须配合独立数值、行为、原生回读与工程证据。

## 验收与当前实现边界

复用现有 Rust 源码检查、编译来源绑定、影响闭包、真实 ggen 漂移/事务、语义 unknown/来源绑定、本地治理权限及接收身份。已有闭合计划的冻结、critic、固定分母、实际评估、试用/拒绝/恢复和追加反馈；尚未实现任意代码泄漏审查、自动调度、成本/噪声校准、独立保留集管理、删减贡献实验和整版本切换。

固定验收包括：高分候选若改变单位/含义仍被拒绝；缺失或超时不能缩小分母；未知成本不能宣称更便宜；修改评估合同不能继承旧比较；给案例硬编码答案不能晋升；旧执行不能冒充修改后的正常化算法；拒绝候选后旧工作版本和历史仍可追溯。本轮实际保留了无收益拒绝、夹带答案/单位改写拒绝、恢复后基线行为、拒绝重试与编译来源反例；完整任意代码泄漏和查询超时恢复仍未证明。

已修复正常化编译来源缺口，正式执行拒绝陈旧源码或 CLI 生成合同；原 source drift/missing checker 和生成失败保留旧版本的实际 ggen 反例仍通过。编译绑定的外部 crate 源字节、全部传递 feature、原生依赖闭包仍开放。ggen 保持规范到代码/说明的一致性；Rust 门禁执行明确规则；独立验证和工程来源检验规则与结果是否正确。三者共同参与升级，各自记录证明范围。

当前工程前提检查也属于不可抵消的必要条件：已声明的模型冲突、资料适用冲突或未知边界使当前用例不满足采用条件。评估器实现升级单独建立编译身份和基线；旧冻结候选只能保留其原执行身份。再次尝试旧假设时，完整拒绝引用和可核新原件只准许调查，不能使 no_delta 变成收益或行业晋升。

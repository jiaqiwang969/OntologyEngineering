# 工作规范、版本与隐私

## 规范从哪里来

本模块规定记录与判断的方法。客户要求、适用外部要求、企业已有制度和项目假设要逐项登记其来源、对象、版本、范围和采用状态。不要把本模块的示例字段、他企做法或待讨论建议写成当前企业已批准的标准。

用 [规范登记模板](../assets/templates/norm-register.json) 记录本轮真正影响决定的规则。发生冲突时比较各来源的适用范围与权限，保留反证和处理决定；不采用“最新消息最高”或一条固定来源排序解决所有冲突。

| 环节 | 方法约定 | 留下的可复核结果 |
| --- | --- | --- |
| 接收资料 | 保留原件；提取值与原表单元格、页项或消息对应 | 来源、版本、接收与源日期、覆盖范围 |
| 信息筛选与深读 | 按决定价值查读资料及对话；合并已核实重复，保留条件、冲突和反证 | [筛选依据](high-value-documents.md)、已读范围、新增知识、判断变化及未决项 |
| 识别要求 | 原话、解释、估算、计算和决定分开 | 明确/部分/冲突项与适用对象 |
| 澄清 | 查旧答复再问；说明问题怎样改变决定 | 子问题、关闭条件、部分回应和未决范围 |
| 工艺检验 | 明确产品状态与受检特性；顺序从依赖而来 | 工序前后状态、判据、检验覆盖及重开条件 |
| 能力核对 | 将可调配、名义配置、实际能力分别记录 | 能力证据、条件预算可用范围与待验证项 |
| 核算 | 统一版本、数量、交付和费用范围 | 包含/不含/未知、一项一处归属及计算依据 |
| 方案修订 | 新证据先入状态，旧版不覆盖 | 触发、变化、影响、核验、后继关系 |
| 采用与交付 | 评审意见绑定具体版本及范围 | 内部草稿/条件预算/已认可范围/发送状态 |
| 学习 | 定位事实、方法、语义或工具层 | 条件、反例、验证及采用结果或 no_delta |

## 版本不是单向增加的确定性

方案可以因新增事实变得更确定，也可因旧结论被证实只是转述而重开。用 [修订记录](../assets/templates/revision-record.json) 区分：

- **证据变化：** 原件取得、测量增加、来源被纠正，更新相关结论及范围。
- **要求/范围变化：** 版本、数量、交付或验收调整，重查路线和核算。
- **解释变化：** 同一原话被重新理解，保留两次解释及改变依据。
- **工具/视图变化：** 映射、公式、标注或排版修正；检查实际影响，不能统称“仅排版”。

编号沿用企业现有约定，不强制某组字母或版本次数。每版最低能追溯：来自哪个快照、为什么改、改变哪些条目、哪些保持有效、未决条件、此次检查范围。源记录没有变化且只改呈现，不制造新的工程事实。

反馈指出报告问题时，按以下线索追查：**定位版本和条目 → 原始证据 → 对象与状态 → 规则和依赖 → 视图映射 → 原检查覆盖**。错误可能来自输入、解释、规则、缺失依赖、计算或输出；定位后修相应层，保留正常对照与反例。

检验新报告自己的冻结输入与生成结果。旧本体案例通过，只能证明其声明范围；不能证明所有历史报告、未接入生成器或新方案已检查。依赖缺失本身也记为待处理项。

## 可复用内容与私有内容分开

| 留在项目私有工作区 | 可以进入方法模块 |
| --- | --- |
| 客户/供方/人员身份及联系方式 | 通用角色及职责边界 |
| 图号、CAD、BOM、原报价、设备清单、消息 | 抽象对象关系、提问方式和决定过程 |
| 精确金额、尺寸、数量、工序组合和日期 | 经审查的通用条件或重新构造的合成示例 |
| 原始文件路径、文档属性、源文件哈希映射 | 不指回私有材料的案例编号及复用条件 |
| 原件、截图、头像、隐藏表、批注、附件 | 重新编写的纯文本案例与空白模板 |

采用允许导出的文件清单。检查新增文本、链接、文件名、JSON/YAML 值和包内全部文件，避免夹带符号链接或隐藏文件。需要真实来源追溯时将对应表保存在私有项目；通用案例无需携带可反查客户的映射。

关键词检查发现直接标识；人工还需审查稀有结构和数值组合能否重新定位项目。合成数据显式标记且重新检查逻辑，不能冒充现场结果。示例流程仅说明判断方法，不成为其他产品的默认工艺。

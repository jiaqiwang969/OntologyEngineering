# 单调与非单调推理示例
# Monotonic and Non-monotonic Reasoning Examples
#
# 推理是本体的核心能力：从显性知识推导隐性知识
# 单调性（Monotonicity）是划分推理机制的重要维度

# ==============================
# 1. 单调推理 (Monotonic Reasoning)
# ==============================
# 定义：新增知识只会增加结论，不会推翻已有结论
# 经典逻辑（一阶逻辑、描述逻辑）都是单调的
# OWL DL 推理器（Pellet / HermiT）遵循单调性假设

# 已知公理（TBox）：
CNCLathe ⊑ CNCMachine             # 数控车床是数控机床
CNCMachine ⊑ ProcessingEquipment  # 数控机床是加工设备

# 已知事实（ABox）：
CNCLathe(Lathe_001)               # Lathe_001 是一台数控车床

# 单调推导（子类关系传递）：
CNCMachine(Lathe_001)             # 推论1：Lathe_001 是数控机床
ProcessingEquipment(Lathe_001)    # 推论2：Lathe_001 是加工设备

# 单调性保证：之后无论向知识库添加什么新事实
# （设备故障、位置变更、新的分类公理），
# 推论1、推论2 永远成立，不会被撤销

# ==============================
# 2. 非单调推理 (Non-monotonic Reasoning)
# ==============================
# 定义：新增知识可能推翻已有结论（可撤销推理，Defeasible Reasoning）
# 适用于"默认假设 + 例外"形式的工程知识

# 默认规则（Reiter 默认逻辑）：
Equipment(x) : available(x) / available(x)
# 规则解读：如果 x 是设备，且"x 可用"与知识库一致（无矛盾信息），
# 则默认推出 x 可用

# 阶段1 —— 知识库仅有：
Equipment(Lathe_001)
# 默认推论：available(Lathe_001) 成立 ✓

# 阶段2 —— 新增事实与规则：
hasFault(Lathe_001)               # Lathe_001 出现故障
∀x: hasFault(x) → ¬available(x)   # 故障设备不可用
# 撤销推论：available(Lathe_001) 被推翻 ✗
# 对于没有故障记录的其他设备，仍默认其可用
# 这种"结论收回"是单调逻辑无法表达的

# ==============================
# 3. 开放世界假设与封闭世界假设
# ==============================
# OWA (Open World Assumption)  —— OWL / 描述逻辑采用
#   未声明的事实 = 未知（可能为真，也可能为假）
# CWA (Closed World Assumption) —— 关系数据库 / Prolog 采用
#   未声明的事实 = 假（否定即失败，Negation as Failure）

# 示例：知识库中只有一条事实
producedBy(Product_A, Lathe_001)

# 问题：Product_A 是否由 Mill_002 生产？
# OWA 回答：未知（除非显式声明 ¬producedBy(Product_A, Mill_002)）
# CWA 回答：否（知识库未记录即视为假）

# 工程影响：
# 在 OWL 中校验"设备未分配任何任务"这类否定条件时，
# 需借助 SPARQL 的 FILTER NOT EXISTS（局部封闭世界）实现

# ==============================
# 4. 工程应用对比
# ==============================
# 单调推理适用场景：
#   类层次分类、一致性检查、设备能力匹配
#   （要求结论稳定可靠、可审计）
# 非单调推理适用场景：
#   默认配置（设备默认可用）、异常处理（故障撤销可用性）、
#   计划修订（新约束到达后撤销原有调度结论）

# 实现说明：OWL 标准推理器只支持单调推理；
# 非单调能力需在应用层借助规则引擎实现，
# 如 SPARQL 更新、SHACL 规则、Jena Rules，
# 或支持否定即失败（NAF）的 Datalog 引擎

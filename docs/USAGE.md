# 使用工程本体

把解压得到的整个 `ontology-engineering/` 目录安装到助手的 skills 目录。保留内部的
`scripts/`、`references/`、`ontology_engineering/`、`skills/` 和 `runtime/`，不要只复制
`SKILL.md`。完整版和核心版都包含默认 Jev 路由和预写工程本体 instruct。

## 日常调用

直接告诉助手：

> 请调用 $ontology-engineering，结合前面的讨论，分析当前问题并推进下一步。

补充目标、已有材料和本轮限制即可。例如：

- “根据这些需求比较可行方案，先讨论机理和关键约束。”
- “根据这份图纸重建零件，检查装配接口和加工可行性，并交付原生 CAD。”
- “这批定位销压装后出现崩边，结合记录判断先补什么证据，本轮先不改 CAD。”
- “把这些设计、试验和返工记录组织成可追溯的项目知识，判断是否需要本体化和 Semantica 接入。”

助手续接情景，通过 Jev 判断能力需求，读取并复核结果，然后调用实际需要的内部
skill、外部专长或 Semantica 入口。内部模块和协作顺序由任务的输入、产出和依赖决定。
新反馈会更新受影响的判断。换会话时提供项目路径或关键记录，便于续接原对象与版本。

涉及 CAD 时，根入口按本轮产出选择内含的 `cad-agent`：原生零件、装配、机构、图纸
和几何回读由它执行；工艺、公差或检验影响方案时，再联动制造与证据方法。可以说明
使用的 CAD 软件、输入文件、交付格式以及这轮是否允许修改模型。只讨论旧 CAD 证据
的支持范围时，不会因此自动开始改图或仿真。

## 首次准备

- Jev 路由使用 Python 3.11+ 和标准库，可在安装 Semantica 前运行。
- 普通分发包不带凭据。把自己的 Jev 凭据保存在本机 `~/.codex/api-jev.md`，文件权限
  设为 `0600`；维护者也可通过调用入口的 `--credential-file` 指定本地凭据文件。
  凭据不进入 skill、项目记录或 GitHub。
- 需要正式语义发现与执行时，按[分发说明](PORTABLE-DISTRIBUTION.md)安装包内锁定的
  Semantica。CAD 软件、许可和设备配置按实际任务准备。

凭据缺失、服务不可用或用户禁止资料外发时，助手应明确说明 Jev 未完成判断，并继续
能处理的工作。模型候选不替代工程证据、授权或 Semantica 的正式语义审查。

技术调用和记录格式见[情景路由](../references/context-routing.md)。输入由助手整理，
日常使用无需手填 JSON。核心版省去两卷书源码；书内检索及已有书稿修订需要完整版
或相应受控书源。

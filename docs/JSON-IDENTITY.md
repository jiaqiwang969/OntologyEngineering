# JSON identity under generated contracts

A literal object whose key is `$serde_json::private::Number` or `$serde_json::private::RawValue` remains data; it cannot silently become a primitive number or another raw fragment. Preserving that identity grants no Project fact, engineering acceptance, version qualification or learning authority.

`semantica-json` is the single neutral interpretation/serialization owner; `semantica-contracts::json` reexports that owner for generated field hooks. `oe-wire::json` delegates its original strict/canonical/ordered operations and retains its existing SHA wrapper. The native provider protocol parser delegates its original protocol profile. Engineering contracts depend on neutral contracts; wire depends directly on the lower JSON crate. This keeps the source normalizer/bootstrap buildable before generated contract files exist. Both neutral crates depend on neither `oe-*` nor runtime. Moving the algorithms does not introduce a second Project, Dataset, registry, model account pool or history.

The existing input profiles and DTO identity boundary remain explicit. Strict wire input rejects duplicate keys, nonfinite floats and its original nesting overflow, and normalizes finite float values for the existing Python-compatible snapshots. The original protocol profile retains last-key-wins, exact integer/number tokens, finite floats and its original nesting and caller byte bound. Sorted canonical and insertion-order encoding retain their distinct purposes and frozen scalar spelling. The DTO identity profile retains the original arbitrary-precision JSON numbers, including magnitudes such as `1e400`, without importing provider finite restrictions. The pinned serializer retains its original number representation (`1e+400`, integer `-0` becomes `0`). Byte/source SHA is separate from interpreted JSON value identity.

The finite Rust type grammar marks exact `serde_json::Value` leaves recursively inside `Vec` and `Option`. The RDF normalizer emits structural metadata, and both locked real-ggen templates emit the same neutral RawValue field hook. Named contracts use their own generated fields, with no type-name prefix inference. The hook constructs Value and recursive containers directly rather than passing a preserved object through Value deserialization again. It supports raw JSON (`from_str`, `from_slice`, `from_reader`) and a Value whose original identity is still intact (`from_value`). If a caller already corrupted the input into a number before this boundary, the missing original object cannot be reconstructed.

Only an outer `Option` receives serde `default`, preserving the original absent/explicit-null behavior. An inner Option element represents null as None; required Vec fields still reject absence, null and wrong shapes. Existing outer unknown-field rejection remains. The recursive field conversion has an explicit 128-level implementation bound; equivalence for arbitrary deeper Value trees or other serde data formats is not claimed. This is a JSON-specific boundary.

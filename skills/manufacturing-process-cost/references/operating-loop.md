# 从不完整询问到可继续的工程工作

## 先找决定，再找信息

接单者通常先知道“大概做什么、希望更快或更便宜”，未必知道全部接口、验收和成本边界。先把这次决定说清楚，再沿依赖向下查：哪条要求影响哪道工序，哪道工序需要什么能力，哪项缺口会改变路线、价格或交期。

问题的优先级取决于决定影响、不可逆后果、等待时间和取得证据的代价。不要为了表格完整而先追问无关细节，也不要把能继续的独立工作全部挂起。

| 缺口 | 获取方式 | 面向业务或技术的问法 |
| --- | --- | --- |
| 已有资料缺失 | 查原件、附件、历史答复 | “这次价格按哪版图、做到哪一步？” |
| 隐性经验 | 请专家讲具体正常例与失败例 | “这一步主要防什么问题？遇到哪种情况要换做法？” |
| 说法含糊 | 定位对象并回读解释 | “这里说的检测，是加工后的尺寸检查，还是交付前的验收？” |
| 多源冲突 | 对比来源、适用范围与决定权限 | “这两份要求对应同一版产品吗？本次以哪份受控要求为准？” |
| 能力未测 | 查相近记录或安排最小验证 | “这台设备做过相近要求吗？现有记录还不能覆盖哪一项？” |
| 证据过时 | 查变更触发和有效性 | “这项结果是在变更前取得的；变更是否影响它所证明的性质？” |

发问前查已有回答。一个问题包含多个子项时逐项关闭；“已回复”不能替代“已解决”。原话和解释分开，必要时用简短回读确认含义。

客户对话及附件按 [高价值资料与信息筛选](high-value-documents.md) 处理：合并已核实的重复信息，深读会改变决定的原件；保留条件、反证、分歧和沟通状态。将关键内容接回判断和下游影响，再提出尚未被回答的问题。

## 理论如何引导下一问

不要把概念表变成固定问卷。沿一项主张的关系查缺失项：

> 哪个角色，在什么使用情境，对哪个版本、哪种状态，提出什么要求或判断？依据是什么？支持哪项决定？条件变化会影响哪些下游结果？

例如“有设备，可以自己做”：设备身份可能已知，可调配可能已确定；加工空间、夹持、过程能力、检验覆盖和节拍仍需分别核实。后一轮应查这些缺口，避免再次问能否调配。

例如“客户已经同意”：需确定同意的是旧方案的交期、产品接口、预算，还是新版本的全部范围。一个回复不能扩展成其他决定的批准。

如果旧概念无法表达差异，先保存实例、缺失关系、暂行处理与影响；不要把新信息硬塞进已有类别。再评估是否需要语义增量。

## 一次调用如何接到下一次

| 环节 | 最小留存 | 返回关系 |
| --- | --- | --- |
| 续办 | 当前决定、输入快照、方法版本、上次未决项 | 复用旧答复，检查其当前适用范围 |
| 取得信息 | 问题、来源、对象范围、原话与解释 | 回答具体子问题，暴露新问题 |
| 更新 | 新事件、关闭/重开项、假设变化 | 影响工艺、资源、成本与输出 |
| 方案 | 版本、共同比较范围、条件与验证计划 | 允许反馈定位到具体条目 |
| 反馈/执行 | 目标版本、已认可范围、实际记录 | 验证或推翻原估算与路线 |
| 交接 | 当前结论、剩余条件、责任角色、唤醒条件 | 下一次从这里继续 |

渠道状态保留草稿、已发送、发送失败或不可用、已收到、已理解、部分解决、已解决等区别。按照会话已有授权使用指定身份、收件方和内容范围；渠道不可用时保存未发送稿并继续独立工作。收到重复、迟到或无法匹配的消息先核对来源和目标版本。

## 项目工作与经验学习

项目快循环是“发现 → 沟通或验证 → 更新状态 → 方案 → 反馈 → 再发现”；经验循环是“定位新知识 → 脱敏 → 明确适用条件和反例 → 验证 → 采用”。项目工作不必等待通用语义包晋升。

| 发现落在哪里 | 处理 |
| --- | --- |
| 订单、设备、供方的具体事实 | 留在私有项目，按来源和范围核对 |
| 已有方法或规则已经覆盖 | 增加使用证据，语义学习记有理由的 `no_delta` |
| 提问或工作顺序可改善 | 形成方法候选，用独立任务检查效果后采用 |
| 新概念、关系或约束缺陷 | 走根 skill 的完整 Semantica 变更流程 |
| 报告映射、计算或生成器出错 | 修对应工具，复查受影响输出；不预先断定本体有错 |

跟踪可比较的效果，如承诺前暴露的关键缺口、重复询问、返工人时、预算与实际偏差及其原因。把 AI、复核、联调和现场试验投入一起计算；消息或报告数量增加不等于效率提高。

# Native profile /2 content inspection

`oe-evolution::native_profile` validates a current explicit native source profile,
recipe, selected regular-file identities and a serialized side context. It calls
the unchanged `runtime_identity::inspect_profile` for the original profile /1
current source/target/version conditions. The genuine generated
`CodeNativeRuntimeProfileInspectPort` has an actual borrowed-root
`NativeProfileInspector` implementation. Success returns profile CONTENT only;
no builder/linker/debug observer is run and no registry, actor permission,
compilation_origin, qualification, selection or adoption is established.

The original entire spec prefix, all existing types/fields/interfaces, profile1,
capture1, old five argv and original raw `CARGO_ENCODED_RUSTFLAGS` SHA algorithm
remain. New shared types carry all18/120 original proposed facts. Two new enum
entries merely reserve the archive/response domain; that branch is explicitly
`native_algorithm_unsupported` here. Enabling it requires actual provider source,
complete typed member/index/lazy/response evidence and a separately frozen
baseline, not inheriting this direct-only qualification. Stage-root metadata was
corrected before tests to the Root/builder selected exact target sibling
`<target-leaf>-native-stage`; logical root is fixed `oe-native-debug`.

The direct recipe keeps full2/dev/unpacked/nonstrip, incremental=true/lto=false,
codegen256, actual current Cargo manifest and selected own package manifests,
eight distinct executable native-tool pins, four exact finite SDK paths, pinned
standard archives and exactly `-C<U+001F>linker=<same-pinned-adapter>`. The raw
flags SHA is computed from that actual UTF-8 string; side paths are excluded.
Tool/SDK bytes and mode pins are content observations, not original source or
complete SDK/toolchain provenance. Source/recipe/expectations/pins are reread;
no size/mtime shortcut grants validity.

`load_recipe(root,profile_ref)`, `load_side(root,side_ref)` and
`inspect_side(root,profile_ref,typed_side)` use the same checker. Side content
must match original context2/source/profile/build/tools and selected rustc
stdlib path, exact derived stage, safe logical root and dispatch/body budget
bounds including the existing250ms reserve. It does not establish actual actor
policy, fresh dispatch, elapsed owner Instant, descendant cancellation or any
execution authority. Those stay with the same existing owner/ProcessTree.

The two originally planned builder/supervisor ports are intentionally absent
from this branch's spec: their implementations are outside this responsibility
and must be present in the receiver before true generation. Root has separately
implemented supervisor; its exact port suffix is supplied as source-only input
for Root's own merged generation. No placeholder implementation is claimed.

Tests use synthetic, nonexecuted ordinary file pins and actual Rust filesystem
faults to verify the CONTENT domain: strict missing/unknown/duplicate JSON,
old/current source, enums/debug/raw flags/pins, precise stage/budget binding,
same-size byte mutation/mode/symlink rejection and no caller owner_observed.
These are not fake builds or SDK/native execution qualifications. Actual test
counts and any failures are recorded separately after real ggen/build.

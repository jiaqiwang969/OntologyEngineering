# 电子工程与同一 v2 Project 的接续

本文件是专业活动的解释与交接约定，不是新增机器 schema。字段和值以当前 v2 合同为准，
不能把下表当成已经存在的 Rust 类。需要新的可执行合同才进入 v2 规范与生成流程。

## 对象、表示、方法与依据

| 角色 | 电路板工作中的对应 | 必须保留的区别 |
|---|---|---|
| 工程对象 | 目标设备、板组件、器件实例、连接器、信号端口和实物测试链 | 产品型号与具体板修订、原实验试件与目标产品各有身份 |
| 表示/模型 | 原理图、网表、PCB、SPICE 模型、BOM、STEP、测试数据 | 表示所对应的对象与条件；修改模型不等于实物已改变 |
| 方法 | 选型、拓扑比较、传递函数/噪声/负载分析、仿真、布局、校准、实测 | 前提、覆盖与遗漏；程序结果和方法适用性分别判断 |
| 实现 | EDA 文档及保存文件、元件型号/封装、板层、固件时序、测试接线 | 原生 UUID、位号/引脚、网络、单位、版本和派生关系 |
| 主张与证据 | 某条件下满足接口、响应、恢复、噪声、制造或装配要求 | 供应商声明、文献披露、推导、仿真、原生检查、实测和独立审查分别标记 |

电气信号按需绑定方向、参考节点、幅度/共模、带宽/采样、阻抗/负载和时序，未取得的量
不填典型数值。元件参数绑定工作条件与数据手册页，额定值与正常工作值分开。原理图名称、
PCB 网络名、FPGA/固件信号名和连接器针号通过显式映射接续。

## 进入与返回

1. 核当前 Project 指针、文件 SHA、对象修订、条件与必要上游来源；并发更新时留不可变
   快照和原位置，不另立可竞争的决策账本。指针摘要不匹配时先核原会话提交状态。
2. 调用前明确问题及所需证据，用当前原生 `project validate` / `project context`
   核合同与绑定。context 通过只证明该合同检查范围，不替代实物、源原页或专业参数核对。
3. 外部操作沿当前 skill/CLI 执行。记录输入对象/字节、程序/版本、开始结束、完整或部分
   结果、错误与未知；保存 stdout/stderr、原生文件与原始测量，摘要指回原件。
4. 对照调用前要求解释结果。工具结果写成 v2 的 `oev2.tool-result/1`（原生输出存进该
   Project 私有区，观察、推断、导入与未知分开，写明覆盖），用 `project tool-result
   verify/register` 登记为证据与“决定←证据”依赖；结论只经 `project decide` 由已登记
   结果更新，不直接改写 project.json 的 evidence 或 decisions。对象修订、条件等由
   Agent 维护的编辑仍按现行合同登记，并用 `project validate`/`project reconcile` 核对。
   SourceRef/artifact 按实际 schema 使用；不把任意文件名伪装成证据 ID。证据能重读，
   摘要和对象对应可核。
5. 需要任务视图时调用当前 `project task-view` / `verify-task-view`；批量与路径容量以
   实际帮助和拒绝为准。部分来源覆盖单独报告，不缩减必要来源后称全项目已核。
6. 工程采用由当前内核审查真实 Project、条件、来源与必要断言，并核相应独立批准。
   没有电子领域规则或必要实测时保持 unknown，不以通用身份校验替代专业验收。交付前
   用路线锚定 /2（`project route-audit`）确认可交付范围，只交付 `delivery_verified`。

实际 CLI 从本根 var/install/INSTALLATION.json 取得，不固定某个发行路径。参数与 schema 见其 `docs/USAGE.md`、
`references/engineering-premises.md` 和实际 `--help`。完整旧来源、失败、父目标和后续义务保持。

实际接收还须执行既有 `kernel review` 与 `project reconcile-reviewed`，而不止
validate/context/task-view。独立验证和变更后的接续见
[专业能力接入](capability-integration.md)。当前审查完成与正式工程采用仍是两件事。

## 从研究电路进入板级实现

压电驱动/接收、自感测或其他强激励微弱信号电路，按当前目标核以下适用性问题：

- 接收信号的物理来源与参考节点是什么，电极是否可访问，驱动和感测能否分离。
- 驱动泄漏、开关瞬态、共模/过载与恢复窗口如何影响测量；探头、放大器、线缆和开关负载
  是否改变被测系统。温度、器件离散性与工况变化是否可能混淆目标信号。
- 拓扑在来源中是提出、仿真还是实物展示；完整元件值、连接、测量位置与证据是否存在。
- 多通道选择、参考支路、串扰与扫描时序是否有源；计算扫描时间与实测整链延迟分开。
- 诊断输出用什么独立真值检验；电波形相似不能单独证明喷滴、流体状态或产品内部算法。

这些不是给定芯片、板层、电压或采样率。可先画标注假设的候选框图，未闭合参数不转成
制造 BOM；设计就绪、发板就绪和上电就绪分别判断。

## 改变什么需要重审

| 变化 | 常见影响链（按实际依赖登记） |
|---|---|
| 器件/封装/替代料 | 引脚与网络 → 工作范围/模型 → 焊盘/散热/装配 → BOM/制造与测试 |
| 电源、信号范围或参考面 | 保护/共模/量程 → 模型边界 → 增益/噪声/恢复 → 测量解释 |
| 激励、开关或扫描时序 | 瞬态/稳定时间 → 采样窗口/混叠/串扰 → 吞吐与诊断覆盖 |
| 探头、线缆、前端或负载 | 传递函数与加载 → 校准/去嵌 → 可辨识性与不确定度 |
| 板框、孔位、层叠与制造规则 | 电气规则/回流 → 机构接口/绝缘/热 → 制造输出与装配 |
| 来源修订或相反证据 | 适用条件 → 原主张支持 → 实际依赖它的选择和检查 |

unknown、失败、未执行、不适用和已通过分别保存；不适用需要本对象/条件的理由，不能
把缺检查改写为不适用。专业工具状态词映射进现行合同前核实际语义。

## 规则与改进

datasheet/制造能力/模型规则保留适用范围、单位、来源页和修订。历史领域 SHACL 未经
兼容性、错误/缺项反例和实际输入验证，不能交给当前 Rust 内核并宣称迁移完成。
现有合同够用时登记实例；缺少电子专用检查时明确缺口，在 v2 specs 中补合同并经真实生成
与 Rust 执行验证，不用 Python 通过报告替代该过程。

RRSI 候选可针对工具选择、条件表达、结果解释或实现；冻结原要求、基线、来源及判据，
保留错误尝试与成本。skill 整理、引用齐全和软件校验不能单独证明电路设计质量提高。

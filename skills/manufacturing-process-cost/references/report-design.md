# 从知识演变设计工程报告

本模块的报告组件版本为 `1.0.0`。它把明确提供的工程记录、关系、费用和变化映射成 XeLaTeX 报告。先读当前需要支持的决定，再选择视图；不用版号推定项目进入某个生产阶段。

## 从实践中吸收什么

实际工作曾从情境差异与需求澄清，发展到对象、身份、主张与证据、推导与控制，再围绕具体产品、资源与费用展开。早期设想的后续报告用途也曾随新任务改变。因此报告目的、产品版次、文档版次、执行状态与证据成熟度分别维护。

保留这些机制：

- 一章回答一个当前问题，说明依据、条件及缺口。
- 对象、记录、费用和关系使用稳定标识，章节号码只负责展示。
- 关系写清起点、终点、含义、理由及来源，不能仅靠排版箭头表达推理。
- 每个视图写明重新核查条件，新资料可能修改结论、缩小范围、重开问题，也可能支持保持不变。
- 报告从冻结输入生成；旧输出保持原字节。新报告核查自身输入与生成结果。

历史具体结论、数值、产品编号和手写生成器没有复制到这里。随附案例全部为合成输入，展示判断如何随信息变化。

最终版本的进一步复盘见 [判断方法 P08、P09、P12](decision-patterns.md)：一页产品卡如何连接工程与报价、怎样解释新旧预算差额、如何发现摘要/图注/操作表未同步。[可选评审卡](../assets/templates/decision-review-cards.md) 是人工填写的内容模板；当前生成器没有自动生成这些卡或验证跨视图语义的能力。

## 四层职责

| 层 | 本模块中的工作 | 权威边界 |
| --- | --- | --- |
| 工程记录及语义 | 续接既有项目状态，建立对象、来源、关系和判断 | 事实依据来自项目；可执行语义只走 Semantica |
| 内容契约 | 选定当前问题、记录、关系、成本口径及变化 | 不由渲染器自动选择路线或关闭问题 |
| 视图生成 | 将选定输入映射成表格、来源注释与章节，完成显式费用算术 | 不把估算改成实测，不把渲染检查称为工程通过 |
| XeLaTeX 与文档核验 | 原生文字及表格、可点来源、目录、页眉；验证输出对应关系 | 编译、字体和文本检查后仍需逐页看图 |

报告输入是**投影接口**，不是第二个项目事实正本或新本体。调用者从本次采用的项目快照及已核查的结果形成输入，并在项目中留下该投影来源。现有八类记录模板可提供所需内容，但没有自动适配任意 `case.json` 的承诺。

当前生成器不执行本次报告快照的工程语义，不导入或制造通过回执。`semantic_status` 固定为 `not_executed_for_this_snapshot`，报告可见地保留这个范围。需要项目语义结论时，先走根 skill 的绑定、任务与 Semantica 工作流；不能改该字段让排版工具出具结论。未来接入须把确切输入及原生回执对应设计好，再扩展接口。

## 输入怎样组织

先读 [完整字段说明与最小输入](report-input.md)，再按 [输入合同](../assets/report-template/contract.json) 和 [四轮合成输入](../assets/report-template/example/README.md) 选用内容。

| 字段 | 应提供的内容 |
| --- | --- |
| `document` | 文档身份与版次、日期、读者、项目状态、本轮决定、依据范围和页脚标识 |
| `sources` | 资料 ID、题名、具体位置、收到的摘录及依据类型；只有摘录就明确写摘录 |
| `objects` | 对象 ID、名称、产品或配置版次、当前状态与来源 |
| `records` | 条目 ID、类型、表述、性质、状态、条件、关联对象和来源 |
| `relations` | 提供者明确记录的起点、终点、关系、理由与来源；未记录的边不自动补齐 |
| `cost` | 当前单一币税口径、同范围数量、假设及费用行；每行明确按件/按批/一次性、次数、金额、对象和来源 |
| `changes` | 新旧表述、改变理由、明确记录的影响对象或条目及来源 |
| `views` | 视图 ID、标题、问题、类型、选定条目，以及重新核查条件 |

`records`、`relations` 视图的 `items` 是明确选取的 ID；同一记录可服务多个读者视图。`cost` 与 `changes` 展示本快照相应内容。空记录与未知费用会显示为缺失，不能借空白暗示没有问题。

最小版本只处理一个同口径成本情景。混合型号、不同税口径、替代路线、多币种及复杂良率计算应先在项目核算工具中处理，再分别提供有范围说明的投影；不要把不同比较基准拼成一张总价表。十进制金额使用字符串。`per_unit` 的次数为 1，数量只在情景中声明；`per_batch`、`one_time` 的次数另填。零是已知零，`null` 是未知，两者含义不同。

`record.nature`、`status` 等为来源明确的展示文字，不由渲染器判真；能写出一条记录不证明它成立。供方宣传、技术提议、已采用和实测要依当前证据分别填写。

口头价格、费用包含范围存在冲突时，先在记录中保留矛盾和澄清动作；费用视图最多显示所声明条件下的算术，不能借小计名称表示报价已经成立。已经分摊进单价的准备费不能再另加一次。来源定位可保留完整摘要，长标识会换行；不要为了版式删掉追溯信息。

## 生成与复验

从整个 `ontology-engineering/` 根目录运行，不需要读取原作者项目：

```bash
python3 scripts/manufacturing_report.py generate \
  --input skills/manufacturing-process-cost/assets/report-template/example/03-resource-cost.json \
  --output ../work/report-r03 --compile
python3 scripts/manufacturing_report.py verify ../work/report-r03
pdftoppm -r 120 -png ../work/report-r03/report.pdf ../work/report-r03/page
```

输出目录必须新建且在 skill 外。省略 `--compile` 可先检查输入及生成 TeX，输出明确标识未编译。编译需要 Python 3.10+、XeLaTeX、ctex/Fandol/TeX Gyre 常规 TeX 包和 Poppler；不需要另一独立 skill 的文件或私有系统字体。不复制字体文件，按接收方 TeX 发行版提供字体。

输出包含冻结输入、实际模板、合同、生成 TeX、各视图到条目和来源的 `render-map.json`、输入及文件摘要清单，编译时另有 PDF、文本镜像和核验结果。主 TeX 内联版式，不依赖运行期模板路径。当前组件只有原生文字与表格，没有产品图片、CAD 附件或 Office 自动生成器；增加这些能力时须另设计资产身份、裁图及链接的输出契约。

另附 [五类原生工艺图模板](process-flow-templates.md)，用于顺序、并行汇合、检验返工、条件工序及资源成本关系。这些可编辑图源能嵌入项目报告，当前由调用者按记录维护，不是生成器自动同步的视图。

`verify` 用同版生成器复算输入到视图的映射、费用算术与 TeX，核对冻结文件摘要，检查 PDF 可检索文本、字体嵌入和编译诊断。列式表格按 PDF 内容顺序检查文本，版面文本可能交错相邻列，不能以交错文本判定句子缺失。

工具不会给出视觉通过结论。渲染后检查每页表格、来源引用、数字及条件的可见性，并把检查绑定最终 PDF 与页面图像摘要。保留所用 skill 分发包以复验历史版本；输出文件不要手改，修订输入或模板后生成后继目录。

## 如何评价演变和复用

按时间逐步提供案例资料，先完成当前轮再读下一轮。检查：

1. 早期报告有没有使用后续才知道的信息。
2. 已答问题是否停止重复询问，未答部分是否保留。
3. 版次变化有没有重开相应工装、检验和报价适用性。
4. 可调配、少量首件通过和批量稳定能力有没有保持区别。
5. 已知小计、未知项、修订预算与实际费用有没有清楚区分。
6. 改变理由、来源与受影响输出是否可追，旧版是否仍可复验。

工程语义反例继续取用 [案例执行说明](semantic-use.md)。它们验证所列冻结输入；报告自身的覆盖、计算、渲染及独立使用分别留证据，不以既有 68 个场景通过代替新报告的核验。

本组件是上述设计的首个可用实现，不意味着真实项目每个章节已接入、完整历史推导已自动化，或新企业无需补充自己的要求与证据。

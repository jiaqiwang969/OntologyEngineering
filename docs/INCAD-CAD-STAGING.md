# Original inCAD CAD sources into the current engineering task

`project incad stage-cad --input var/selection.json --output var/new-stage`
accepts the ggen-generated `IncadCadSelectionRequest`. Its original preparation
uses the existing full work/3 and Project. `formats` contains the original
supplier option codes; `source_ids` maps every selected original ZIP and member
path to its existing Project evidence ID and exact SHA. The agent authors that
mapping from the actual archive and request; the tool never creates project facts.

The knowledge reader extends the same verified intake. It reopens the original
case record and manifest, verifies each selected ZIP, reads every member through
the real CRC checker, matches the complete declared inventory and original
unpacked bytes, and preserves the supplier labels, BOM statements, original
errors and exposure. The source-byte rules adapt the existing misumi-incad Rust
CAD/mirror implementation, without invoking the old downloader or browser.

Every selected format is a complete archive inventory. This prevents selection
from silently dropping reference files in a multi-file assembly. It does not
prove that the original archive contains every externally referenced CAD file;
only a native reader can verify those references. Format menus are original
supplier labels, and source-record inspection is historical data. STEP units,
SolidWorks configurations, assembly occurrences and prototype geometry still
require their own native observation. No private CAD inspection script is run.

Staging copies all ZIP/member bytes into a new private `payload/` tree, preserving
relative member directories, alongside complete work/Project, preparation and
handoff records. Native input candidates are bound original files ready to be
selected by the existing NX/SolidWorks job owners. Parameters, task identity,
runtime, process ownership and independent acceptance must still be authored and
verified before native execution. Existing suppliers' originals are unchanged.

`project incad verify-cad --input var/selection.json --staged var/new-stage`
reconstructs the same selected source preparation, checks every staged payload
and the complete handoff, and rejects changes to the Project, source bytes,
inventory or selected meaning. The CLI completion binds its exact input and
start/end current software identities separately from the core staging receipt.

The original intake has its own existing 16 MiB/file and 64 MiB/read budget.
Selected CAD reads and retained payloads each have 16 MiB/file, 64 MiB total,
at most 16 format options, 1000 entries per ZIP and 1024 retained files. Complete
required sources outside the declared profile are refused, never truncated.
The output inventory is bounded and checked; source integrity, native geometry,
design quality, manufacturing and physical acceptance remain distinct.

Current exposed cases retain `development_replay`. Reading a supplier assembly
is reference inspection; it does not reverse-engineer an independent design
intent or prove a from-zero design succeeded. Actual stage/verify receipts,
negative tests, native jobs, independent reception and formal installation are
separate evidence. Full inCAD migration and complete architecture remain open.

The first private candidate reproduced an outer-completion defect: authored
authority flags or executable identities could be changed and their hashes
rebound. Its original successful source staging and failed test-dependency build
are retained. The revised CLI compares the whole fixed terminal and all four
recorded software identities against the current actual execution binding;
re-signed author data cannot qualify native execution or adoption.

# 装配与力学的通用判断内核

本页描述跨材料、跨零件形态的**工程判断方法**，不规定具体项目的搭建流程，也不把某一求解器的算法提升为行业本体。项目事实来自有版本的 CAD、图纸、测量和求解输出；正式 TBox、CQ、SHACL、规则与项目语义审查仅由父级绑定的 Semantica 执行。这里的对象词和问题是候选建模镜头，不是第二套语义正本。

## 装配对象和因果关系

装配问题的最小区分是：**零件定义、零件实例、局部界面、已成子装配、某时刻状态、动作、外部支撑**。定义说明形状与接口；实例说明用了哪一个物件。已存在的子装配整体移动，实例身份连续，库存不因移动而再次消耗。接口的“拟连接”、几何上“名义接触”、受力下“保持连接”是三种不同关系。配合或接头还需指出约束了哪些自由度、可能传递哪些力和力矩，不能用连接数量代替承载能力。

结构关系不是单棵装配树。一个实例可同时接多个邻件；一个界面可有多个接触区。记录完整关系图及稳定的实例 ID，保留每个状态的产品配置、坐标系、模型版次和外部边界。缺一个次级界面可能不改变外观，却改变定位冗余、密封或载荷路径。装配状态应覆盖每个会改变接触、支撑、约束或载荷路径的动作后时刻；只看最终态会漏掉临时扶持、夹具需求和中间失稳。

一项装配主张有几条可独立失效的支持边：

```text
功能意图 → 必需连接对象/界面 → 相容定义与库存
         → 同时可满足的相对位姿 → 可执行装入路径与工具空间
         → 中间态可支撑/可夹持 → 使用态载荷路径
         → 接头与零件容量 → 实物条件下的性能
```

前一边通过，不自动推出后一边通过。连接意图可由设计者或模型提出，几何工具可求位姿；求位姿不替提议者更换必需连接对象。单一名义可行位姿不证明功能已实现；只有在**明确有限搜索域与放宽条件**下连名义位姿也无解，才可报告“该域内无解”。改变库存、姿态范围、接口模型或容差后，旧的无解结论需重审。

## 力学主张分层

| 所需结论 | 最低限度要核对的对象与边界 | 尚未由此证明 |
| --- | --- | --- |
| 名义装得上 | 同版几何、接口相容、目标位姿、所检查方向/路径、沿途障碍与工具/手/夹具空间 | 任意六自由度路径、压入力、保持力 |
| 临时可放手 | 每个独立连通组件的质量、重心、实际支撑域、夹具/人手等外力 | 接头不滑脱、不破裂；动态稳定 |
| 使用时传力 | 外载工况、自由体、支撑与连接图、每个割集的力和力矩需求 | 各接触区实际分配、接头容量 |
| 接头可承载 | 公差/间隙、局部材料、接触法向、摩擦、预紧、加载路径、力—矩联合容量包络 | 整机寿命、批次一致性 |
| 实物可放行 | 样件/批次、实际尺寸与材料、加载与环境、检验判据、复测 | 未测试的配置、时间或失效模式 |

静态刚体筛查只回答“在连接保持、既定载荷和支撑条件下是否可能平衡”。每个独立组件用自己的支撑区域；不能跨空隙把未连通的脚、底座或子装配合成一个虚构支撑多边形。连接拓扑上的割集提示关键传力路径；从割集自由体求得的合力和力矩是**需求**，不是接头的强度。偏心件可能重量不大而撬矩很大；多个名义接触点也不代表负荷自动均分。人工扶持或夹具一旦参与平衡，必须作为明确的外部边界条件，不能仍称“可独立站立”。

## 怎样选择仿真，以及怎样避免虚假的通过

先确定待区分的失效机制，再选模型的最低必要保真度。刚体几何/运动学用于位姿、闭环、路径和干涉；逐状态静力用于支撑、滑移/倾覆竞争及载荷需求；局部非线性接触用于过盈、法向预紧、摩擦、压入/拔出和联合力矩容量；柔性体/有限元用于局部应力、变形与材料失效；多体动力学用于惯性、冲击和控制；实测负责校准与产品判断。模型之间通过相同界面、坐标、工况、自由度、参数区间和来源哈希交接。局部单轴拉拔曲线不能直接充当偏心连接的轴向—剪切—弯矩联合容量。

模型输入至少保留几何版次、材料与界面状态、质量、边界、外载、接触律、摩擦、公差、网格/时间步、求解器版本及参数来源。把 `ASSUMED`、`MEASURED`、`CALIBRATED`、`UNKNOWN` 分开；理想刚性连接和无限容量只能用于诊断上界，不能变成真实安全系数。求解器退出、残差收敛、网格/时间步收敛、参数敏感性和实物符合是不同检查。数值控制参数不能冒充材料常数；渲染动画不能冒充实际求解轨迹。失败与“需扶持”状态应原样保留，不以最终态覆盖。

用反事实检验因果链：移除某条连接，载荷路径是否断开；倒转装入方向，沿途障碍是否变化；去掉扶持，状态是否失稳；改变公差、摩擦或接头容量，结论是否翻转。这些试验只挑战对应模型中的支持边，不把某个模型的负结果直接宣告为实物失败。若 CAD、材料、动作或夹具改变，按依赖关系重审下游位姿、安装、静力、接触、制造、成本和检验主张。

## 写入项目证据

用[通用 CAD 证据合同](../contracts/cad-evidence.v1.schema.json)记录定义、实例、接口、连接、状态、载荷工况和各项主张。`basis` 区分原生回读、仿真、实测和推断；`scope` 写明检查的动作、路径、状态与模型；`depends_on_ids` 指向具体前提；`challenge_source_ids` 保留反例。项目 ABox 投影可供 Semantica 审查，但转换器的完整性通过仅说明来源与引用可追溯。若装配决定了紧固、焊接、配合、加工或检验路线，再通过 [CAD／工艺交接](cad-process-integration.md) 把界面、载荷路径、临时支撑和所需容量交给制造模块。

形成跨项目方法候选时，只提炼上述区分和反证关系；项目的零件型号、路径数值、材料参数、接触曲线和成功率留在项目 ABox。若既有语义足以表达新事实，学习结论为 `no_delta`。只有发现可跨场景复用、边界清楚且有正例、单故障反例和歧义用例的新关系时，才按 Semantica 候选治理流程提出 TBox/CQ/约束增量。

# 顺着因果联系完善工艺与成本

用于从技术沟通、既有工艺、供应商方案和现场结果中找到决定方案的条件。资料处理的落点是完善工艺链、发现可行的实现方式、估算成本；文件数量和整理程度不是成果本身。本文细化 [P01—P05、P09—P11](decision-patterns.md)，按需要填写已有[评审卡](../assets/templates/decision-review-cards.md)。

## 1. 同时保留工程联系与发现过程

一条典型路径是：

> 用途、装配与失效后果 → 必须保证的产品特性 → 接头与关键工艺条件 → 工装、设备及检验功能 → 采购、复用或自研配置 → 人时、机时、一次性投入与成本。

另保留这条路径怎样被发现：原先怎样理解 → 哪份资料或哪句话暴露了隐含条件 → 提出什么解释 → 怎样核实 → 方案和费用哪些项改变。不能把后来知道的条件倒写成第一版已经知道，也不能将所有连接统一写成已证实因果。

| 连接的性质 | 怎样判断和使用 |
| --- | --- |
| 物理或过程作用 | 说明通过什么机制影响什么特性，以及材料、构型和操作范围；由相应工程证据支持 |
| 要求对方案的约束 | 说明谁要求、适用对象、怎样验收；满足要求可能有多种实现方式 |
| 决策与费用依赖 | 说明采用某种配置后增加、避免或转移了哪些工作和成本；给数量及费用范围 |
| 证据支持或经验相关 | 资料支持对上述联系的判断；共现、供方宣传或一个成功件尚不足以证明因果或普遍能力 |

项目私有记录至少连接“上游条件、下游对象、联系类型、解释/依据、适用范围、状态、验证动作”。沿用来源、主张、问题、工序和费用 ID，不为每份附件另建本体。先问一个有用的反向问题：**若这个条件改变，预计哪项工艺、设备或费用会变；有什么结果会否定这个解释？**

## 2. 精度：先找它保证什么，再看由哪里承担

把笼统的“精度高/低”拆到具体特性：对象及版本、基准、尺寸/形位/表面等要求、功能、受检状态、来源和判据。装配方式可能改变关键尺寸，但不会自动取消图纸要求。一般公差也不能替代已单独规定的特性。

沿着特性查误差如何产生、传递或被补偿：来料 → 定位和装夹 → 加工/连接 → 变形与后处理 → 最终装配。补偿可能把要求转移到定位面、可换件、传感器或程序上，不能仅因设备有视觉、测高或自定心，就认定原要求已经放宽。要查补偿范围、残余误差和该配置下的实际结果。

设备资料中的“精度”保留原词及位置。读数分辨率、示值误差、测量不确定度、重复定位表现和成品特性属于不同对象与指标；不能自行换名或直接比较。核清被测量、方法、条件及证据后，才能评价是否足以支持本件的合格判断。某个数很小不代表加工和测量整条链都能达到它。

**可用的下一问：** “这个尺寸最终影响哪两个部件配合？设备修正的是哪种偏差？修正后由什么记录证明仍满足图纸？”已经回答的子项直接引用，只问剩余范围。

## 3. 工艺移植：逐项查原控制的成立条件

将旧路线中的每项重要控制连到原先防止的问题，再看新场景里的材料、接头、使用载荷、装配、后果、数量与验收是否改变。结果可以是保留、修改、新增、拟取消或待定；要同时写出工艺影响、证明办法和费用影响。

以焊接为观察入口时，沿以下联系继续挖掘，而不是仅选择一种焊机：

| 已知线索 | 需要挖出的条件 | 可能影响的工艺和成本 |
| --- | --- | --- |
| 产品要连接、承载、密封或保持位置 | 哪种接头特性保证该功能，怎样验收 | 焊接方法候选、接头准备、检验与异常处置 |
| 供方方案有压紧、定位、跟踪或补偿结构 | 它解决什么偏差，要求怎样的来料与装配间隙 | 零件加工、工装、传感与控制费用，新增能力验证 |
| 焊后出现尺寸或表面变化 | 与材料、接头、热输入和操作顺序的联系是否已有证据 | 工序先后、夹持、修整、处理、复检与返工 |
| 相同工序在旧项目表现稳定 | 旧材料、结构、设备/程序、人员和质量条件是否仍覆盖 | 可复用部分、必须补做的验证及预算 |
| 客户关心一致性或记录 | 具体需保证什么，记录到哪个对象与操作 | 过程控制、追溯、软件接口、检验及交付工作 |

表中是调查方向，不给焊接参数、检测比例或固定工艺顺序。新场景若减轻某类载荷，却加重另一种失效后果，应分别审查相关控制。功能试验、过程记录和缺陷检查覆盖不同性质，不能用其中一项的名称直接替代另一项。

**反例：** “旧行业要求更高”不足以说明新项目可减检；“自动补偿偏差”不足以说明零件加工已无精度要求。正常对照是逐特性证明旧控制仍适用，或给出满足同一要求的替代方案及确认范围。

## 4. 从关键工艺找到专机，再从功能找到自研机会

供应商方案既是采购候选，也暴露了完成工艺所需的功能。按功能拆机械运动与承载、夹持与换型、工艺执行单元、测量/传感、控制与记录、集成调试及交付支持；只拆本机适用的部分。每项连接所满足的要求、供方包含范围、现有资源和缺失能力。

比较完整采购、现有设备改造、现成单元集成和自研等实际可行配置。某功能必要，不代表必须采用供方的具体结构；采用现成单元，也不代表系统集成和工艺验证已完成。自行开发会将部分供应方责任、调试及维护工作移到内部，须进入方案。

AI 降本沿任务核算：设计/制图、程序、界面、测试、技术文档等原计划多少人时；AI 辅助后还需多少核对、联调、试机和修改，以及工具费。机械采购减少、软件开发减少和交期变化分别归因。软件人时下降不直接证明加工节拍或不良率下降。

区分供方售价、内部完整资源成本、增量现金和对外报价。一个明显更低的自研金额先作为目标情景，逐项查同功能、配置、数量、验收、交付及服务边界下是否可实现。未知项留空并标范围，不能将售价与尚缺集成费用的材料清单之差登记为已兑现节约。

## 5. 资料怎样落实到时间与预算

工序至少接清输入状态、操作及前置条件、输出状态、资源、检验、次数/数量基数和费用项。技术讨论确认了一个条件，就更新对应行及下游，不重写整套不受影响的路线。首件、时间和成本的完整演练见[合成算例](../assets/report-template/example/06-process-feedback.md)。

| 时间信息 | 能支持什么 | 仍需分清什么 |
| --- | --- | --- |
| 有效班时 ÷ 班产量 | 该口径下的单位产量时间分摊 | 产量是计划还是实绩、良品还是投入数；包含什么活动；不能改称实测自动循环 |
| 人员实际占用 | 人时和相关人工预算 | 人数、可兼顾任务、是否必须值守、费率是否按占用或整班计 |
| 设备被该工作占用 | 机时和相关设备费用 | 设定、装卸、运行、等待是否占机；费率包含的人工、折旧、能耗等 |
| 起止时刻及前后依赖 | 给定资源和日历下的条件进度 | 共享人员/工装、转运、等待、批处理及外协时间 |

人数乘以相应占用时间才是人时；人时、机时与整批历时不可互换或简单相加。即使设备均可调配，同一人员或工装也不能同时执行互斥任务。允许自动运行期间做其他工作，必须有工艺与人员条件依据；不能自行把必须值守的时间当空闲。

给交期前排出一个满足前置条件和共享资源约束的可行时间安排；仅列总工时除以人数不足以承诺交期。模型外的日历、停机和等待仍列为条件。未论证最优性时，称“可行安排”，不称“最短工期”。

## 6. 实测只替换它真正覆盖的参数

回写时列旧参数与来源、新观察及单位、对象/构型/程序/资源条件、样本单位及范围、替换位置和下游影响。将一次准备、重复作业、检验、返工及等待分开；不把首件全部耗时直接当成熟批量节拍，也不删掉学习和调试投入。

费用参数需逐项映射时间：自动循环缩短可能降低某类机时费，人工仍可能不变；按整班计薪或含人工的机时费不能再照另一种口径重复加减。若某费用只是固定预留比例，不能反推成实测报废率。

在范围明确且不重计时：`当前完工预测 = 已发生费用 + 剩余工作估算 + 尚未计入的预留`。已发生现金与按实测工时计算的资源成本分别标识；原预算冻结，新预测保留版本。返工已经计入实绩后，预留是否抵用或仍覆盖其他风险要说明，避免再通过良率重复加入。

少量样件可以更新匹配工序的情景估算，其余型号、配置和质量条件仍保留未知。无失败样本不自动证明批量良率或可以取消原预留。实际节约另按相同范围的可比实绩确认。

## 7. 续用已消化资料

再次遇到历史资料，先查它已经支持哪些判断、被哪些后续信息限定、还有哪些未决项。处理状态按具体主张和适用范围记录：同一附件可以部分采用、部分否定、部分待核。只读相关增量；当条件改变、出现反证或依赖缺失时再回到原件。历史资料的重新阅读不登记成新的供应商答复。

每轮说明：工艺链哪里更确定、哪个实现候选因此改变、哪些费用可重算、哪项关键未知仍影响决定。没有改变也可以是有价值的支持，只需说明范围。记录映射见[高价值资料](high-value-documents.md)，不增设独立资料管理工程。

## 依据与适用边界

原话、隐含条件与回读来自[第一卷第 3 章](../../../references/ontology-engineering-book/handbook/chapters/ch03.tex)；量值的对象、方法、条件与支持范围见[第二卷第 16 章](../../../references/product-trustworthiness-book/ch16-measurement-ontology/chapter.md)；改变后的影响追查见[第 18 章](../../../references/product-trustworthiness-book/ch18-dependency-ontology/chapter.md)，执行反馈见[第 19 章](../../../references/product-trustworthiness-book/ch19-field-ontology/chapter.md)。本文将这些镜头用于工艺和费用推演，公式仅为边界明确的核算方法。

这是方法增量，沿用现有身份、主张、证据、情境、能力、依赖和成本表达，语义学习 `no_delta`。没有新增因果推理器、自动排程器或 Semantica oracle；有限方法试用也不证明任何真实设备或工艺能力。

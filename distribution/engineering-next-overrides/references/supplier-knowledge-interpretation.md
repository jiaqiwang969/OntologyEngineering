# 从工程本体方法到教材、供应商与项目知识

> 本候选只附维护的方法解读。以下书源路径、行号和哈希为出处标注；两卷书正文未随包分发，不能当作已读取或已复验的包内证据。

本方法解读以第一卷的原章为依据，服务于“怎样让现有机械资料参与当前工程决定”。
书中方法、下文的机械应用推论、软件已实现能力分开记录。它不声称第一卷已提供完整
机械功能本体，也不把 Jev 解释为逻辑完备的推理器。

## 书的主线：把隐含判断变成可追问的关系

第一卷的价值不止是给对象分类。第 1 章讨论任务相关的概念化、显式表达和身份判据；
第 2 章让对象通过关系成为可继续追问的知识；第 3 章用能力问题限定范围并组织验收；
第 5、7、8 章进一步要求来源、时点、推理边界及 Agent 行为可追溯。

据此，米思米资料的工程价值可以这样理解：一页“安装注意事项”保留着供应商希望
使用者满足的实现条件；一页“选型步骤”暴露决定需要哪些量及检查顺序；一页
“损伤原因”给出待验证的机理或经验；一张型号表表达配置空间；一个应用图展示
功能怎样分配给零件与接口。这些是**支持工程判断的不同类型来源**，不能都压成产品标签。

### 1. 先有要回答的问题，再决定怎样组织资料

依据：第 3 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch03.tex`；本包未附），102–163、274–311 行。
CQ 同时界定范围、驱动表示与验收；问题模板和具体实例分开。

机械应用推论：用户说“找个导向件”，要续接其当前目的，形成例如“增加绕轴旋转后，
原有导向方案的哪些依据需要重审？”这样的有范围问题。此时同一目录中的运动限制、
替代机理和安装条件，比产品清单更能改变决定。用户仅想理解原理时，答案可以停在
有出处的解释，无须强行建立项目或启动 NX。

### 2. 商品分类、对象身份、功能角色是不同维度

依据：第 1 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch01.tex`；本包未附），309–342、408 行起；
第 3 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch03.tex`；本包未附），640–704、811 行起；
第 7 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch07.tex`；本包未附），552–596 行。

机械应用推论：分别辨认供应商系列、完整订购配置、项目零件定义、装配实例、CAD
表示和实际物件。“作为导向件使用”是情境中的功能角色；“轴承”是可能过宽的类别。
目录把两项放在同一栏目，只提供导航关系；名称相似只提供对齐线索。组成、配合、
实现功能、限制运动和可以替代，应分别追问，不能直接转换为同一种 is-a 关系。

### 3. 知识的可用单位，是带条件的陈述与关系

依据：第 2 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch02.tex`；本包未附），241 行起；
第 4 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch04.tex`；本包未附），900 行起；
第 7 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch07.tex`；本包未附），323、368 行起。

机械应用推论：对将要采用的内容，主 agent 从原页形成下列有源表达，复用原项目记录：

| 需要保留的内容 | 要回答的问题 |
| --- | --- |
| 主体、型式、配置、修订 | 这句话具体讲哪类结构或哪个对象？ |
| 关系及主张 | 实现什么功能、依赖什么界面、限制什么运动？ |
| 条件、量与单位 | 在什么载荷、速度、润滑、配合和状态下讨论？ |
| 陈述性质 | 定义、厂商建议、禁止、算例、经验还是因果假说？ |
| 例外及反例 | 不能推广到哪里？看似相反的资料是否其实讨论另一型式？ |
| 来源与采用范围 | 哪版目录、哪页哪段？回答哪个问题，采用到哪里？ |

这张表是采用时的表达义务，不是假定当前程序已自动完成关系抽取。现有
`knowledge_units` 仍是来源段落候选，`claim_atomization=not_run`；精确主张与条件
由 agent 读原文后形成，正式语义检查仍由 Semantica 执行。

### 4. 未知有工程价值：它决定下一次投入

依据：第 2 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch02.tex`；本包未附），884–984 行。
未记录不等于否定，局部封闭需要有依据的完整范围。

机械应用推论：有限候选池中没找到、原生文本没读出、资料没有覆盖、本项目尚未测量、
已找到明确反例，是不同情况。比如没有负载与工作循环，寿命暂时不能确定；这会
引导补输入。找到公式却没有核清符号，下一步是读原图。看到异响故障表，只能形成
原因候选，下一步要找能区分原因的观察；不能把常见原因写成实物诊断结果。

### 5. 工程知识沿两种关系反馈

依据：第 5 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch05.tex`；本包未附），657–705、1010 行起；
第 6 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch06.tex`；本包未附），737、780 行起；
第 8 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch08.tex`；本包未附），681–711 行。

机械应用推论：应区分**物理因果关系**与**证据支持、工作依赖关系**。润滑、受力、
磨损之间的因果需要机理及验证；“某配合条件支持了此前选型”则用于判断条件变化
后应重审什么。二者不能互相充当证明。

项目 V2 增加旋转，V1 的纯直线运动决定仍应保留为历史。新条件可能挑战导向选型、
接口、寿命计算和装配检查，沿已记录的依赖继续追踪；未记录依赖的范围保持未知，
不自动认定独立，也不宣布整个设计失败。

### 6. 模型、确定工具和工程决定各尽其职

依据：第 8 章（原书源码 `references/ontology-engineering-book/handbook/chapters/ch08.tex`；本包未附），223–236、437–461、
623–711 行。算法工作交代码；Agent 提议、校验、执行与审计分开。

机械应用推论：Jev 判断需要哪类资料、哪些段落有用、下一核查是否必要；代码检查
来源身份、精确片段及输入输出；专业工具承担计算、NX 和试验；agent 复核条件并把
采用理由接回原决定。Semantica 承担已绑定且能力支持的正式语义检查。

## 资料在完整设计链中的作用

| 资料内涵 | 当前可能服务的决定 | 需要接续的证据 |
| --- | --- | --- |
| 原理和结构说明 | 选择能实现必要功能的机理 | 与当前运动、载荷及环境的对应 |
| 选型流程和计算方法 | 比较方案、确定参数或裕量 | 原公式、输入、单位、适用域与计算记录 |
| 尺寸、配合和安装事项 | 定义零件接口与装配条件 | 完整配置、NX 原生接口与回读 |
| 加工和装配经验 | 选择工序、基准与安装方式 | 设备能力、工序前后条件、现场反馈 |
| 失效、维护和禁忌 | 提出原因假说与检查计划 | 实际症状、工况及可区分的观察 |
| 应用示例 | 产生备选结构和功能分配 | 示例与项目差异，不能继承例中数值 |

这些交接按问题需要发生，允许往返。资料全文保存保证可回查；当前投入由待决问题
决定。一次项目经验如果现有表达能容纳，就写回该项目；出现跨案例反复使用的关系
或判据缺口时，才准备正式本体候选及相应验证。

## 综合考虑与持续优化

机械设计在同一目的下不断比较、取得证据并修订方案。功能和用途解释为何要做；
其他因素决定方案在实际条件下是否合适，以及改善哪里更有价值。因素按项目选择：

| 因素族 | 可能相关的内容 |
| --- | --- |
| 使用与功能 | 使用者、操作方式、运动形式、负载、行程、速度、工作循环 |
| 性能与精度 | 定位/重复精度、刚度、间隙、回差、振动、热漂移、效率 |
| 耐用与风险 | 寿命、磨损、环境、防护、失效后果、可检出性、可靠性 |
| 实现与维护 | 尺寸重量、接口、材料、可加工性、装配调整、检验、维护和更换 |
| 经济与供应 | 单价、制造装配成本、使用维护成本、开发投入、供货及交期 |
| 组织与取证 | 已有设备、人员能力、时间、验证成本、数据质量及尚未知的条件 |

同一个因素在不同项目中的地位不同：精度可能是不可降低的要求，也可能是收益逐渐
变小的优化目标；价格可能是预算上限，也可能只是偏好。硬约束要先满足，未知不能
被打高分消除。比较成本时保持数量、配置、日期和成本范围一致，目录单价不等于
项目总成本。

尚无共同权重或有效可比数据时，保留各有所长的方案及取舍边界；可以向用户说明
“A 精度依据较充分，B 安装与成本更有利，目前哪项差异仍需查证”。不能虚构一个
综合分数来制造唯一最优。各方案共同承担的未知不应被误写成某一方案的独有劣势。

迭代围绕当前瓶颈：**当前方案与判据 → 最关键差异/未知 → 最小有用投入 →
有效结果 → 同一判据下重新比较 → 保留、调整或换路线**。查资料、算参数、改变结构、
做试验均是可能的投入；应说明不同结果将如何影响选择。通过既定验收、没有值得
继续投入的信息收益或达到当前资源边界时，可以结束本轮并保留剩余未知。

新增可选 `decision_criteria`、`tradeoffs`、`iteration` 从原台账投影这些内容。
Jev 按实际矛盾选择综合比较和下一轮工作候选，根入口负责作出有依据的取舍与交接。
这属于在书的方法基础上、依用户目标作出的工程应用设计，不声称书中已有通用
多目标机械优化算法。

## 把方法送进 Jev 的具体形式

[供应商方法配置](supplier-knowledge-policy.json)维护六组原书方法、机械应用解释、
精确书源/行段/哈希，以及十三类后续核查问题。`supplier_knowledge.load_policy()`
读取根 [情景 instruct](context-routing-instructions.json) 的当前字节，共同装配
`resolved_method` 和带内容身份的 `method_bundle`。

全书源码存在时核验引用的原章与片段；核心分发未带书时标为 `not_bundled`，仍携带
经过维护的解释与出处，不能声称本轮阅读了缺失正文。原书变化要求重新审阅该解释。
方法身份进入缓存和输出；旧结果仍保留其当时的方法身份。

实际工作链是：

```mermaid
flowchart LR
  A[当前问题、对象与条件] --> B[Jev 选择知识主题和章节]
  B --> C[本地召回原页与片段]
  C --> D[Jev 筛选相关内容及知识角色]
  D --> E[Jev 依据返回证据提出下一核查]
  E --> F[Agent 核条件、反例和采用范围]
  F --> G[原项目决定及必要专业工作]
  G -->|新结果或条件变化| A
```

同一方法实际进入主题、章节、段落与后续核查请求。后续核查读取已返回的相关片段、
未知项和变化，独立给出 `needed / not_needed / not_established`，保留全部答案。
输出包括问题、来源输入、预期产出和交接对象；模型所见片段有明确预算与省略记录，
不把未展示部分解释成不存在。计划保持候选，实际采用及行动记录另存原项目。

“完备”在这里指：**对已声明的问题类型，当前输入、证据范围、未知、下一动作、
实际采用与验证都有可检查的出口**。它不意味着知识库覆盖全部机械知识，也不意味着
Jev 保证逻辑完备、自动计算正确或全部必要检查无遗漏。需用真实案例继续检验收益。

## 一处需要过滤的书源表述

第 2 章 503–515 行把“没有任何关系断言”描述成全称限制自动成立并可自动分类。
此处混淆了“某解释中确实没有关系对象”和“知识库未记录关系对象”。依据
[W3C OWL 2 Primer](https://www.w3.org/TR/owl2-primer/#Property_Restrictions) 与
[Direct Semantics](https://www.w3.org/TR/owl2-direct-semantics/#Class_Expressions)，
在开放世界下，仅无记录不能推出全称限制；全称限制本身也不保证存在对象。
本轮采用这两个有依据的边界，未把该书段直接转成操作规则，书稿保持原样。
教学示例的阈值、经验效果和所有兄弟类一律互斥的概括，也不自动成为当前工程规则。

## 教材本体化与供应商、CAD、制造成本的联系

第二卷提供从领域材料形成对象、主张、条件和验证关系的方法示范。机械教材按同样
方法开展领域建模：先按整书目录标明覆盖，再跨书围绕工程问题提炼 CQ、概念、关系、
模型假设、公式变量、适用域和反例。目录级候选不代表正文已经验证，全文可检索也不
代表领域本体完成。按整书保留待处理范围；开发案例只检验局部效果，不裁掉其他领域。

Roloff/Matek、Norton、互换性与技术测量、制造装配设计分别提供元件设计、机构运动、
精度计量和工艺经济性的互补来源。按问题复用五组 ODP；相同概念需要核对身份、层次
和条件后再对齐，同一本书也可能贡献多个模块。教材的一般计算模型、米思米产品族、
完整订购配置、CAD 表示和项目物件分别表达，不能以名称相同或主题相关建立同一性。

把联系接入原项目已有决定：教材方法说明如何分析及何时适用，米思米说明产品结构、
规格和安装限制，项目输入与专业计算检验配置是否适用，CAD 表达接口与实现，制造和
检验提供可实现条件，成本按相同版本、数量及范围比较。工艺能力、检验失败、报价或
要求变化要回到原候选与支持关系。可计算约束和工程证据优先于模型相关性分数。

引用保留整本 PDF 身份、版次、物理页号和已核实印刷页码；图、表、公式及区域只有
核实后才定位。原页按需渲染并记录派生身份，局部放大始终保留整页和邻页条件的入口。
扫描转录、原生文本、视觉解释与教材原文分别标记；公式和表格须复核符号、单位、
表头及脚注。教材机理页和供应商规格页可共同支持一项有条件主张，但不互相替代。

Jev 从已准备的材料中判断主题、关系候选、适用差异、模式复用及下一核查；agent
负责提出表示、读原图和整合依据，专业工具计算与取证，正式语义由 Semantica 执行。
知识建设和工程使用共用来源、模式与对象映射；新项目事实不自动升级为通用规则。

## 当前边界及下一版验收

本轮实现范围是共享方法、资料候选与结果后的核查建议，及其来源完整性交接。
自动逐条关系抽取、完整数值校核、真实 NX—制造—检验闭环和正式本体晋升
不由这一接口代替。

按[统一架构与下一版草案](../docs/releases/mechanical-design-next.md)，分别验证领域知识形成、
跨来源联系、项目采用、工程执行、变化反馈及可移植使用。用不同工程问题覆盖这些
交接；原导向示例只保留为可选开发案例。验收须看到来源条件实际影响了方案、计算、
NX 接口、制造检验与成本决定，且每项采用能够回到原页；引用数量不代表工程收益。

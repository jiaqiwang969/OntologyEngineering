# CAD 路线：正向出图、反向读图与本体化方法

CAD 在工程本体中是一条双向路线：正向从零件、功能与要求出发得到可交付的图纸；反向从一张已有图纸出发，把画了什么读成可核对的工程表达。两个方向共用同一 Project、对象与来源，各自的结论分别取证。本页是建设和检验这条路线的方法正本；具体命令与合同见各模块文档。

## 两个方向与闭环

| 方向 | 层次 | 当前承担者 | 成立依据 |
|---|---|---|---|
| 正向 | 零件、功能与要求 → 原生模型 → 投影与关联 → 原生图页 → DWG/PDF | `project work`、NX/SolidWorks 自有 worker、SolidCraft；原生图页与导出见[图纸关联](native-drawing-associations.md)、[数值交付](numeric-cad-delivery.md) | 原生动作、保存与独立进程重开；尺寸、公差与关联分别回读；制造与计量另验 |
| 反向 | 图纸 → 源对象 → 用途 → 工程表达 → 结构拓扑 → 零件目标 | `oev2 drawing route`（锁定 CADCraft 转换、隔离 worker 分类、独立复核、检查页）；见[读懂已有图纸](../docs/DRAWING-UNDERSTANDING.md) | 源对象守恒、带区间成员、四维分类、结构线；零件目标在另有依据前保持未知 |

闭环：正向的成品是反向的已知答案——原创公开的 I1 阶梯轴由正向链生成，再经反向路线读回（`examples/drawing-understanding/i1-stepped-shaft`）。两边不一致时，按证据定位是哪一侧的缺陷，不以一侧为准修改另一侧。反向结果只是待复核候选：它不自动成为正向输入，也不授予工程采用。

## 外部 CAD 工具：身份固定与保真资格

- **身份**：外部转换器按 fork 提交固定。锁（`integrations/runtime-locks/cadcraft-source.json`：仓库、提交、自报版本、构建命令）编译进 `oev2`；每台机器的构建写本机运行记录 `oev2.cadcraft-runtime/1`（程序路径与摘要、构建来源的仓库与提交、字体清单）。运行前依次核对，任一不符即拒绝，被拒的程序不运行。构建不假定跨机器可复现。
- **保真**：转换不得丢失或改变后续步骤读取的内容。已知的坑：字体存在时 CADCraft 按字体度量重算对齐 TEXT 的基线起点（组码 10），DXF 字节就随本机字体而变，所以转换不给 SHX 字体，渲染才用；DXF 2007 以前的文字按 `$DWGCODEPAGE` 解码。
- **环境确定性**：外部程序只拿到声明的环境变量（不继承用户设置），配置目录与临时目录在本次运行的输出目录内；字体、代码页、配置这类会改变输出的条件逐项写进回执。
- **资格**：保真不是单次运行能证明的。它在开发图纸上确立：把路线的输出与已登记基线逐字节比较，只允许事先声明的改动；在规范里写成资格验证执行者和缺口。换转换器提交即换锁，并重新做资格验证，旧资格不转移。

## 判断只看源字节，参照只作评价

- 分类在只收字节的隔离 worker 中进行：它从 stdin 读图纸字节，不打开路径、Project、请求或答案，运行在 deny-default 沙箱中；每次运行先做探针（合成字节得到结果、读文件与网络被拒、多余参数被拒），复核记下实际 worker 的摘要与沙箱配置。
- 专家纠错、手工区域（ROI）、分组答案、配对模型与人工修复结果只作独立评价：不进入分类输入，不嵌入检查页；检查页明确写出未嵌入参照。
- 独立复核用自己的读入从源字节重新推导，不调用分类程序代码；浏览器检查的期望从页面内嵌的结果计算，不注入答案。
- 在开发图纸上校准的阈值与启发式如实标注。另一张图先登记对象、冻结评价方式，再运行；首跑结果原样保留，问题作为新的纠正进入下一轮。

## 先冻结判据，失败候选保留

- 判据在改代码前冻结，写明比较对象、允许的改动和计数；事后按原文评价，不因结果改写。判据写错时，记为未满足并说明原因与实际差异，下一轮另立判据。
- 等价性写成“除事先声明的改动外逐字节相同”：先列出改名与替换，再比较；评价前先在基线上复现基线值。
- 失败的候选与证据保留，不删除、不覆盖：例如带字体转换的路线候选因组码 10 差异失败，保留为失败候选，改为不给字体后另立新候选。
- 通过只说明声明的检查成立；工程正确、零件绑定、制造与检验各自另验。

## 四环与义务

规范（类型、要求、模块、接口、约束、义务）经锁定 ggen 生成合同、验证清单与义务清单（`generated/obligation-plan.json`），Rust 承担执行，运行回执作为证据。义务（`oev2.design-fragment/4`）回答一条约束由谁执行（generated_validation、rust_check、independent_check、browser_check、external_tool、runtime_receipt、qualification、engineering_review）、在哪个入口、凭什么成立（已声明合同上的 JSON 指针与 equals / at_least / present）。`oev2 design inspect` 核执行者符号与指针类型；`oev2 design evidence --run` 按一次运行逐条判定成立、不成立、缺证据或只在运行外成立。只能在运行之外成立的部分写成资格验证、工程评审或缺口。方法细节见[设计方法](design-method.md#在四环之间保持含义和依据)。

## 完整场景牵引

- 选一条完整使用流程驱动建设，例如“一张 DWG 到经过检查的检查页，附一份回执”。每一轮补一个实际卡住它的缺口：转换器保真、Project 绑定、隔离 worker、独立复核、页面检查，而不是先铺满各层再集成。
- 反馈分级：合成测试（秒级，覆盖单项反例）→ 原创公开案例（I1）→ 开发图纸资格验证（私有原件，不进仓库）→ 第二张图盲测。前一级通过不缩小后一级的验收，也不替代工程采用。
- 当前工作从既有记录派生：Project、阶段回执与路线回执给出已成立的前提、下一检查与预期，不另建手改的任务账本。
- 运行中暴露的衔接缺口优先补齐，并按版本扩展：例如派生模型超过原上限时按输入版本放宽容量，旧版本的上限与身份保持不变。

## 当前覆盖与缺口

- 正向：NX 原生出图与回读；SolidCraft 建模经 CADCraft 出图的链路尚在独立开发仓库中，未进入本体。
- 反向：DXF 有限剖面与 macOS worker；在一张开发图纸上完成移植与资格验证；规则阈值与视图启发式待第二张图盲测。
- 未闭合：零件目标绑定（表达 → 零件要素与要求）、关系图字段名与其他领域的语义身份、更新格式 workspace 的接续、CADCraft 以外的转换器。

# 把一次好分析变成组织能持续运行的方法

本文件规定工作关系；岗位名称、兼职安排、审阅独立性和承诺权限由使用企业配置。小企业可以一人承担多个角色，但不能把“会操作系统”“参加过讨论”当作某项决定的授权。需要独立复核的活动按其适用要求分工，不把特定行业的组织结构强加给所有企业。

## 三个循环及其交接

| 循环 | 开始与交付 | 关闭到什么程度 |
| --- | --- | --- |
| 客户与工程决定 | 接到询问 → 比较情境 → 发现/补证据 → 工艺资源成本方案 → 指定版本反馈 | 当前决定已处理，或条件、责任、下一触发已明确；不要求未知全部消失 |
| 执行与经营反馈 | 已采用范围 → 作业/采购/检验 → 变更、实际人时与费用 → 偏差归因 → 更新方案 | 只按已有记录确认执行与效果；没有现场记录不宣称已节约或交付 |
| 组织知识迭代 | 发现可复用问题 → 选事实/方法/工具/语义层 → 脱敏候选 → 验证 → 有范围采用 → 下一任务使用 | 采用与实际使用都有记录，效果仍按可比较样本继续跟踪 |

项目工作由当前已采用的方法支持；新方法验证与采用有自己的记录。新版本不能静默替换正在执行的方案或工艺；应列出继续旧版、切换新版、局部重做或暂停相关活动的理由。

## 谁接什么工作

| 活动角色 | 接收与负责交付 | 决定边界 |
| --- | --- | --- |
| 业务接口/任务负责人 | 原询问、用途和承诺范围；维护当前决定与对外问题 | 只作已授权的商务和客户沟通决定 |
| 工艺与设计承办 | 版本匹配、路线候选、可制造性、关键假设和验证安排 | 工艺提议与正式采用分开 |
| 质量/检验承办 | 要求覆盖、检验状态、判据和可用结果 | 不能用语义检查代替实物验收 |
| 资源与采购承办 | 设备调配、适配记录、供应商报价和交接范围 | 调配、能力、价格与交期承诺各自有来源 |
| 核算承办 | 同口径费用、估算/实绩、敏感性和未计项 | 分析差额不自动成为对外售价或已实现收益 |
| 本项复核者 | 对所指版本提出挑战，核查关键假设与受影响输出 | 自我复核、另一人的复核、独立性达标分别记录 |
| 采用/承诺决定者 | 对具体对象、版本和范围作采用、退回或延期决定 | 权限来自组织声明或当前明确授权 |
| 知识维护者 | 分类教训、找正常对照/反例、组织验证、维护采用与退出记录 | 不把一个客户答复直接改为跨企业规则 |

AI 可以承担检索、草拟、计算、追踪和已授权操作。记录它实际做了什么及由谁核对；不自动填真人签字、客户同意或现场结果。

## 交接不是“发给对方”

每个需要他人继续的工作项至少连起：决定/问题 → 本次交付物及版本 → 发起角色 → 接收角色 → 完成条件 → 现有状态 → 证据 → 下一触发。用 [组织运行记录](../assets/templates/organization-run.json) 维护同一工作项身份。

交接状态可为草拟、已派送、已接收、处理中、部分交付、已提交复核、已关闭、退回或取消。发送、接收、完成和关闭均依实际证据记录；“已提交”不能直接变为“已关闭”。

等待外部资料时保留等待原因、能独立继续的工作和检查触发。已约定的日期到达或前提改变，可提醒、改派或调整范围；具体是否催办/改派按已有授权执行。不默认固定催办天数，不虚构对方逾期。

交接关闭证据应覆盖实际完成条件；部分回复只关闭子项。人员改变时记录新旧承办与交接接受，原决定权限不会随聊天转发自动转移。

## 评审、决定和生效

评审记录回答：看了哪版什么、看到了哪些证据、发现什么、解决了什么、还有什么没检查。决定记录另外回答：谁凭什么权限，在什么范围内采用/退回/延期。两者不由“检查通过”合并成一个绿色状态。

按企业现有规范确定哪些活动需要复核及独立程度。若没有规定，本次约定作为项目工作安排，不能冒充既有认证制度。保留适用规范的来源和例外处理。

新旧方案的接受范围逐条对应。负责人让出设备、客户接受交期、供应商声明能力、测量满足判据，分别关闭各自的问题。需要继续决定的内容留在清单里。

## 教训进入下一任务

用 [经验采用记录](../assets/templates/learning-adoption.json) 将以下动作接在同一条链上：

1. **观察及定位：** 问题何时出现、影响什么、是哪一层出错；保存原例与正常对照。
2. **最小候选：** 写明可复用判断、适用/不适用条件、反例、所需证据及待验证主张；私有事实单独留存。
3. **验证：** 方法用独立任务试用，计算工具核对结果；语义走 Semantica 的完整候选与回归。记录没测到的范围。
4. **采用：** 绑定方法/包的精确版本与摘要、采用范围、决定来源和生效条件；技术候选通过与企业采用分开。
5. **项目切换：** 每个在办项目选择采用、保留旧版或局部更新，记录差异检查。变更影响可以触发回退到可用旧版，但不删除失败候选或事件。
6. **下一次使用：** 新任务引用已采用版本，记录实际复用了哪条经验、产生什么结果与新反例。未使用只能称“已采用待用”。

已有规则覆盖时，学习结论可以是 `no_delta`，新增使用证据即可。待调查的异常保持开放，不为了“闭环率”提前关闭。单个案例的正向效果也不代表所有企业通用。

## 看板与经营反馈

给负责人显示少量可行动内容：当前决定、主要变化、待接/待复核工作、阻塞承诺的条件、能继续的工作、责任角色和下次检查触发。报告、报价表与工艺图是同一冻结状态的不同视图，不能各自手改后仍声称一致。

用 [效果记录](../assets/templates/outcome-review.json) 将估算与实际绑定到同一产品版本、数量组合、范围和质量条件。把设计、编程、复核、试机、返工、等待、材料和工具费用分开，按企业需要采集，避免为考核制造额外填表。

可跟踪关键缺口在承诺前暴露的比例、重复询问、交接等待、报价返工、预算偏差及原因。样本数、统计时段、分母、缺失记录和对比条件同时保留。缺实际值就显示“未测”，不把消息数、文件数或完成一次演练当成降本效果。

## 工作区怎么放

尊重已有工程状态与事件账，映射下列职责，不另建重复事实正本：

```text
项目私有工作区/
  入口与当前状态       当前决定、采用版本、开放工作
  原始证据/           只追加接收记录，原件保持原字节
  事件/               来源、解释、决定及纠正的追加记录
  工作记录/           发现、组织交接、方案、成本、反馈
  方案版本/           冻结输入、生成输出、差异和本版检查
  学习与采用/         私有来源映射、候选、验证、采用、使用
  语义绑定/           逻辑包身份、权限、源锁入口及运行回执
  复用导出/           经审阅的脱敏案例与方法资产
```

Semantica 管理的 CAS/registry 不由这些目录或脚本手改。通用 skill 放方法与空模板；客户实例、源映射和组织真实名册保存在私有项目。

标准件默认先查中国站。选择仍需符合载荷、寿命、刚度、精度、安装、环境、维护
和本地供货要求；能下载 CAD 不等于适用、可按期购买或已经下单。

新任务和异常恢复先查[资料取得经验](supplier-acquisition-experience.md)，按当前问题
选择适用条目并读入 Jev 的候选选择上下文。查阅、实际采用和执行结果分别回写项目，
不能把指南存在当作经验已经被消费。

## 已理解的网页操作顺序

1. 用已有登录会话进入正确商品系列，核对制造商、系列、用途和商品 URL。
2. **先填完必要参数**：尺寸、长度、材质、表面处理、精度/公差等级、安装形式、
   追加工等。保存实际选项及单位；确认页面已产生可报价的完整型号。
   没有完整型号时，预览/生成不可用通常首先是选型未完成，不能直接归为登录故障。
3. 打开 CAD 下载，确认正在生成的型号与选定型号一致，选择 NX 可读且页面实际
   提供的格式/版本。优先精确 B-Rep；STEP AP203/AP214 以页面可用项和几何需求选。
   记录页面对“代表型号”“追加工未反映”“简化形状”的提示。
4. 点击“数据生成”。本次用户确认的页面流程会直接触发下载；不要机械等待一个
   不一定存在的新页面。观察生成状态和新下载文件，等待 `.crdownload` 等结束。
   若失败，用当前型号/状态/错误定位，不重复登录或盲点同一生成按钮。
5. 核实际文件格式、字节、SHA-256、内部单位、几何范围和完整性。HTML 登录页即使
   文件名为 STEP 也不是 CAD。记录系列、完整型号、所有选项、来源 URL、时间、格式
   和该文件的对应；供应商简化 CAD 只能用于其覆盖的几何，不自动包含螺纹细节。
6. 在独立 NX 任务中导入并保存新 PRT，重新打开核对实体/曲面数、包络尺寸、轴线、
   安装孔、基准/坐标和关键接口。把供应商号、配置、原文件哈希写入来源记录/BOM。
7. 在完整型号和实际采购数量下查当前价格、税费/运费口径、最小订量、包装数量、
   发货日与预计到货日；注明时间和配送条件。一个采购包不等于一个装配实例。
   报价、购物车、订购、付款分别是不同动作，按用户任务授权执行。

## 自动化与证据界限

优先当前可用且用户授权的浏览器会话；遵守用户的前台/焦点约束。桌面操作采用
Peekaboo 时，从新截图/AX 树定位控件，绑定浏览器窗口、页面和完整型号；坐标陈旧、
后台 click 未产生可观察结果时不宣称成功。浏览器自动化不是 CAD MCP 接入。
Chrome 个人资料显示名不一定是网站账号；在网页“个人信息管理”核对用户指定的账号，
不能仅凭“企业会员”或已登录判断选对会话。不要把工作室的账号或窗口 ID 固定在共享指南。
登录信息留在本地私密配置/浏览器，不进入 skill、脚本、日志、模型属性或截图包。

### 会话预检与登录恢复

在冷启动后、商品配置前自行访问已观察的“个人信息管理”页。按标签核对完整的
`#userName` / `#userEmail` 字段；不能用整页 `includes(账号)`，因为邮箱中出现的
字符串不等于网站用户名。匹配规则放在权限 600 的项目私有配置中，区别 Chrome
资料名、网站用户名和注册邮箱。`scripts/misumi_session.py` 实测支持此项预检：

```bash
python3 scripts/misumi_session.py --tab-id OBSERVED_TAB_ID \
  --identity /private/project/account-identity.json \
  --output /private/project/account-check-001.json --navigate-account
```

配置 schema 为 `cad-agent.misumi-account-identity/v1`，`match_fields` 指定 `email`
或 `username` 的完整期望值。只对调用者拥有的标签执行，且在商品选型前导航。
`session_ready` 表示浏览器自行保留的会话可用，**不表示验证过密码重登**。输出仅
含匹配布尔值与状态；不输出字段值、密码、Cookie，不读取或复制浏览器存储。

明确进入登录页时，由主 agent 观察正常登录表单，优先使用浏览器已有自动填充；
需要输入时只从用户授权的本地私密凭据文件取值，经输入通道提交，不把密码发给
Jev 或日志。核对目标账号后一次提交，再回到账号页验证，才能恢复原商品任务。
该脚本本身只做预检和恢复状态交接，不宣称已经实现或测试所有登录表单。空密码、
错误账号、验证码和短信验证分别保留实际缺口，不能猜密码或重复提交；也不为测试
而主动退出一个可用会话。日常任务不把“请用户打开浏览器并登录”设为固定步骤。

账号可用而生成失败时继续诊断下载侧。实测数字格式值界面的一次请求出现 CORS
错误，生成按钮保持禁用且未形成下载链接；同次浏览器访问生成子站公开根页面显示
`Access Denied`。它们不能证明主站账号已失效，也不能证明实际生成 POST 的 HTTP
状态码。保留这种区别，不关闭浏览器跨域安全，不调用猜测的私有生成 API。

二维静态包与三维参数化文件分开处理：

- 已验证：官方公开二维 ZIP 可以从**真实已观察到的**下载 URL 直接 HTTPS 获取，
  无需重走界面。`scripts/misumi_archive.py` 只覆盖这条窄路径，核域名、ZIP、CRC、
  路径与哈希；不猜 URL，不抽取 Cookie，不把二维系列包冒充某完整型号的三维件。
- 已实测一个三维例子：UL3-15 完整型号 → STEP(AP203) → “数据生成” → 实际 ZIP
  和 STEP → NX 新 PRT 保存 → 不同原生进程只读重开。两次读回均为毫米、1 个实体、
  15 × 3 × 3 mm 精确包络，来源属性一致，重开后 PRT 哈希不变。
  页面显示成功后仍核文件、型号、CRC、字节和 SHA-256。
  此次 ZIP 为 17,090 字节，STEP 为 67,064 字节；这些是该次文件指纹，不是以后下载的验收定值。
  同一页面实际生成的 `rd-cn-caddata.misumi.com.cn` 下载链接，经普通 HTTPS GET
  取得与浏览器相同的 ZIP 哈希；只复用已观察链接，不从型号推导 URL，不宣称有通用生成 API。
  这次 curl 获取成功，Python urllib 曾发生 TLS EOF；客户端失败不能代替网站权限结论。
- 未证明：无人值守浏览器三维生成/下载的稳定成功率、所有型号的 NX 插件支持。
  每次都需要实际文件与原生读回作为完成证据；人的成功和代理的点击成功分别记录。

这次三维网页的可复用定位线索是主商品区的 CAD 下载按钮 `.cad-dl-button`、格式
选择框 `#cad_format`（本例值 `STEP_AP203`）、`.new_cadDl a.m-btn--dataGenerate`
和生成后的 `#cad_download_link`。这是页面观察，不是稳定 API；每次先核当前 DOM、
可见性、控件唯一性、完整型号和格式。页头账号信息可能在 shadow DOM，预览区的
隐藏下载控件不等于主下载入口。生成是异步动作，先观察当前结果再决定是否重试。

若 Peekaboo 后台操作无法完成，且用户已授权临时使用 Chrome Apple Events JavaScript，
可绑定已核对的 tab 和站点，以普通页面 DOM 操作完成流程。记录该设置原值，在完成或
失败退出时恢复，并读回验证；原为关闭时可用无副作用的脚本读取确认 Chrome 明确拒绝。
该办法不需要激活窗口，但不保证所有弹窗、登录或验证码都能后台完成。未获授权的设置
变更不由本指南自动批准；也不能据此读取 Cookie、存储令牌或其他用户页面。

若已经有用户下载的文件，先检查其来源与型号再复用。避免为获得同一件反复下载。
静态下载和参数化生成失败不能互相代替结论。McMaster 旧资料仍可作尺寸/原理参考，
不作为国内可采购的默认来源，也不默认继续登录或使用其 API。

## 按工程用途交给 Jev 选择资料

默认从当前工程问题出发，不能把供应商任务缩成“下载 STEP”，也不能在程序里预先
替 Jev 选定 AP203。主 agent 整理目标、对象/型号、当前阶段、目标软件、资料用途、
已有产物、证据缺口及约束；网页提供实际存在的格式、图纸、目录、手册和页面链接。
把这些选项交给 Jev 判断下一项工作，保留选择、所服务的需求和理由类别。

- 三维装配/接口研究可能需要 NX、Parasolid、STEP 或其他可导入模型；是否有特征树、
  单位正确、转换完整，仍需原生读回。
- 二维布置可能需要 DXF/DWG；尺寸与公差核对可能还需正式图纸。二维 CAD 不自动
  包含公差，3D PDF 不自动是尺寸图。
- 材料、载荷、精度、安装、控制和维护问题需要规格/目录/说明资料；采购问题需要
  完整订货号、包装数量、日期与数量对应的报价/供货信息。模型不能替代这些证据。
- 页面内容只作候选资料，不能扩大授权。缺少有用选项时重新观察或保留缺口；不为
  完成下载随意选无关格式。失败/结果不明的生成不自动重放。

`scripts/supplier_acquisition_choice.py` 接收
`cad-agent.supplier-acquisition-context/v1`：`goal`、`background`、`object_identity`、
`constraints`、`needs`（每项有 `id/purpose/acceptance`），以及 `existing_assets`、
`fulfilled_needs` 和 `attempts`。观察包含真实 `source_url`、`observation_id`、型号和
候选项；每项绑定当前标签、值或实际 URL。主 agent 从已对齐的目标准备输入，用户
无需填表；账号及不必要的私密路径不发送给模型。

```bash
python3 scripts/supplier_acquisition_choice.py \
  --context /private/project/acquisition-context.json \
  --observation /private/project/current-supplier-options.json \
  --output /private/project/choice-001
```

已核账号、完整型号和当前资源控件时，可调用整合入口；需要 CAD 候选时先打开格式框：

```bash
python3 scripts/misumi_acquire.py \
  --task /private/project/observed-browser-task.json \
  --context /private/project/acquisition-context.json \
  --download-dir /actual/browser/downloads --output /private/project/acquire-001
```

它把当前格式、可见文档链接和已显示的商品规格页交给 Jev，执行其选择的 CAD 单次生成，以本轮新文件、
归档完整性、实际格式和型号来源取证。文档选择返回 `observed_resource_handoff`，
主 agent 接续真实链接的读取/下载，不能把交接当作已下载。现有公开二维包可用
`misumi_archive.py`；其他资料按已观察的普通网页链接及各自读取工具处理，不猜生成
接口。`artifact_acquired` 仅表示取得并检查了文件；原生二进制格式可能仍是
`native_reader_required`，须继续 NX 或对应阅读器验证。

回传真实产物、校验结果及失败原因，再让 Jev 从剩余需求和新观察中选择下一步。
生成仍在处理、超时或结果不明时，所有同次 CAD 生成选项暂缓，不能靠改选格式重放；
确认同一生成服务失败也保持此限制。主 agent 提供独立恢复依据后再开放，规格页或
其他独立资料仍可推进。点击已执行而后续读回失败时，保留上游执行记录，不能重写
为“尚未点击”。
只有主 agent 已核对、带证据引用的需求接受记录才能提供 FINISH；模型自报完成或
已有文件名不关闭需求。这是主 agent 编排的有界资料循环，不是后台常驻工程目标
控制器，也不是 Semantica 的语义验收。

Jev 的候选和置信度不是执行或验收依据。对“必须与人工 STEP 同格式对照”等明确
要求，主 agent 需核所选格式是否满足该项；另一个 NX 可读格式即使成功下载，也不能
关闭这个对照要求。需要先复核选择时单独运行 `supplier_acquisition_choice.py`，
由主 agent 依据实际页面接续执行，不把模型建议当作用户新增授权。

2026-09-26 复测：用户加载普通 Chrome 账号会话后，三个原失败型号均实际下载到
新文件，覆盖 Parasolid 与 DWG；另取得气管接头规格页面归档。这证明该会话下的
相应选型、格式选择、生成及落盘路径可用，不证明完全后台冷启动、失效后的密码
重登或十轮独立重启已经通过。此前无界面模式的失败保留；重启、模式与会话同时
变化，不能把恢复归因到一个未经单变量对照的原因。

## 历史固定 STEP 对照入口（不作默认选型）

本体的 [Jev 浏览器工具](../../../references/jev-browser-tool.md) 支持绑定已有 Chrome 标签。
网页账号须先核实，完整型号须先生成；型号 URL 不能替代这两个检查。实测发现，由页面选型产生的
`HissuCode` URL 直接重新打开可能返回 404，而首页中的系列入口正常；此时沿实际入口重新选型，
不把旧 URL 的失败解释为账号失效，也不猜供应商生成 API。

调用者从当前观察准备任务 JSON，选择 `backend=chrome_apple_events`，填写现有 tab ID、
真实按钮标签及 `#cad_format` 下当前提供的 STEP(AP203) 选项。起点为完整型号页、CAD 弹层关闭。
参考已观察的 `.cad-dl-button` 与 `.new_cadDl a.m-btn--dataGenerate` 补充自定义按钮。
文件记录必须在项目私有目录；账号、tab ID、个人资料名不写入共享 skill。

```bash
python3 scripts/misumi_browser_download.py \
  --task /private/project/browser-task.json --part CONFIRMED-PART \
  --download-dir /actual/browser/downloads --output /private/project/new-run \
  --policy jev --delivery browser
```

入口自动使用父本体的独立 Jev 环境。`--policy fixed` 使用相同的 DOM 输入、前置条件和文件验收，
适合已知流程与对照实验。两条策略均以“打开下载 → 核对格式 → 单次生成 → 等待文件 → 独立校验”
为边界；模型只能从满足当前前置条件的动作中选择。意外中断保留现场，不盲目重放。
输出中的 `download_verified` 绑定新文件、ZIP CRC、精确型号、AP203 和毫米单位；它不代表 NX
重新打开或机械适用性已验证。相同字节可关联已有的原生核验记录，并注明本次未重新执行 NX。

Chrome 可能只允许第一份文件，后续页面仍显示成功但下载被“多个文件下载”权限挡住。
先读下载状态并按用户授权处理该站点权限；不要把生成成功当作落盘成功，不循环重登账号。
用户手动允许多文件下载属于准备条件，不计入无人值守执行成功；保留准备中的人工介入。
助手临时开启的 Apple Events JavaScript 设置则在完成或失败后恢复原值并核对。

可显式选 `--delivery observed-url`，只下载本轮页面实际产生的官方文件链接到新目录，不推导 URL。
此模式需要独立核对普通 HTTPS 路径：浏览器与命令行可能使用不同的现有网络代理，TLS 失败必须记录。
不得静默更改浏览器或系统网络配置，也不把这一模式的结果计为浏览器自动下载的成功。

## macOS 冷启动与不同 CAD 界面的实测边界

2026-09-25 实测，`open -g -j` 或 NSWorkspace 的 `activates=false` 不能证明 Chrome
自身不会激活；即使带 Headless 参数，经 LaunchServices 启动后立即发送创建窗口命令，
仍曾出现前台切换。启动后隐藏、再切回原应用不能记为“不转移焦点”。

用户已授权完全退出和重启 Chrome、并要求不占前台时，已验证的路径是直接运行 Chrome
可执行文件，以 `--headless`、明确配置的正常用户目录和已观察的账号页面 URL 启动。
让 Chrome 自行加载登录会话，不读取或复制 Cookie、凭据或个人资料文件。
Headless 未指定用户目录时可能使用临时隐身会话，不能据此判断原账号失效。
先从系统读回本轮 PID、初始化完成及 `activationPolicy=prohibited`，再绑定启动时
已经创建的网页、核对网站账号；不向尚未就绪的进程抢发创建窗口命令。
账号、用户目录、窗口 ID 和测试记录留在项目私有配置，不固定到共享 skill。

冷启动验收要连续覆盖启动前、网页操作和退出后的应用激活事件及前台采样；浏览器主

# 工程、工具与经验形成同一工作系统

状态：**重构中，2.0.0-rc.6 整合候选**。用户用自然语言说明目标与条件，Agent 还原问题、选择能力并组织验证；工程本体维护当前 Project，memory 保存可回查的过程与经验。二者随同一仓库构建和发布。

## 对象、方法与实现

工程对象与其模型分开记录；模型条件、来源陈述、真实观察和推断保留身份。规范通过锁定 ggen 生成共享合同，Rust 执行明确检查和数据处理。工具提供各自范围的调查、计算、制品或运行证据。采用要求回到同一对象、修订、条件与验收。

Agent 负责开放式解释、比较、提炼和下一动作选择。专用判断服务依赖已从本候选移除；核心流程无需其账号、密钥或网关。可选普通模型调用保持显式条件，不能把模型答案当作工程通过。

## Project 与 memory

Project 是当前工程事实、对象、来源、决定和采用的正本。memory 保存经验修订、时间线、失败、纠正、方法条件和因果未知。召回得到的经验经来源与 Project 绑定检查进入待核候选，不能直接支持决定或关闭验收。

真正使用经验后，记录它改变了哪个动作、实际结果以及代价；未用、拒绝、无帮助和返工同样保存。后续任务重新核来源与条件，不能把曝光或保存成功当成收益。

## 专业工具接续

GitContribute、LeanToken、REA、Jacobian、SmokingGun、flameox 与第七种专业能力 [electronics-design](../modules/electronics-design/SKILL.md) 按问题选择；每项工具的输入、实际程序、版本、输出、覆盖和未知都回到同一 Project。电子能力从一个 Skill 入口调度五个内部模块。上游安装与本项目最小差异见[工具接入](TOOL-INTEGRATIONS.md)，正式结果协议见[交接合同](../references/professional-capabilities.md)。

多个报告引用同一原件或测量，不自动增加独立证据。性能任务先保留原行为、输入和基线，比较时核环境、样本与测量条件；一次指标变化不证明原因或总体收益。

## 知识与工程实现

两卷方法书分别支撑对象/关系表达与主张/证据/验证；机械设计、运动、公差计量、制造装配和米思米资料按具体缺口组合使用。原页、版本、单位、适用与失效条件、反例需保留。命中资料不表示产品设计已通过。

CAD、图纸、BOM、制造与检验沿[工程交付](ENGINEERING-DELIVERY.md)的完整依赖。来源检查、几何观察、原生保存、独立重开、实物计量与工程采用分别核验。局部软件或历史案例通过不能关闭整个体系的未完成目标。

## RRSI 与当前范围

真实反馈可以提示理解、规范、实现或使用方法的偏差。冻结原目标和判据，提出有限候选，经独立验证决定采用或拒绝；没有可验证改进时保留基线。方法比较、开发回归与未见任务收益分别报告，见[有证据的改进](../references/regularized-evolution.md)。

专用判断服务目标按用户要求退出当前版本，其余工程目标、CAD16 与完整 Semantica 范围保留。安装闭环与工程能力分别验收，实际结果见[验证记录](UNIFIED-VERIFICATION.md)。

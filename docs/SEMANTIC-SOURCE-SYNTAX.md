# 来源查询的语法、集合与构造输入

本增量接续完整 Rust Semantica 的原语义验收，位于私有 `rdflib760-nullable-internal` 来源图入口。工程本体先区分输入、来源身份、构造条件、验证结果和采用；规范正本中的四项约束经锁定 ggen 生成对应关系，原 parser、planner、同一图会话与 Rust evaluator 执行。公开查询 `/1–4`、正式 RC4 和原63项目标保持原身份，不能由当前源码推断已完成安装。

`source_input` 保留原输入准备：全局 Unicode escape 展开与制表符展开，语法检查点记录处理后的输入、字符位置和原异常。超出 Unicode 范围与尚不能在 Rust UTF-8 查询中接续的孤立 surrogate 分开；没有把所有错误统一改成一个“解析失败”。原生解析器诊断和该固定来源的诊断不混用。

`source_collections` 在同一次解析中保留集合、嵌套集合及匿名属性列表的原构造次序，并使用相同的来源 Literal、谓词与空白节点得到物理三元组。后续执行仍沿现有 sealed 来源图入口。来源语法的表示与执行后的图结构不同，不能从扁平化图反推原始语法。

无参数 BNode 构造含随机输入。默认构造生成 `N` 加 UUID4 形式的身份；明确注入的可失败构造器仅作用于来源图入口。原始观测记录每次调用及返回值，接收时可据此固定构造条件，逐项比较未经改写的完整预期，并检查调用次数、次序及别名。另行检查正常随机生成、构造失败、失败后新查询、显式名称不消耗随机输入、重复构造值保持别名、旧入口不调用该构造器。有限样本不证明全球无碰撞，也不恢复历史随机状态。

来源证据为56个原始案例，涵盖20个集合/属性语法、8个实际 WHERE 执行及28个输入/异常案例；7项执行边界控制与它们分列。两项原 LC07/LC08 预期保持原样。原 LC04 的历史随机身份没有构造输入证据，继续保留原预期、显式失败与接续义务。不能用规范化随机名或换答案宣布它通过。

原件与固定运行环境、原始构造事件、完整查询结果和精确异常存于 `source_syntax_protocol_query_cases.json` 及其绑定回执；`QUERY-NUMERIC-PROVENANCE.json` 记录接续范围。来源对照是 development_replay；是否通过本次编译、完整相关回归、独立接收或正式安装，分别查当前源码身份的维护回执。孤立 surrogate、完整语法及动态 registry、其他平台与完整 Semantica 仍需各自验证。

方法接续复用 [工程探索](ENGINEERING-EXPLORATION.md)：先冻结原预期和可判别动作，再检查实际构造、解析、执行及错误阶段，依据结果决定修复哪个 owner。此次没有新增通用探索方法，记为 `no_delta`。质量、成本、曝光与后续任务的独立证据尚未齐备时，方法收益保持未知；局部查询对照不证明实际项目的机械方案或实物验收达成。

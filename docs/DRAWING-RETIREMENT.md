# 有源旧尺寸退役

当完整原件表明图中某尺寸已失去关联、且当前替代尺寸已按独立意图检验时，可以在副本上明确退役旧尺寸。此能力接续同一 Project 的图纸缺口，保留原对象版本、必要验收与旧失败。

`oev2.nx-drawing-retirement-params/1` 的 `retire_drawing_dimensions` 使用真实 ggen 从 `specs/modules/nx-sheet-dimensions.toml` 生成的意图。完整输入 SHA256、全尺寸清单及唯一观测签名共同限制作用域；不按名义尺寸值或跨进程 tag 选择对象。签名保留尺寸、单位、类型、所有者、关联位置、父对象观测及文字框，仅显式去掉临时 tag 和名称。签名是该原件内的观测身份，不表示持久拓扑身份。

删除前，已有 `sheet_dimensions` owner 检查全部保留尺寸的独立意图、当前父对象、图页成员视图、计算尺寸和非 retained 状态。目标必须 retained=true。原生包装器在调用 `UF_OBJ_delete_object` 前再次核所有者、类型与 retained 状态；完成对象遍历后才执行删除。SDK 返回零仍须由 `UF_OBJ_ask_status` 及实际剩余清单证明删除。每次删除后、保存后都重新核完整清单和原几何；失败保留尝试和返回，不继续保存部分成功。

`oev2 cad drawing dimension-inventory` 从完整原生接收包取得冻结所需观测。`compare-retirement` 重新检查执行原件，要求独立进程、相同 worker/runtime、保存文件完整字节与重开输入一致，并重新选择保留尺寸。旧维护与尺寸创建协议含义不变。当前实现只支持显式平行尺寸及保留意图完全覆盖的范围；不完整、重复或模糊的观测拒绝。

源码、软件回归、Windows 构建、实际原生删除和独立重开分别验收。尺寸关联通过不代表文字可读、不重叠、视图可见或制造图通过；实际展示、完整制造检验及工程采用仍有独立义务。Project 只接收有范围的事实与剩余缺口，不自动替换当前模型。新实现和局部开发回放不证明 RRSI 方法收益。

平台：纯检查在 Rust 支持的平台运行；删除执行限当前明确绑定的 Windows NX SDK/worker。源材料依据当前 SDK `uf_obj.h` 的删除与状态说明，实际 SDK 文件摘要、工具身份和结果保存于各次私有维护回执，不把设备路径或私有 CAD 纳入分发。

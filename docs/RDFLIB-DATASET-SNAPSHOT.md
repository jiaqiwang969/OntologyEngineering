`snapshot_rdflib` returns `semantica-rdf-dataset-c14n-v2`: injective UTF8 canonical JSON/base64URL predicate encoding for default/IRI graphs, five-triple reification for blank graph names, RDFLib 7.6.0 Color/refinement/individuation/Traces and original `n3()` strings sorted and joined with LF, without a final LF. Multiline literals keep original triple quotes and embedded LF; this historical field is not ordinary N-Quads serialization.

The original term domain distinguishes plain strings and explicit `xsd:string`, and preserves decimal scale and the first stored language spelling. The single existing session captures a lossless lexical projection during actual NT/NQ ingestion, checks its RDF1.1 projection against the existing parser's result for the same bytes, and retains actual source hashes. No caller JSON can install a graph or execution receipt. Snapshot cache follows this session's revision and is invalidated by the same mutation owner.

`SemanticDatasetIdentityDiagnosticPort::diagnose_identity` is an explicit new observation profile. Its input reuses the generated observation-time-only `SemanticRdfLibSnapshotRequest`; caller graph, digest, proof and authority fields are refused. Rust reads the same `DatasetSession`, checks the retained projection's actual core mapping against the current dataset, and reports both unchanged snapshots and their common revision. It groups retained language spellings by full original literal text, datatype and the original case-insensitive language key. The text digest in each reported alias is a locator, not the grouping key.

Original mixed-case symmetric graphs expose the identity boundary: reversing statement order can change the compatibility hash while the separate RDF1.1 RDFC identity stays invariant. `known_language_case_alias` reports an observed alias scope; it does not assert that every graph containing an alias has different hashes. When no alias is retained, stability remains `not_established`. A spelling already discarded by duplicate-quad storage cannot be recovered by this diagnostic. Original algorithm outputs, original observed hash sets and all old tests keep their identities; there is no arbitrary selected gold, lowercase source rewrite or claim that RDFC covers the complete original term domain.

`loaded_source_byte_sha256` copies actual retained load observations in their existing order. Supported deletion may leave historical load references; clear-all follows the original owner and clears them. These hashes are not a complete mutation ledger or source authentication. Generic updates invalidate the original projection, so this profile refuses instead of inventing missing terms. Observation time is limited to 1024 UTF8 bytes and the complete serialized diagnostic to 16 MiB; refusal does not mutate the dataset or revision. The old snapshot and parser budgets retain their original contracts.

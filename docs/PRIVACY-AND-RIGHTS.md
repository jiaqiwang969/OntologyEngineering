# 隐私、来源与公开发布

OntologyEngineering 默认把标准原文、企业资料和生产会话视为私有受控证据。公共发布
采用 **default deny + allowlist**：没有明确登记为可公开的资产，不进入公共包。

## 三层信息模型

| 层 | 典型内容 | 默认处理 |
|---|---|---|
| 私有证据层 | 标准原始 PDF、购买记录、MinerU/OCR 抽取物、企业文档、真实项目数据、会话与附件 | 仓库外保存；最小权限；不得公开 |
| 受控派生层 | 条款锚点、内部审读笔记、候选转述、原始生成图、模型事件和人工评语 | 私有或受限协作；逐项审查 |
| 公共制品层 | 原创讲解、合成案例、经清权利图、本体、查询、约束、脚本和发布 PDF | 白名单放行；保留版本与权利状态 |

哈希和逻辑 ID 可以连接三层，但公共层不得保存能够还原个人目录、账号、企业存储位置或
受限原文的路径与内容。

## 永不直接公开

- ISO、IEC、GB 或其他受限标准的原始文件及未获许可的复制/扫描/抽取物；
- 客户名称、供应商信息、真实产品参数、缺陷、事故、人员或现场照片；
- Claude/Codex/ChatGPT 会话、rollout、隐藏提示、附件缓存和临时文件路径；
- API key、token、cookie、私钥、密码、`.env` 和带凭据的配置；
- `/Users/<name>/`、`/home/<name>/`、`C:\Users\<name>\` 等个人绝对路径；
- 未确认输入权利的参考图、标准截图、商标、人物肖像或生成图；
- PDF、图片或办公文档中未清除的作者、软件路径、EXIF、批注和修订记录。

## 公共资产最低登记

每个公开资产至少记录：

- 稳定的 `asset_id` 与仓库内相对路径；
- SHA-256；
- 作者或生成方式；
- 输入与参考材料的权利状态；
- 许可证或发布依据；
- 是否含个人数据；
- 技术复核与公开批准状态；
- 对应书、章节和冻结版本。

`pending`、`private`、`internal-only`、权利不明或包含个人数据的资产一律不放行。

## AI 与 ImageGen

- 只提交有权使用的输入；不要把受限标准原文当作普通提示材料；
- 使用合成场景代替真实企业、产品、人员和事故；
- 把模型输出视为候选视觉或候选文字，不视为事实证据；
- 公共台账记录项目自己的 prompt contract、provider 名称、时间、哈希和人工复核；
- 不公开平台内部 skill、模型实现、私人 session、原始附件路径或密钥；
- 发布生成资产前同时复核输入权利、相似性、商标/人物、事实暗示和元数据。

## 本地与公开仓库隔离

推荐使用两个根目录：

```text
private-evidence-root/      # 原始来源、企业资料、受控抽取、会话；不进入 Git 公共历史
public-book-root/           # 仅接收白名单制品、合成 fixtures 和相对逻辑 ID
```

不要依靠 `.gitignore` 作为唯一保护。`.gitignore` 只防止常见误加入；正式公开仍需资产台账、
隐私扫描、人工复核和 Git 历史检查。

## 发布前检查

```bash
python3 scripts/check_public_privacy.py --root . --include-ignored
git status --short
git diff --check
```

随后人工检查：

1. 新增文件是否全部在公开白名单；
2. PDF 和图像元数据是否已清理；
3. 来源、图像和文字权利是否有明确状态；
4. 合成案例是否可能被误认成真实企业事实；
5. Skill/Agent 是否扩大了读取、写入、发布或授权权限；
6. Git 历史是否曾包含应删除的秘密或受限文件。

隐私扫描通过不等于版权已经清理，也不等于内容适合公开。

## 发现泄漏时

立即停止发布和同步；保留最小审计证据；轮换已泄漏的秘密；确认受影响的文件、提交、
release 和镜像；必要时重写 Git 历史并通知已获得副本的协作者。仅删除工作树中的当前
文件不能消除历史泄漏。

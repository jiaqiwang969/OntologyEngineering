# Explicit annotated source composition

The current candidate `specs/engineering.toml` explicitly declares `oev2.design/4` and `validation_encoding = "oev2.validation-groups/1"`. It shares repeated validation fields while retaining the same complete Design owner. Legacy flat1 and composed2/3 remain accepted with their original meanings and limits. Each source file <=4MiB; all root/fragment bytes <=8MiB; <=32 files. Relative paths, hashes, input formats and all existing link/alias/unknown-field refusals remain enforced.

A locked complete/1 foundation is permitted only with exact matching version/problem/purpose. `oev2.design-fragment/2` contains definitions and no independent Project. There is one complete semantic Design AST, existing cross-reference/field metadata/platform/constraint/interface validation, one RDF normalization and the same locked ggen renderer. A future canonical engineering.toml/2 can move the former full/1 bytes to one foundation; it must not declare two canonical fact stores. Tests use a separate complete source clone for this transition.

When canonical engineering.toml declares/2, the Rust build captures that actual root and every declared fragment by bytes/SHA. Formal2 validation/normalization/generation/publication requires this exact current capture; changes, even a matching updated callerSHA, require rebuilding the normalizer before current execution. Legacy1 code binding remains separate. Source checks occur during loading, after actual generation and before the existing atomic directory exchange. No unread/uncaptured source or schema downgrade can authorize publication; the previous generation remains intact on failure.

`oev2.normalized-design/2` preserves the complete old semantic AST inside an explicit new envelope with all input2 source identities. `design-composition-source.json` stores every original file/hash/size and parser byte/line/key locators. `oev2.generation/2` binds those sources and current compilation, preserving actual version identity rather than resigning wire1. Equivalent flat1/composed2 semantic products must have identical contracts, checks and interfaces; source/normalization/generation identities remain versioned. No derived-model, output or template budgets increase: the existing32MiB derived-model and16MiB other-artifact limits remain independently enforced.

Windows stable metadata observation uses GetFileInformationByHandle for link count rather than the nightly-only [MetadataExt link-count API](https://doc.rust-lang.org/std/os/windows/fs/trait.MetadataExt.html). The borrowed handle lifetime follows the stable [AsRawHandle contract](https://doc.rust-lang.org/std/os/windows/io/trait.AsRawHandle.html). Actual Windows execution/native qualification remains separate from the current macOS source/ggen acceptance.

This is bounded source composition, not engineering acceptance, an unlimited model loader, a second renderer or a separate Project. Whole19/19/22/13494/55, original74 SPARQL residuals and native/SDK qualification remain open.

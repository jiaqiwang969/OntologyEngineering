# METHONTOLOGY 生命周期与概念化产物
# METHONTOLOGY Lifecycle and Conceptualization Artifacts
#
# METHONTOLOGY（Fernández-López & Gómez-Pérez, 1997）
# 是最接近软件工程规范的本体构建方法：阶段明确、产物可交付

# ==============================
# 1. 生命周期总览
# ==============================
# 管理活动（贯穿全程）：进度控制、质量保证
# 开发活动（主线）：
#   规格说明 → 概念化 → 形式化 → 实现 → 维护
# 支撑活动（贯穿全程）：
#   知识获取、集成（复用）、评估、文档化、版本管理

# 与软件工程对照：
#   规格说明 ≈ 需求分析    概念化 ≈ 概要设计
#   形式化   ≈ 详细设计    实现   ≈ 编码
#   评估     ≈ 测试        文档化 ≈ 交付文档

# ==============================
# 2. 规格说明书（Specification）示例
# ==============================
# 本体名称：车间设备调度本体 (WorkshopSchedulingOntology)
# 目的：    支撑设备能力匹配、任务排产、冲突检测
# 形式化级别：形式化（OWL 2 DL）
# 范围：    设备/材料/工序/任务/工作单元；不含财务与人事
# 知识源：  设备台账、工艺规程文件、调度员访谈、IOF参考本体
# 用户：    调度系统（机读）、工艺工程师（编辑维护）

# ==============================
# 3. 概念化产物（Conceptualization）
# ==============================
# METHONTOLOGY 要求产出一组中间表格，先于任何OWL代码：

# (1) 术语表（Glossary of Terms，节选）
#   术语          类型      描述
#   ----------    ------    --------------------------------
#   Equipment     概念      车间中可执行加工/测量任务的装置
#   CNCLathe      概念      数控车床
#   canProcess    二元关系  设备具备加工某材料的能力
#   hasPower      属性      设备额定功率，kW，非负实数
#   Lathe_003     实例      3号数控车床

# (2) 概念分类树（Concept Taxonomy）
#   Equipment
#     ├── ProcessingEquipment
#     │     └── CNCMachine ── CNCLathe / CNCMillingMachine
#     └── MeasurementEquipment

# (3) 二元关系表（Binary Relations Table）
#   关系名      定义域       值域       逆关系        特性
#   --------    ---------    -------    ----------    ------
#   canProcess  Equipment    Material   processedBy   —
#   locatedIn   Equipment    WorkCell   contains      函数性
#   precedes    Process      Process    follows       传递性

# (4) 概念字典（Concept Dictionary，节选）
#   概念        实例标识        属性                  关系
#   --------    ------------    ------------------    ----------------
#   Equipment   serialNumber    hasPower, hasStatus   canProcess, locatedIn

# (5) 实例表（Instance Table，节选）
#   实例        所属概念    属性赋值
#   ---------   --------    --------------------------------
#   Lathe_003   CNCLathe    hasPower=15.5; hasStatus=Idle

# 产物的价值：领域专家不读OWL，但能逐行评审这些表格——
# 概念化表格是专家与本体工程师之间的"共同语言"

# ==============================
# 4. NeOn 场景化方法（概览）
# ==============================
# NeOn（2009）不规定唯一流程，而是给出9种可组合的场景：
#   场景1  从头构建（规格→概念化→实现）
#   场景2  复用非本体资源（术语表/分类标准/数据库Schema → 本体）
#   场景3  复用本体资源（导入/裁剪已有本体）
#   场景4  复用并重构（对已有本体做模块化改造）
#   场景7  复用本体设计模式（ODP，如"部分-整体"模式）
#   ……
# 工程现实中最常见组合：场景2 + 场景3
# （把企业已有的设备分类标准转成本体，同时对齐IOF顶层）

# ==============================
# 5. 评估与文档化
# ==============================
# 评估三个层面：
#   一致性  —— 推理器检查（无不可满足类）
#   能力    —— CQ验收查询全部通过
#   质量    —— OntoClean元属性审查（见 ontoclean-evaluation.txt）
# 文档化最低要求：
#   每个类/属性有 rdfs:label（中英双语）与 rdfs:comment
#   版本信息 owl:versionInfo + 变更日志

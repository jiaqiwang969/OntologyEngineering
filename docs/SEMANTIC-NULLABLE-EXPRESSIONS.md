# 查询表达式与聚合中的空值、错误和失败

这是完整 Rust Semantica 的内部实现增量，接续[字段存在性基础](SEMANTIC-NULLABLE-TUPLES.md)。同一个 spareval 执行器现在有一条私有的 typed 分支，用于分别传递正常 RDF 值、明确的 None、返回的 SPARQL 错误对象，以及抛出的 SPARQL/基础设施失败。`SimpleEvaluator::nullable_expressions` 默认关闭；没有新增公开 `/5`，也没有改变现有用户入口的查询合同。是否通过验证、安装在哪个版本，以绑定实际源码的维护回执为准。

工程本体要求“缺少事实”“明确空值”“表达式错误”和“执行失败”不能被程序悄悄混成一种未知。[注释规范](../specs/modules/semantic-nullable-chains.toml)规定这些含义及检查边界，锁定 ggen 生成合同索引与检查映射，Rust 在既有编译器、Dataset 和消费路径中实现；源推导预期、独立失败注入与真实任务反馈用于检验改动。该链条遵循“工程本体论规定含义 → ggen 生成合同 → Rust Semantica 执行 → 依据反馈检验改进”，不以生成或测试数量代替工程采用。

| 执行位置 | 本增量规定的行为 |
|---|---|
| 原始变量读取 | 缺失且无初始值时抛出新 NotBound；字段存在但为 None 或错误对象时保留这个返回值。明确 None 不读取被它遮住的初始 RDF 值。 |
| 算术操作数与 Expr 边界 | 直接变量操作数会把 None 转成抛出的 NotBound，或重抛原错误对象；子表达式返回的错误对象则进入运算的值检查。Expr 只捕获 SPARQL 错误并把它作为值返回，基础设施失败继续传播。 |
| COUNT | 跳过抛出的 NotBound，计入返回的 None 和错误对象。DISTINCT 先求值检查是否见过，未见过时再求值更新，保存第二次结果的身份。不能用一次求值的集合插入代替。 |
| SAMPLE | “还没选到”和“已经选到 None”是两个状态；选中 None/错误/RDF 后不再求值。一直没有选到时，结束输出一个明确的 None 字段。 |
| Group | 输入和累积完成后才产出组；消费输入或累积阶段发生失败，整次聚合中止，不产出看似有效的部分组。结束转换阶段的失败可能发生在前面组已产出之后，不能套用零输出结论。旧 RDF 分组键保留原来的哈希字节，避免新增值类型扰动已有分组遍历和 LIMIT 行为。 |
| Extend | 返回 None 时写入或覆盖明确字段；返回或抛出的 SPARQL 错误保留原行；执行或 RDF 转换失败向上传播。 |
| FILTER | 真值保留行；假值、None 或 SPARQL 错误丢弃行。Dataset/取消失败向上传播。原 Python 的直接变量分支会吞掉全部异常，这里选择的失败传播是显式 Rust 安全合同。 |

私有 typed 查询的图模式迭代器返回一次失败后就停止，再次请求下一行也不能继续消费并产出后面的成功行。尚未接通完整条件、错误或上下文语义的 `LeftJoin`、`OrderBy`、`Lateral`、`Service` 明确拒绝进入该分支；既有 HashLeftJoin 的字段承载测试不能替代这些操作的 typed 验收。

消费入口的直接变量、字面量和命名节点使用 Dataset 的内部表示，避免为读取一个原始值而额外经过 `ExpressionTerm` 转换或词法规范化。SAMPLE 直接取变量时，RDF/None/错误对象保持到实际结果解码处，只有 RDF 才要求 Dataset 转换。这不改变 Dataset 自身的表示合同，也不说明原查询解析器的规范化已经接续。

表达式编译仍由一个 AST 分派负责；旧分支与 typed 分支共用加、减、乘、除、正号、负号六个算术内核。最初的表达式增量只接通有界整数操作数，乘法结果形成 Decimal 后不能继续参与外层算术；后续[原始算式边界增量](SEMANTIC-NULLABLE-CHAINS.md)在同一实现中有限接通了带编译器来源标记的整数值 Decimal 算术子结果。外部 Decimal、浮点、日期操作数、小数商舍入、负 Decimal 零、未接通的类型以及范围溢出仍明确拒绝。整数除法仅接收精确整数商；除零返回 SPARQL 错误。这些限制不能解释为原 Python 同样失败，也不能称完整数值兼容；前轮接收记录保持当时的实现与范围。

独立预期取自保留的 RDFLib 7.6.0 源码，记录摘要见规范中的 source。它是有限控制流程的源推导表，本轮没有运行旧 Python。验证分别覆盖原始/操作数/Expr 边界、真实表达式上下文的转换失败，以及既有聚合和行消费者。新增的真实 Dataset 故障控制分别进入 FILTER、COUNT（含 DISTINCT）、SAMPLE 与 Extend，检查原失败类型、终止后的转换次数；SAMPLE 的直接变量另查原字段直至结果解码的保留。分组哈希控制同时比较选定旧/新键的实际字节流和 FxHasher 结果。实际执行通过与否另由维护回执记录。错误对象按实例身份区分，不能用相同诊断文本合并，也不能假称已复现所有原始异常文本和分配规则。

完整数值/函数/聚合范围、初始上下文的 thaw/forget/remember、原连接算法，以及原始 bindings 与 Semantica wrapper 的不同输出仍须完成。本文保留的旧 Group 消费已有计划中的变量键；缺失/None 的局部合并保持该旧路径含义。后续[数值聚合与来源分组增量](SEMANTIC-NUMERIC.md)通过显式 SourceAggregateV1 接通真实原始键、AS、显式/隐式空组、SUM/AVG 和顺序合同，独立保留旧 Group 对照；仍不等于完整上下文生命周期、任意计划或全部聚合验收。完整闭合并对照独立原预期前，不开放 nullable 查询 profile。旧 `/1–4` 和原观察保持各自身份；13494 项、19 模块/协议、工程证据和最终采用的范围没有因本增量缩小。

# 方法提炼与成熟度

## ABox、TBox 与规则分别放什么

- **ABox**：某次观察、模型版本、配方用途、来源、假设、试验与计算结果；某专家建议选一条路线也是一条有来源的主张，不是工艺能力公理。
- **TBox**：跨任务稳定的对象类别和关系，如主张依赖某份证据、测量绑定某个配置。具体尺寸、设备功率、客户要求和固定工序不作为通用类的必然属性。
- **CQ／约束／规则**：哪些事实可回答问题，哪些条件缺失或冲突，何时需要重审支持边。检查器执行成功只说明这套检查运行过。

Semantica 已有 Claim/Evidence、Measurement/configuration 等词汇时优先对齐。名字接近不等于语义相同：计算量、假设值和观察量不能一律归为 Measurement；制造批量口径也不等于物理量。书中有某个概念，不代表运行包已实现其全部规则。

## 不成熟的好想法怎样吸收

保留原想法要解释的现象，把它改写为可反驳的条件命题。列出适用对象、需要的事实、可能的替代解释和一个会改变决定的反例；再形成最小合同，做正例、单故障反例、信息不足例及兼容例。至少换一个领域检查：如果一离开原零件名称和固定参数就说不清，说明还没有完成抽象。

分别记录成熟度：**方法假说 → 合同可执行 → 合成反例通过 → 独立任务试用 → 真实效果复核**。这些标签描述方法的证据成熟度，不改变 refinery 的 candidate/proposed/committed/regression_passed/release_complete/promoted 生命周期。前者不是 registry 状态；后者也不是物理有效性的证明。

本模块提炼了九类方法。若方法检查的逻辑已覆盖新问题，而新输入只是另一种零件、材料或相机，就增加 ABox，学习结论为 no_delta。只有新增关系、判别条件或反例揭示真实语义缺口，才送根 domain-ontology-loop 形成完整 PackageDelta。例子的名称、编号、来源文件和参数全部改成独立合成数据；公开候选不带原项目追溯材料，私有来源索引单独保存。

## 因果链如何落到动作

`决定主张 → 必要功能 → 工艺作用／物理机制 → 实现条件 → 模型保真义务 → 验证证据 → 适用性判断`。

例如替代连接工艺时，先列出连接需要承担的密封、承载和传热功能。模型若预先绑定了全部界面，它只能研究该假设下的行为，不能反过来证明候选工艺能实现全部界面功能。观察到反例时先定位被反驳的支持边，再讨论补工序、改结构、换路线或补证据。

同样适用于机构：轨迹可实现不证明指定电机有足够能力；适用于视觉：未检出不证明未观察区域无物体；适用于成本：物理有效量不能代替实际投料量。共用的是因果与证据关系，各领域的数学、材料模型和采集算法仍归专业工具。

旧领域 skill 中的独立本体／规则不能只换入口名就称已合并。迁移时逐条保留真实 CQ、资产、正反例和权威归属；尚未迁移的局部检查不得为这个包的同一主张提供第二个正式语义结论。

## 从待决问题识别对象与关系

工程设想先保留原话、来源、服务对象、用途、错误选择的后果及当前决定。把“做一套设备”
展开为需要实现的功能、可检查的要求、条件和候选机制；不要先选熟悉的设备，再倒写需求。
需求尚未确认时保留候选解释。表达偏好只影响相应视图，口头建议只证明有人提出了建议。

能力问题（CQ）应能指出所问的对象、关系、范围和预期答案形式，例如“对这个配置，哪些
必要功能还没有适用证据”“改变这项条件会重开哪些决定”。先找已有表达和检查；仅在
确有新关系或判别条件时提出语义增量。业务疑问可以先留在缺口记录，尚未绑定 query、
输入和 oracle 时不能称为已实现 CQ。依据见第一卷第 3 章及第二卷需求、变化和依赖各章。

按以下关系审阅，沿用项目已有 ID 和记录；此表是建模方法，不声明新增 TBox 或完整检查器：

| 关系 | 要保留的限定 |
| --- | --- |
| 要求约束对象或功能 | 来源、采用范围、对象版本、工况、判据；指标目标与实测结果分开 |
| 设计或工艺实现功能 | 机制主张、必要条件、界面与失效路径；预期实现与已验证实现分开 |
| 某方案参与某次候选比较 | 决定、版本、比较范围和判据；优选/排除是这次评价的结果 |
| 证据支持、限制或反驳主张 | 来源活动、对象、条件、允许结论、未知与反例；文件用途不替代支持关系 |
| 活动取得证据或改变工程对象 | 输入状态、操作、预期输出、有效条件、资源和实际执行记录 |
| 活动依赖前置活动或条件 | 依赖类型、理由和来源；已知清单的完整范围，不能从没画边推断可并行 |
| 决定采用某版方案的部分范围 | 决定者、权限来源、证据、剩余条件与再审触发 |
| 文档呈现某个快照 | 受众、过滤规则、输入/产物摘要和发布范围；内部证据仍保留 |

一个方案在甲工况被优选，不会因此在乙工况自动优选；退出比较也不改变设计对象身份。
一张真实试验照片可同时用于说明和有界观察，但须有原始来源、对象和观测条件。生成示意图
不能证明实测性能，展示界面不能证明工具执行过；“用于沟通”也不能抹去真实数据的血缘。

## 从功能差异到候选比较

先统一比较的必要功能、对象版本、工况、数量与交付范围。候选的定义可以逐步完善；缺少
决定所需定义时记录欠定项，不伪造精确排名，也不阻止独立探索。用硬约束和因果证据筛选，
再比较仍适用的方案。权重、论文数、专家偏好和漂亮图形不能代替功能证据。

每次评价保留支持、反证、未知、追加设备/工序/维护的代价，以及保留、优选、排除或暂缓的
理由与范围。冻结只对明确的设计/需求/试验合同等版本轴生效。候选缺证、有效证据反驳候选、
本次试验无效分别处理；排除一种机制可以是有效进展。

## 把证据缺口变成活动

沿当前决定挑选会改变选择的未知量，再寻找可行的取证动作。资料检索、尺寸复核、计算、
仿真、台架试验和现场试制各有用处，不要求所有项目先仿真或先完成整套计划。

一个需要投入的动作接到原工作项上，按需要说明：目标主张/缺口、对象版本、输入与前提、
操作或模型、对照与独立实验单位、测量判据、原始数据去向、无效条件及资源。预先写出
支持、不支持、仍不能区分、记录无效时分别允许什么结论、下一步做什么；不要预填成功。
能借到设备、能在某时段使用、量程与精度适用、已经校准和获准运行分别有依据。

仿真先选能回答问题的最低必要保真度。用模型验证支持预测主张时，保留预测冻结、参数与
软件版本，以及校准和验证数据的血缘与顺序；按所需独立性选择留出、盲验或其他有依据的
方法。适用时由 `validation-lineage` 检查记录中的独立性，不能把所有探索性计算一律要求
盲验，也不能把拟合数据改名为验证数据。自制试样须能追溯制造过程及批次差异；扩大尺度时
明确新增的主要不确定性、前置条件、退出判据和允许外推范围，不固定样件等级数。

核对实际执行与结果时按活动 ID、版本和范围逐项对应。若 A 已验证、B 无效、C 已执行但
尚未审阅，C 仍开放；“完成记录数等于结果记录数”不能关闭它。试验产物、数据有效性、
主张适用性和决定采用各自记录，不能凭脚本成功或文件存在推进整体状态。

动作选择还需考虑是否可取得证据、能否区分替代解释、时间费用和不可收回的投入。没有
可信概率就不计算精确的信息价值。制造中的实施方法接
[P05 最小验证与 P11 投入排序](../../manufacturing-process-cost/references/decision-patterns.md)，
人员、资源、预算和依赖接[组织工作项](../../manufacturing-process-cost/references/organization-loop.md)。

## 反馈怎样改变下一步

读取新证据所指的对象、版本和条件，定位受影响的支持边，再决定保留、缩小、重审或重做。
对照新旧依赖，不能因删掉旧边而漏查旧承诺。影响清单说明哪些对象要重审，不证明每个对象
都已失效，也不证明物理因果关系；依赖清单不完整时显示未查范围。

分别记录功能/主张的支持状态、各活动的执行与有效性、采用决定、文档快照及 Semantica
生命周期。新证据可以撤回支持或重开义务，不能用只增不减的项目阶段掩盖退回。文件发布
可以只发布一份带未知项的研究计划；它不自动冻结设计、批准试验或放行产品。

输出从当前来源生成：一句话当前判断、改变理由、候选差异、下一动作与未决条件；需要时
再展开试验方案、预算、进度或提案。正式文档冻结输入和输出的精确字节，记录各自 SHA-256、
来源/分析版本、受众过滤及发布决定，保留被过滤的内部记录。文档校对、字节核验和适用的
独立审计分别报告，不能冒充 Semantica 执行或实物成立。

## 现有检查覆盖到哪里

`pattern-identity/scope/realization/change` 可审阅已声明的身份、范围、功能与变化；
`controlled-effect-contrast`、`representation-adequacy`、`validation-lineage`、
`acquisition-execution-mode` 等分别核对对应证据义务。具体输入合同以锁定包的
`method_evidence.py list` 和 `judgment_review.py` 为准，不能因术语相似直接映射。

这些检查不自动识别全部必要功能，不生成最优试验，不证明活动依赖清单完整，也不求解
资源排程或验证整份提案。尚未编码的活动计划、记录对应和视图一致性由明确的工程审阅
留证，机器语义状态保留 `not_run/unsupported`。有实际反例需要新增机器判据时，按根
domain-ontology-loop 提交完整增量；方法说明和记录模板本身不增加可执行语义覆盖。

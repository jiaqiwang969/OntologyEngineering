# 第7章：软件层开发 —— 支撑材料与证据边界

本章正文围绕一场 EPS 软件评审展开：Table 7 的 ASIL D 查询准确返回十个 `++`，但当前软件需求和架构仍是 Draft，单元验证是 Planned，报告只是空模板；推荐矩阵不能替代项目方法选择，更不能替代执行结果。

> 状态边界：EPS 内容全部是 `TeachingExample`。当前没有软件实现、目标构建、测试日志、覆盖率结果、异常处置、FFI 证据或批准报告；专家来源复核仍为 `pending`。知识门禁通过只表示当前输入满足当前编码的局部合同。

## 三层身份

| 层 | 当前对象 | 能回答 | 不能回答 |

## 当前软件链

```text
SG_NoUnintendedAssist [ASIL D]
  <- FSR_DetectUnintendedAssist [ASIL D]
    <- TSR_TorquePlausibility [ASIL D]
         allocatedTo EPS_ControlSoftware
      <- SSR_TorqueRangeCheck [ASIL D]
           allocatedTo SWU_TorqueMonitor
      <- SSR_InputPlausibility [ASIL D]
           allocatedTo SWU_PlausibilityCheck
```

`derivedFrom` 从下游指向上游。当前查询可以证明这条链存在，却不能证明两条 SSR 的范围、变化率、数据新鲜度、诊断可信条件、反应时间、运行模式、配置和标定已经项目化。

`requiredDevelopmentASIL` 只表示软件组件/单元因分配而承担的最低开发义务，不表示开发已经完成。两个单元均承接 ASIL D 需求；在没有 Part 9 分解关系和充分独立性证据时，拆成两个单元不会降低等级。

## 配置与标定边界

Part 6 Annex C 是规范性内容。配置数据的 ASIL 取其所作用的可配置软件的最高 ASIL；标定数据的 ASIL 取它可能违背的软件安全需求的最高 ASIL。配置数据/规格、项目采用的配置集、标定规格，以及量产发布的标定值和完成标定的应用特定嵌入式软件，分别有验证责任。C.4.10 只针对安全相关标定数据，要求采用 Table C.1 所列机制检测非预期改变；C.4.11 只规定标定数据的生成和应用，包括程序、生成工具与验证程序。配置数据由 C.4.1–C.4.4 另行治理；项目可以采用类似的额外完整性策略，但不能把它归给 C.4.10/C.4.11。文件进入版本库、CRC 或校验和一致不能单独替代这些结论。当前 EPS 只登记字段与开放责任，没有发布数据或发布验证证据。

## FFI 边界

`FFI-EPS-SW-001` 当前为 Open。Part 6 Annex D 是资料性、非穷尽的故障模型提示；其中时间与执行、内存、信息交换三类提示在 EPS 中被项目化细分为执行/调度、共享内存、通信顺序与陈旧数据、共享外设/驱动、错误处理与控制流五条通道。这五条不是 ISO 的封闭清单，也不证明已穷尽。ASIL D 软件分区的支撑条件保持为“专用硬件特性或等效手段”；MPU 是候选手段之一，不是被本章错误扩写成唯一答案。分区有效性证据要在软件集成与验证中取得。

## §4.3 与 Table 7

- 连续条目（`1、2…`）：相应 `++/+` 方法原则上适用，替代或不全选按 §4.3 说明仍满足要求。
- 备选条目（`1a、1b…`）：选择适当组合，优先考虑更高推荐度，并说明所选组合怎样满足要求。
- Table 7 的 `1a–1n` 是备选组；十个 `++` 是推荐候选，不是十项逐项强制。
- 手写 C 候选路线没有可模拟单元功能的行为模型时，背靠背对比为不适用；开发路线变化后判断重开。

## 当前门禁能做什么

- `CQ-CH07-01/02/03` 查询 SSR 派生、端到端追溯和软件分配前提；
- `CQ-CH07-04` 查询 Planned 活动、Draft 规格和 Draft 报告；
- `CQ-CH07-05/06/07` 查询 Table 7 与跨表推荐画像；
- `CQ-CH07-08` 查询 §10.4.5 在 A–D 下的要求/建议模态；
- 软件专属 Shape 拒绝非法上游、缺分配、开发 ASIL 降级和 Completed + Draft 报告；
- 集合/库存/矩阵 Shape 拒绝受控方法表的漏表、漏行、缺格、串格和错等级。

这些规则不能判断方法适用性、组合充分性、源代码正确、FFI 成立、日志真实或报告技术上可接受。当前十二表（Table 2、4、5、7–15）/62 方法/248 单元是冻结 oracle 的受控预期；Table 1、3、6 目前只有教学摘要，没有进入同等级逐格来源治理。只有实际运行与 oracle 一致，才能说本次受控范围通过，且来源专家复核仍是独立的人类门。

若继续扩展机器合同，候选对象包括：受控软件/构建/目标配置；方法适用性与失效条件；组合选择、理由、证据面和评审状态；逐用例执行、实际结果、异常与覆盖；FFI 通道、措施和集成证据。它们只有在能回答具体 CQ、触发门禁或承载责任时才应进入模型，字段数量不等于现实证据。

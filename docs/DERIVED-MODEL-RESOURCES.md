# Bounded derived-model resource profile

The complete design now exceeds the previous generation snapshot's 16 MiB per-file guard. The original `GENERATE-02` and `GENERATE-03` refusals remain recorded under that old implementation. This is a resource limit change; none of the engineering acceptance criteria, original source content or required checks is removed or relaxed.

The explicit `oev2.derived-design-model-resource/2` profile admits at most 32 MiB for the canonical generated design RDF only: generation-stage `model.ttl` and public `generated/model.ttl`. Every other generated/public file retains 16 MiB. Editable specifications and template files retain 4 MiB. Original engineering source inputs retain their existing 16 MiB boundaries. Public inventory retains its 256 MiB total and 10,000-file ceiling. No caller filename, basename match, nested path or unrelated `.ttl` file obtains a larger input allowance.

The std-only rules in `build_support/source_limits.rs` are shared with runtime through `oe_core::source_limits`. Generation derives a complete model, refuses an over-limit result, and then checks full input/output byte hashes with the same role-specific limit. Generation receipts identify this profile; new publication requires that exact profile. Reproduction compares all generated bytes and does not accept a partial model or truncation. Historical receipts retain their original identity and are not rewritten to claim the new profile.

The same canonical public-artifact limit applies to build-time public manifests, runtime public-source checks, fixed evaluator identity checks, and CLI inventory/install pre-read, copy and post-read. Symlink, complete manifest, byte-count, source drift and atomic publication rules remain. Normalizer source inputs are not the derived RDF and keep their original bound. Distribution archive/member and ZIP central-directory limits are separate and unchanged.

Boundary tests use real files with independent 16/32 MiB expectations, unchanged default refusals, complete hashes and over-limit/path counterexamples. Actual ggen, current builds, original failure retention and a new receiver establish this increment's evidence. A larger generated RDF does not prove complete Semantica migration, architectural completeness, a successful design or RRSI improvement. Finite resource limits remain explicit dependencies for future growth.

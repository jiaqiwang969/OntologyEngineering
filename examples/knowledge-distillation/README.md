# 有条件工程知识的凝练示例

[直线与旋转运动示例](linear-motion.json)从两页资料提炼八个有精确来源的片段，
用于比较运动型式、导向机理、加工条件和下一步选型输入。它是工作方法示例，
没有完成全目录凝练，也不是新的语义 schema 或知识数据库。

模式定义引用既有 [P-ID／P-CLAIM／P-SCOPE／P-REALIZE／P-CHANGE](../../references/judgment-pattern-source-map.json)，
正式含义从锁定 Semantica 包读取。领域条目只写对象、主张、条件、反例和出处，
项目里再填写实际参数、采用理由和变更依赖。继续使用已有
[方案记录](../../skills/manufacturing-process-cost/assets/templates/solution-record.json)，
不因新增目录另造通用规则或项目状态机。

凝练保留的关键区别：177 页普通直线轴承不适合旋转；221 页微型滚珠衬套支持
复合运动。它们对象不同，不能合并成互相矛盾的规则。加工导致的适用部位变化
也必须保留，不能为了缩短文字删掉条件。另一种独立旋转支承路线明确记为工程
假说，避免冒充目录已经给出的结论。

评价凝练质量时，比较能否回答原问题、保留反例、识别未知并追溯来源。相同陈述
可合并正文并保留各处来源和局部条件；相似名称或脱离上下文的同句不证明可以合并。
导航、广告、重复页眉及无关型号表不进入共用工程知识。数值、公式和混排表格未经
原页复核，不直接变成可计算参数。

每张卡还给出原理结构、加工区域或选型流程图在原页上的位置，供回读原图。
全文索引中的跨栏文本不代替箭头、图注、尺寸线和完整限制条件。

原 PDF 由 Drive 来源组件提供，下载后归回本 skill 的 `sources/`；Git 与核心 ZIP 不携带原件。
`source_sha256` 是原始下载页的身份；从分片恢复的是该原文件，哈希保持一致。
`assembled_sha256 + pdf_page` 是整本 PDF 的定位；从合并 PDF 重新抽页或渲染
所得文件属于派生文件，另记哈希。没有取得原件时，来源核验状态必须保留未知。

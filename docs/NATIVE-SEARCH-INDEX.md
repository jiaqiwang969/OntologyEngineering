# 原值搜索索引

工程本体规定含义 → ggen 生成合同 → Rust Semantica 执行 → RRSI 根据反馈检验改进。来源中的文字、类型与未知不能因软件表示而改变。本轮在现有 `GraphSearchIndex` 内实现有类型文档、查询、缓存和保存恢复；运输复用 specs 经真实 ggen 生成的 `SemanticNativeValueEnvelope`，没有新的图、Project、registry 或晋升入口。

普通字符串和原值适配共用码点 Text、倒排表、分词、打分、候选排序及 128 项 LRU。旧 API 和旧存储格式继续显式保留；`new_native` 开启原值 profile，禁止混用旧 API 或用普通 serde 把非有限数写成 null。原值节点输入是索引所需的标准化映射，尚未接入原 ContextGraph 的全部导入、图变更及 HTTP 响应。

文档身份与字段保留 Unicode 码点，包括 surrogate；confidence 保留 float64 位及 NaN/±inf。properties 可含 None 键；列表、元组、set 的 fragments 与 frozenset 的文本表示按原规则区分。set 迭代顺序由保留值提供，不声称重建 Python 对象的 hash、相等或别名行为。当前仅接受标准化 Dict 或假值 properties，过滤器键须为 Text；其他形态显式拒绝，完整原输入域仍未关闭。

原字段转换失败可留下已完成的索引变更；例如替换节点时先移除旧文档，再遇到 tags 类型错误，旧查询缓存仍保留原命中。资源或截止时间拒绝在暂存副本中处理，保持调用前状态。confidence 转换先于 tags；过滤器在真正检查候选时执行，缓存命中和无候选时不提前制造原版没有的字段错误。

宿主提供累计文本、访问和路径深度限额及截止时间；fragment 遍历延迟展开，repr 深度累计在同一路径。新存储 profile `semantica.explorer-index/2` 通过既有原值合同保存文档、postings、排序、原 float 位、缓存键及 LRU 顺序。恢复前验证载体和材料化的节点/链接/标量成本，避免共享引用绕过实际复制额度；恢复检查文档身份、规范化 ID、分词、postings、缓存结构和顺序。原部分失败形成的陈旧缓存 ID 仍可合法存在。源图摘要、修订与授权继续由调用宿主负责；此存储本身不证明与任意当前图一致。

原版真实 `GraphSearchIndex` 的 13 次变更、303 次查询是冻结开发对照：比较文档、postings、查询分数/诊断、失败状态、缓存和逐次保存恢复后的行为。逻辑集合在观察投影中排序，不能据此宣称 Python set 迭代相同。输入、输出及原错误文字另存私有证据；Rust 目前对照错误类别，不宣称完整消息逐字兼容。资源拒绝和合法载体内的索引损坏另有反例。

上述行为须以当前源码测试、实际 ggen 生成/漂移和编译回执取证。平台范围是本次 macOS 上的 Rust 库开发验证；没有新增网络、UI/WASM、设备或独立接收证据，也不代表正式 skill 已切换。已暴露案例不属于 RRSI 未见验证，不从表示兼容推断工程质量或成本收益。

下一依赖是把这份原值索引与同一 DatasetSession 的原值 context、图修订、类型索引和原变更状态一起接通，再验证导入与各 HTTP 序列化差异、CSV。整个原库迁移、正式接收、真实反馈选用/恢复、实际项目的制造图与实测验收仍开放；其他项目保持原有闭环或暂缓状态。

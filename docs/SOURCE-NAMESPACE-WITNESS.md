# 有源命名空间状态与连续动作

完整 Rust Semantica 的当前内部增量，为同一 DatasetSession 增加生成的 `SemanticSourceNamespaceState4` 及六个组成类型。它记录共享前缀绑定、各自延迟建立的默认图/Dataset 管理器、前缀树引用、split/QName 缓存。读取不会建立管理器或改变缓存。见证类型的 `4` 不表示公共 source-session `/4` 已开放；实际选用仍查私有维护状态。

查询未命中缓存且调用者未给非空 namespaces 时，使用当前共享绑定；生成的 nsN 因而能供后续查询/更新使用。显式 namespaces 保留优先含义，缓存键仍依据原调用参数。完整 UPDATE 的临时管理器只向共享存储登记默认绑定，其私有缓存不变成持久管理器；输入构造早期失败与已进入后端的语法失败分别处理。NT/NQ 选图及缺省图枚举保留原初始化时机。

有源 DTO 可携带 N3 无法输出的 URIRef，原始 Turtle 异常与后续查询分别保留。没有放松 RDF 文本解析器的入口检查。缺失 QUERY 类型的 ASCII 错误从实际语法检查点取得位置，并复用现有 typed 原始错误格式化；其他未收到的诊断保持明确范围。

Rust 检查节点引用、前缀树关系、循环、规范节点编号、绑定/缓存唯一性与 QName 关系，输出先计字节预算再分配。结构一致性不能证明执行真实性，也不能识别一个仍然自洽的缓存条目删除；需要原始执行绑定与独立结果比较。当前无 strict-cache 执行路径，非空 strict-cache 明确拒绝。

独立原库输入共29组156动作（18/108、6/33、5/15），逐项核对结果/异常、版本、查询缓存和前后完整命名空间状态；另16个冻结结构对照与只读/预算拒绝检查。测试输入与原件位于私有 sources，不进入分发。实际通过数量、失败、二进制、平台与源摘要见私有维护记录，案例为 development_replay，不代表工程或方法净收益。

公共 Turtle 结果/见证、host 接收、同源生产程序与新根安装尚须接续。应复用现有 SerializeRequest 的字符串 format 和原连续动作 owner，再显式扩展版本；原 `/1–3` 的 NT/NQ 输出不改签。未完成的其他格式、原 UPDATE 失败、全部 Semantica 与原63项/CAD16/制造检验/最终计量义务仍保留。

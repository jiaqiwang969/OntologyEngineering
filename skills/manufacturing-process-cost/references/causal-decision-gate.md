# 工艺替代的因果与反证关口

用于从一条制造路线换到另一条路线，且将要提出“可交样、可整批制造、可按期交付”等高成熟度主张时。这里规定的是**项目输入与语义验收问题**；本文件不是可执行本体或第二语义后端。正式查询、shape、rule、receipt 只由项目绑定的 Semantica package 执行，按[语义执行与证据范围](semantic-use.md)报告状态。

## 两条不同的链

**物理因果链：**要求和使用情境 → 需要的功能 → 可能的失效路径及成立条件 → 工艺形成的结构或控制 → 该结构在指定产品状态下是否中断失效路径。孔、间隙或焊缝名称本身都不是“必漏／必不漏”的充分原因；连接性、压力、间隙和有效边界需由 CAD、仿真或实物证据分别确定。

**认识与决定链：**有来源的 ABox 观察／计算／专家建议 → 对象、版本、状态与适用性复核 → 对具体 `TrustClaim` 的支持、反驳、超出范围或未知 → 依赖这条主张的路线、试样、成本、交期和对外输出。仿真警讯是关于该算例的事实，不能直接变成实物失效断言；但若旧推荐使用了该算例作支持，原支持边必须重开。

## 项目投影的最小内容

1. **决定级别与主张：**是探索试验、条件候选，还是整批制造／交付承诺；主语绑定产品版次、工艺版次、数量、交付状态和有效窗口。专家偏好记录发言角色与原话，只是候选主张，不能自动视为客户变更批准。
2. **局部完整性：**列出至少一项本轮必要功能，并声明清单来自哪些图纸、要求、旧工艺意图及 CAD 特征检查；说明该清单覆盖的对象和未审资料。只有“已完整”的声明却没有功能条目，仍属于未建清单。没有完备声明时按 OWA 记“未知”；只在声明的对象和版次内用局部 CWA 报“缺少覆盖记录”。
3. **功能覆盖差分：**每项旧工艺预期承担的密封、隔离、支承、传热或其他功能，在新工艺中由哪个特征／接头／控制承担；给出其作用区域、失效机制、产品状态、验证方法及来源。旧工艺本身尚未实测的功能不能倒填为“已实现”。
4. **挑战事件：**记录来源、对象／版本／状态、目标主张或支持边、挑战类型、适用性和处置。直接几何反例可挑战布局覆盖；未校准或异构型模型优先挑战它所支持的模型假设，不作为真实工艺失败。挑战被处置须有新的证据及有权复核，不能只改文字状态。
5. **下游依赖：**每项路线推荐、工艺卡、首件计划、成本、交期和报告摘要连接其所依赖的功能与证据；变更后保留旧边的身份与退出理由，不能只看新图。

## Semantica 应回答的 CQ 与门禁边界

- 该高成熟度路线主张是否有非空、完整的功能清单及有来源的产品／工艺快照？
- 对每个必要功能，是否有同版、同状态、作用区域明确且经适用性复核的机制和验证证据？未验证可以留作候选，但不能升成整批可交付。
- 是否有开放的、确实指向必要前提或支持边的挑战？挑战只在参考模型范围内成立时，是否错误地被写成实物失败，或仍被当作生产能力支持？
- 当前摘要、工艺程序、报价和交期是否比已复核的 `TrustClaim` 更确定？若是，输出应回退到受支持的级别。

可用 Semantica 的 CQ／SPARQL 查询找缺口、SHACL 检查闭合交付字段、受限规则传播有来源的依赖变更，再由原生执行与回执给出**项目内的语义裁定**。这只裁定记录和支持关系；CAD 拓扑、接头物理、漏量、强度和实物放行仍来自各自工具与有权人。没有项目 Binding／Task、真实证据投影或完备性声明时，不出具“语义通过”，也不把查询空结果解释为物理安全。

**触发点：**工艺替代被提议时、新几何／仿真／试验进入时，以及形成整批路线、报价或交期结论前。独立的探索性研究可继续；受影响的高成熟度主张在开放挑战关闭前保持待验证。运行的 package、scenario、输入快照、receipt、finding 和受影响输出应一起留存。已有冻结教学案例通过，不等于本项目关口通过。

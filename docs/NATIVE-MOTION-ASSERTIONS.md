# 原生运动观察进入当前工程主张

显式 `cad_native_motion` 使用生成的 `CadNativeMotionAssertion1`，接续原 `kernel review --project`、work/Harness 的当前工程检查。原 `mechanism_motion` 继续检查分析驱动模型。`cad motion receive/receive-reopen` 的完整 Project 绑定已收拢到 kernel；原 CAD 原件接收与错误含义保持。

主张引用独立冻结的原 motion 或 reopen 请求，在 Project.evidence 登记该请求的完整摘要，通过 source_refs 和 affected_decisions 连接决定与下游。Agent 从自然语言维护这些记录；用户不填结构化表单。

| 命题 | 限定判断 |
|---|---|
| discrete_pair_checks | 完整原批次的声明位置、组件身份及 pair query 重新检查；非空采样/配对覆盖完整才支持 |
| sampled_no_interference | 上述检查成立且全部配对是原 no_interference；任一 interference 或 touching 为 violated |
| independent_reopen_bounded | 原完整运动/保存与独立进程重开接收，只覆盖被核的位置和有限几何 |
| independent_saved_reopen、continuous_collision_clearance、manufacturing_acceptance、physical_accuracy | 当前接收不证明这些完整义务，保持 unknown |

`append-only-project/1` 严格保留原 schema、project_id、目的、对象映射、所有旧来源/依赖和原顺序的完整旧决定。其他条件字节不变；当前对象的条件须为原工程前提版本，只允许在原 assertion 序列之后追加合法的本种类主张。其余完整 JSON 字段（包括事实、目标、必要验收、goal_support）相同；不能删除要求或修改载荷/材料取得支持。当前 revision、证据、决定和依赖可追加，但旧条目不覆写。条件结构变化规则为显式 /1，不修改历史 SHA 或历史请求，也不形成自引用摘要。

纯内存声明检查保持 unknown，当前检查实际重新接收原件并替换该项未知；其他种类的历史行为不变。原件缺失、源不符、条件变化或证据不足均保留 reason 和 unknown；已核干涉使严格无干涉主张 violated。原结果及下游受影响决定均留在 CheckResult，工程采用仍经原审查权限。不得接受序列化的 pass 或 received_scope 作为原件替代。

本增量的软件检查、实际原件回放、当前平台、安装选择、新原生资格和工程采用分别验收；接收历史原件不要求盲目重派 NX。当前进展见私有维护记录，原 63 项、20 条必要验收与所有失败继续保留。

命题结果的影响从该 assertion 和明确 affected_decisions 开始，复用 Project impact 追踪下游；不能将一项反证说成对象/来源发生变化。同一原件支持其他命题的可能性保留。来源或对象确实变化时，原 Project reconcile 的完整追踪不变。

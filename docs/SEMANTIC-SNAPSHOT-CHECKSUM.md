# 快照校验和

`kernel snapshot-checksum` 候选接续原 `version_storage.py` 的
`compute_checksum` 与 `verify_checksum`，由既有 Rust 内核接收 ggen 合同。
当前是否已构建、安装和正式选用须核最新维护回执；源码存在不授予接收资格。

显式 `plain_json` 接收原有限 JSON；`native_value` 使用既有类型载体保存
非有限浮点、元组、集合、非字符串键、代理码点与共享节点身份。
普通字典不会仅因含 `schema` 字段被自动解释为载体。载体尚不表示循环对象；
循环状态、跨请求共享身份与持久化继续由存储接续承担，完整目标保持。

计算保留原 ASCII 转义、排序比较次序、紧凑分隔符、数字格式和 SHA256。
验证保留缺少或假值 checksum 时提前返回，只移除顶层 checksum，并精确比较
摘要大小写。原异常作为完整结果记录；错误合同、载体或资源不足拒绝整次请求。
输入绑定摘要与原快照摘要是两个不同用途，既有工程来源摘要算法不变。

资源限制按阶段区分：完整请求及结果各不超过 16MiB；原生载体最多 65536 节点、
131072 引用、4MiB 标量存储与 128 层深度，整数载体也受这些大小限制。
编码阶段最多 16777216 次访问、128 层深度；65536 位限制针对数值比较工作区，
不作为整数载体的预先拒绝条件。原版整数转文本的 4300 位错误另行保留。
5 秒期限在编码器访问节点时检查，不覆盖输入解析、I/O、请求摘要和结果处理，
也不承诺整个请求在 5 秒内终止。假值 checksum 可以使未使用的大整数保持未序列化；
独立原版案例同时保留提前返回和实际计算时的整数转文本失败。

共享编码器复用现有原生值、精确数值、浮点文本和 CPython 排序实现。
独立排序函数可在默认配置下调用，不因此启用查询引擎的可选语义功能。
公共回归保留 141 个原版合成案例及两个大整数短路/文本失败案例；
真实 Project 的六个相关案例保留在私有维护区，
不进入分发。验收还需当前代码构建、实际入口、Windows、新根安装和下一次使用反馈。
通过校验和说明相应内容一致，不证明来源适用、机械设计合格或工程批准。

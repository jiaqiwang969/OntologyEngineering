# 幻觉控制三层架构
# Three-Layer Hallucination Control Architecture
#
# 原则：不试图"训练掉"幻觉，而是用本体在系统层面拦截幻觉

# ==============================
# 1. 幻觉的根源
# ==============================
# LLM 生成的是"在语言上最可能"的续写，而非"经过核实"的事实：
#   训练数据中没有 Lathe_003 的功率 → 模型按"车床通常15~30kW"编一个
#   提问超出知识边界 → 模型倾向于给出流利但无依据的答案
# 幻觉无法仅靠提示词消除——需要外部知识系统提供硬约束

# ==============================
# 2. 三层控制架构
# ==============================
#
#   用户问题
#     │
#   [第一层 生成前] 约束注入（Prompt阶段）
#     │   · 把本体词汇表/类定义注入上下文："只能使用以下设备类型……"
#     │   · 把取值范围注入："功率单位kW，范围(0,10000]"
#     │   · 声明边界："知识库中没有的信息回答'无记录'"
#     │
#   [第二层 生成中] 工具调用（受控通道）
#     │   · LLM不直接回答事实，而是生成查询（SPARQL/函数调用）
#     │   · 事实只能来自知识图谱返回值（见 text2sparql.txt）
#     │
#   [第三层 生成后] 事实校验（出口闸门）
#     │   · 实体校验：回答中的实体能否链接到本体个体？
#     │   · 断言校验：回答中的三元组是否存在于图谱/可由推理导出？
#     │   · 范围校验：数值是否通过SHACL形状检查？
#     │   · 一致性校验：是否违反不相交/函数性公理？
#     ▼
#   通过 → 输出（附溯源）；不通过 → 拒答或降级为"无记录"

# ==============================
# 3. 制造场景演示
# ==============================
# 问："Lathe_003 能加工钛合金吗？它功率多大？"

# 无控制（直接生成）：
#   "Lathe_003功率22kW，可以加工钛合金。"  ← 两个事实都是编造

# 三层控制下：
#   第一层注入：本体中 Equipment/Material 词汇 + canProcess 定义
#   第二层查询：
#     ASK { mfg:Lathe_003 mfg:canProcess mfg:TitaniumAlloy }  → false
#     SELECT ?p { mfg:Lathe_003 mfg:hasPower ?p }             → 15.5
#   第三层校验后输出：
#     "功率15.5kW（来源：设备台账）。知识库中没有该设备可加工
#      钛合金的能力记录（注意：'无记录'不等于'不能'，
#      如需确认请联系工艺部门）。"

# ==============================
# 4. 类型混淆的公理拦截
# ==============================
# LLM常见错误：把概念归入错误类型（嫁接幻觉）
# 防线：互不相交公理 + 出口校验

# 本体公理：
#   AllDisjointClasses(CNCLathe, CNCMillingMachine, Robot, AGV)
#   Equipment ⊓ Material ⊑ ⊥

# 拦截示例：
#   LLM输出断言 (Lathe_003, rdf:type, Robot)
#   → 与已有断言 (Lathe_003, rdf:type, CNCLathe) 在不相交公理下矛盾
#   → 推理器报不一致 → 该输出被拒绝

# 工程提示：不相交公理是性价比最高的防幻觉公理——
# 建模时对每组同层兄弟类显式声明 AllDisjointClasses

# ==============================
# 5. 溯源与审计（PROV思想）
# ==============================
# 每个对外输出附带证据链：
#   结论：    功率15.5kW
#   证据：    (mfg:Lathe_003, mfg:hasPower, 15.5)
#   来源图：  graph <http://example.org/graph/ledger>（台账，可信度高）
#   查询：    所执行的SPARQL原文
#   时间戳：  2026-06-11T10:30:00+08:00
# 价值：事后可审计"AI为什么这么说"；
# 高合规行业（航空DO-178C、汽车ISO 26262、医药GxP）可直接复用该审计链

# ==============================
# 6. 评测指标
# ==============================
# 上线前用标准问题集评测：
#   事实准确率   —— 回答中可校验断言的正确比例（目标 ≥ 99%）
#   拒答正确率   —— 知识库无记录时正确说"无记录"的比例
#   幻觉漏过率   —— 编造内容通过三层闸门的比例（目标 → 0）
# 经验：第二层（工具调用）贡献最大；三层叠加后漏过率可降1~2个数量级

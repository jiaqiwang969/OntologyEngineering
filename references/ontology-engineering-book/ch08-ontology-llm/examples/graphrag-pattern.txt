# GraphRAG：知识图谱增强的检索生成
# GraphRAG: Knowledge-Graph-Augmented Retrieval Generation
#
# 朴素RAG检索"文本块"，GraphRAG检索"结构化子图"

# ==============================
# 1. 朴素RAG的两个局限
# ==============================
# 局限1：结构丢失
#   文档切块后，"设备-工序-产品"的关联被切断，
#   检索到的块可能只含关系的一半
# 局限2：多跳失效
#   问"P001延期会影响哪些客户订单？"
#   需要 产品→工单→订单→客户 三跳关联，
#   没有任何单一文本块同时包含整条链路

# ==============================
# 2. GraphRAG 流程
# ==============================
#   用户问题
#     │
#   (1) 实体识别与链接
#     │     "P001延期影响哪些订单" → 锚点实体 mfg:P001
#     │
#   (2) 子图扩展（k-hop / 按关系类型走）
#     │     从P001出发沿 producedBy/contains/orderedBy 扩展2~3跳
#     │     得到：P001 ← W001(工单) ← O-2026-088(订单) ← 客户C17
#     │
#   (3) 子图裁剪与排序
#     │     按与问题的相关度裁剪（边类型白名单、路径打分），
#     │     控制在LLM上下文预算内
#     │
#   (4) 子图序列化 → 注入上下文
#     │
#   (5) LLM 基于子图作答（要求引用图中三元组作为依据）

# ==============================
# 3. 子图序列化格式对比
# ==============================
# 格式A：三元组列表（最忠实，token较省）
#   (P001, producedBy, W001)
#   (W001, partOf, O-2026-088)
#   (O-2026-088, orderedBy, Customer_C17)
#   (O-2026-088, dueDate, "2026-06-20")

# 格式B：自然语言化（LLM理解最稳）
#   "产品P001由工单W001生产；W001属于订单O-2026-088；
#    该订单的客户是C17，交期2026-06-20。"

# 格式C：JSON（适合函数调用/结构化输出链路）
#   {"entity":"P001","produced_by":{"workorder":"W001",
#    "order":{"id":"O-2026-088","customer":"C17","due":"2026-06-20"}}}

# 实践：格式A+B混合——三元组保证可校验，旁附一句话说明降低误读

# ==============================
# 4. 检索策略：向量 vs 图 vs 混合
# ==============================
# 向量检索：召回与问题语义相近的"描述性知识"（维修案例文本）
# 图检索：  精确获取"结构性知识"（关联、路径、聚合）
# 混合（推荐）：
#   实体锚定 → 图扩展拿结构 → 对图中实体挂载的文档片段再做向量检索
#   （例：拿到BearingWear节点后，再向量检索关联的维修工单文本）

# 变体：层级社区摘要（Microsoft GraphRAG, 2024）
#   离线对图做社区检测，逐层生成社区摘要；
#   全局性问题（"本月质量问题集中在哪类设备？"）检索社区摘要而非节点

# ==============================
# 5. 与本体的关系：GraphRAG 因本体而可靠
# ==============================
# 没有本体的图谱：边类型随意、方向混乱 → 扩展结果噪声大
# 有本体约束的图谱：
#   关系白名单来自本体属性定义（扩展时只走声明过的属性）
#   类型过滤用类层次（"影响订单"只保留 Order 类节点）
#   答案可再走一遍第三层校验（见 hallucination-control.txt）

# ==============================
# 6. 评测要点
# ==============================
# 多跳问题集：人工构造50~100个2~3跳问题
#   对比：朴素RAG vs GraphRAG 的答案完整率与事实准确率
# 典型结果形态：单跳问题两者接近；2跳以上GraphRAG优势显著
# 成本注意：子图扩展的图查询延迟 + 序列化token开销，
#   用边类型白名单与跳数上限控制（一般 k ≤ 3）

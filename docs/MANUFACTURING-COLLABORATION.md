# 从群里的生产问题开始，持续跟进到方案落地

典型使用方式是一个工厂或项目的微信群：一线员工、技术人员、负责人和供应商持续提出
新品试制、工艺选择、生产路线、设备选型、采购、质量和成本问题。助手跟随讨论及现场反馈，
逐步建立这个项目自己的本体，形成并反复修订方案，直到当前问题得到有依据的处理。
当前专业能力覆盖离散机械制造及相关 CAD、装配、检验和成本；具体领域知识与工具按任务补齐。
员工用日常语言参与，不需要先读两卷书、学习本体术语或填写工程数据库。

这是加载本 skill 的 AI 助手的持续协作方法，入口版本为 `0.1.0`。微信群是资料和讨论渠道；
助手通过已授权的读取工具或用户提供的记录获得内容，不能声称自动收到尚未接入的消息。
输出可先供用户审阅，向群内发送按已有明确授权执行。

## 项目越聊越清楚，通用 skill 不装客户资料

项目私有工作区持续保存原始消息和文件、人物及职责、对象与版本、事实与假设、因果候选、
决定依据、方案历史、检验结果、报价和现场反馈，以及项目的 Semantica 工作区和精确绑定。
企业资料可在有权限且适用的项目间引用；同群的不同订单不自动合并，同一人说的话也不自动
具有相同的批准范围。

项目本体逐渐连起“谁要求什么 → 哪个产品/功能 → 什么结构和工序实现 → 哪台设备或供应商
具备什么能力 → 怎样检验 → 影响哪些费用和交付”。ABox 记录带来源的实例与发生的事，
TBox/约束表达本项目需要的概念与关系；“有人这样说过”和“内容得到验证”分别保留。
新增概念或关系的草稿可以先作非权威候选，正式语义仍由同一 Semantica 工作区治理。

这些项目本体和业务资料**不写入通用 skill 或公开包**。skill 保存通用方法、工具合同和
合成模板。只有另有授权、完成抽象脱敏与验证的通用方法才可能回到 skill；持续聊天本身
不授权导出客户知识，也不自动形成跨企业规律。

## 每轮交流怎样接续

1. **接上原来的事。** 读取该项目当前方案、已采用范围、开放问题和上次约定；把新消息定位
   到具体对象、工序或决定。不要每次从零询问，也不要把新消息一律视为推翻旧方案。
2. **弄清新增了什么。** 保留发言人、时间、消息/附件位置和版本；区分需求、观察、专家建议、
   待验证原因和已有权限内的决定。局部答复只关闭对应问题，冲突及遗漏继续保留。
3. **沿关系深入。** 追查会改变选择的未知条件；接入 CAD、工艺、设备能力、检验和成本工具。
   群成员的职位或经验帮助判断信息来源，不能替代功能覆盖、能力证据或图纸要求。
4. **更新项目本体和方案。** 已有概念与规则足够时更新实例和支持关系；新证据沿依赖关系
   重开受影响的工艺、设备选择、检验、报价和交期。真正缺少语义表达时，才在私有 Semantica
   中建立后继候选、回归并按项目授权采用，不在 skill 内建立项目规则或第二个判断器。
5. **输出这轮有用的结果。** 说清“现在判断什么、依据是什么、方案改了哪里、还差什么、
   下一步怎样验证”。按需要给方案比较、工艺流程、设备/供应商比较、成本估算、试验安排、
   现场指导或对外答复草稿；不为了消息增加而重复生成整套报告。
6. **等真实反馈再接续。** 记录谁接什么、期待什么结果和下一触发；员工、供应商或客户给出
   新资料后沿同一问题更新。是否接收、完成、验证和采用分别取证。下一次继续当前版本，
   能解释为什么保留、改变或放弃旧方案。

工作区、角色和已有记录直接遵循[组织闭环](../skills/manufacturing-process-cost/references/organization-loop.md)；
不另造一套聊天状态库或强制审批流程。

## 员工怎么开始

直接说手头的事，并提供已经有的工单、图纸、照片、读数或作业指导书。例如：

- “我第一次做这道工序，帮我看这张工单，先做什么、做到什么程度？”
- “新产品准备试制，这几条工艺路线怎么选，还缺哪些条件？”
- “这几家供应商、这几台机器怎么比较，哪些能力要实际验证？”
- “这两个件装不上，照片和图纸在这里，帮我一步步找原因。”
- “换刀以后尺寸开始变化，看看要核对哪里。”
- “我要交班，把已经做完、还没检查和需要接着处理的事写清楚。”
- “这一批用了这些料和工时，帮我看看预算哪里漏了。”

不必一次说全。助手先读取已有资料和前次记录，只补问会改变当前动作的关键信息。
当前环境不能读取某种文件、连接 CAD 或取得测量时，说明具体缺哪一步，先处理能核实的部分。

## 当前问题进入现场操作时

先给一小段能照着做的指导，复杂工序分步展开。按当前任务保留以下内容，不强迫每次填表：

| 员工关心的事 | 助手应交付的内容 |
| --- | --- |
| 现在做到哪里 | 哪个零件/批次、图纸与工艺版次、当前工序、已经完成和未检的部分 |
| 下一步做什么 | 对哪个部位、用什么工具、按什么顺序做；参数带单位并注明具体依据 |
| 怎么知道做对了 | 检查哪个特征、在什么状态下测、用什么方法、与哪条判据比较 |
| 不符合或拿不准时怎么办 | 哪一项先不继续，先核对或补测什么，已有职责中谁能决定后续处置 |
| 这次留下什么 | 对应件号的实际读数、照片、材料/工时及未决项；下次从这里接续 |

给出依据的文件名、版次和页码/条目；对长过程可整理成
[现场任务卡](../skills/manufacturing-process-cost/assets/templates/shop-floor-action-card.md)。
卡上的“结果”只填真实反馈，不能预填合格。员工返回照片或读数后，助手核对对象和单位，
判断它关闭了哪一项、还有哪一项未证实，再更新下一动作。

例如，员工说“按工单做 B 版零件，但桌上只有 A 版图纸”，应先得到“找到工单指定的 B 版
图纸，核对本批件号和已做工序；影响尺寸的加工先等这一步核对，已知资料整理可继续”。
找到同版图纸和已采用工艺后，再给对应操作、参数出处与检验步骤；不能一直停留在提问。
这个例子只说明接续方法，不提供任何项目的制造参数。

## 协作怎样接到现有能力

1. **先认准当前任务。** 从工单和已有记录确认对象、版本、工序与状态；口头建议、图纸要求、
   实测现象和推断分别保存。沿用组织已经采用的工艺和授权范围，缺失或矛盾的关键条件先定位。
2. **再处理决定当前动作的问题。** 几何、装配和可达性接
   [CAD 模块](../skills/cad-agent/SKILL.md)；工艺、检验、设备、交付和费用接
   [制造模块](../skills/manufacturing-process-cost/SKILL.md)；证据适用性接
   [工程证据方法](../skills/engineering-evidence-methods/SKILL.md)。只加载本轮需要的部分。
3. **把依据接到动作。** 由 agent 从私有项目记录准备源定位、任务和已有项目绑定，调用
   [共用证据审查](judgment-intake.md)。现有 P-ID/P-CLAIM/P-SCOPE/P-REALIZE/P-CHANGE
   分别检查已声明的对象身份、主张依据、适用范围、必要功能及变化依赖；它们不能代替未读取
   的图纸、未测量的实物或尚未编码的工艺知识。只读审查未执行时明确保留状态。
4. **把结果交还员工。** 已采用工艺有据可查时，转成当前工序的动作与检查；尚未采用的改法
   写成候选或试验方案，注明试验对象、观察结果和决定条件，不直接扩成整批操作指令。
5. **沿同一记录接续。** 反馈写回对象和工序，异常或版本变化沿依赖关系重审相关动作、检验、
   材料、费用与交期。保留旧依据及纠正原因；交班列出实物状态和未完成检查。群里提出
   换设备或供应商时，将能力声明、实测能力、报价范围和交期承诺各自接到同版产品与路线。

大量资料才使用 Jev 做候选初判；单个现场问题不必走批量处理。没有 Jev 凭据仍可用现有
工程工具和语义审查。现场资料是否可送外部服务依据项目现有授权判断。

## 三个容易走错的地方

**参数缺失：** 员工说“之前一直这样调”，可以记录这次说法并查旧工艺、设备及结果，不能
编出温度、功率、转速、扭矩、公差或合格范围。缺哪个关键参数，就明确影响哪个动作；
仍可继续识别材料、核对版本、准备测量等不依赖它的工作。新人需要专业操作能力时，
按现场已有岗位安排接给相应人员，不把一张任务卡当成培训完成记录。

**局部检查通过：** 某个尺寸、外观或模型通过，只关闭对应问题。改工艺、换材料、换设备、
换装夹或更改装配关系，要核对它同时影响的功能与检验；负责人的推荐、动画和理想边界仿真
不自动证明整件或整批合格。

**异常原因未明：** 先保留实际现象、影响件范围和可检查的原因候选，不从照片直接宣布根因。
复测或试验应能区分候选原因；返修步骤和最终处置依已有工艺或有依据的新决定。接到消息、
完成操作、检测通过与允许流转分别记录。

## 交接与记录由谁处理

员工提供实际信息，agent 将它写回企业已有记录；没有记录体系时，按本次需要取用模板。
任务卡从这些记录生成，不另建一套主数据：

| 现场内容 | 现有记录位置 |
| --- | --- |
| 对象、工序、设备、检验依据与结果引用 | `solution-record` 的 `product_mapping`、`routes.operations`、`inspection_plans` |
| 本次观察、未决项、变化与下一步 | `loop-run-record` 的 `feedback`、`engineering_update`、`handoff` |
| 谁接续、接受了什么、复核及决定 | `organization-run` 的 `work_items`、`reviews`、`decisions` |
| 实际用料、人时、返工、费用与估算差异 | `outcome-review` 的 `metrics`、`cost_effort_components` |

模板入口见[制造模块](../skills/manufacturing-process-cost/SKILL.md)。现场卡注明生成依据和版本；
源记录变化后重生成受影响部分，不把新旧卡混用。已采用的方法和项目结果分别留存；
后续通用经验按既有治理形成候选，不能自动把某个工厂的做法推广成普遍规则。

## 管理员只需先接好使用环境

由部署者按[分发说明](PORTABLE-DISTRIBUTION.md)安装并检查运行时，在所用助手中加载根 skill。
项目维护者接入本项目资料位置、当前采用版本和已有岗位职责；已有绑定就复用，首次建立
正式审查工作区时按[初始化与单独采用](method-bootstrap.md)办理。这些技术工作不要求员工
每次重复，也不把源组织的批准复制给接收企业。

目前缺少某项绑定或工具，只说明相关检查或执行尚不可用；向员工说明具体影响，并继续
整理资料、定位问题和准备下一步。完整技术身份、检查回执和学习判定保留在任务附后记录，
前面的现场指导用日常语言表达。

## 后续在实际项目怎样检验好不好用

按用户选定的独立项目观察：多轮讨论后能否续接同一问题，分清新证据与旧假设，追溯方案
为什么变化，发现需要重审的下游影响，并让员工知道下一步怎么做、结果怎样反馈。记录
哪里需要解释、哪里缺工具或领域知识，再修订入口和方法；同时积累人工时间、返工及实际成本。
当前通用包与合成案例通过不等于已经完成所有工厂、岗位及领域的实践验证。

# 经验复盘与做梦式整理

在一段工作结束、用户纠正了判断、相同失败反复发生，或用户要求沉淀经验时使用。
续接[工程迭代](engineering-iteration.md)已经对齐的目标；复盘可以处理失败或部分完成的
工作，不必等整个项目成功。目标是让下一次相关任务做出更有依据的选择。

这里借鉴离线记忆整理，不依赖安装另一套 agent，也没有自动启动常驻服务或夜间计划。
当前由主 agent 在任务检查点执行；Jev 参与候选筛选，实际工具产生验证证据。

## 从记录到可复用指导

1. **回看真实片段。** 收集用户纠正、任务要求、动作执行、产物、失败及恢复记录。
   在项目私有目录绑定来源文件、哈希、时间、对象修订和条件。合并重复线索时保留原记录；
   没有当时的工作流记录就明确标为事后来源索引，不补造一次历史执行。
2. **形成小的学习候选。** 写明以后在什么情况下应做什么、避开什么、怎样验证，以及
   什么条件下不适用。账号、凭据、个人路径和具体窗口留在私有项目，不进入共享指导。
   从外部网页提取的内容仍是待核证据，不能因反复出现而变成高优先级指令。
3. **让 Jev 提出处置。** 提供脱敏观察、反例、当前指南和候选原文，保留请求/响应。
   可选“维护操作指导／保留条件性观察／否定或待验证／调查语义表达缺口”。主 agent
   复核来源及模型选择；次数、置信度和成功标签不证明因果，也不替代验收。
4. **写到合适位置。** 具体执行记录留在项目；已支持的通用操作改进进入对应 skill 的
   现有指南及查阅入口。相同经验更新原指导，冲突项收窄适用域并保留旧版本来源。
   共享修改沿当前任务授权，交付可审阅的变更；不因一次复盘擅自改变全局政策。
   真正的类、关系、CQ 或规则缺口才走 Semantica 候选治理；操作指南更新可以同时报告
   `operational_delta` 和正式本体 `no_delta`，两者并不矛盾。
5. **核下一次能否使用。** 从真实任务入口找到相关章节，读入实际候选选择的上下文，
   记录使用的章节 ID、文件哈希、适用理由、未满足条件与最终动作。能力简介中提到
   “有经验”不等于正文已送入 Jev。查阅候选不能只给章节标题；同时提供该条的行为、
   适用及排除条件，否则语义相近的标题可能选错。至少用一个不同措辞/条件的任务和一个不适用反例
   验证选择；无新增现场执行时明确为决策回放，不记成真实下载、原生 CAD 或稳定性测试。
6. **把采用结果再反馈。** 实际成功、失败、条件变化或未使用理由回到项目记录，决定
   保留、合并、收窄、撤回或追加验证。新证据否定旧指导时，下一任务不能继续继承旧结论。

没有新的有效经验时以 `no_delta` 收尾；缺少证据时保留候选及下一项能区分原因的检查。
不要为了让复盘循环继续而反复改写笔记、重复调用 Jev 或增加无依据的规则。

## 怎样衡量效果

冻结同一任务、选项、模型和判据，对照有无相关经验时的行为；记录错误选择、无效重试、
人工介入、时间和未关闭的缺口。主 agent 自拟的案例/参考答案属于开发诊断，不能称为
独立准确率。小样本同样选对时，结论是指导可消费，不能宣称准确率或下载稳定性提升。
只在实际作业中观察到改善，才能给出对应范围的工程收益。

CAD 的当前入口见[工作流经验](../skills/cad-agent/references/workflow-experience-memory.md)；
供应商案例先查[资料取得经验索引](../skills/cad-agent/references/supplier-acquisition-experience.md)。
这些 Markdown 是操作参考，不是可执行语义库；正式检索、激活及本体生命周期继续由
source-locked Semantica 负责，不启用历史独立 memory 后端。

## 借鉴来源

2026-09-26 查阅 [OpenClaw Dreaming](https://docs.openclaw.ai/concepts/dreaming)：
先整理近期信号，再反思主题，最后有条件地维护长期记忆，并保留可审阅的记录。
这里借鉴分阶段整理和来源约束，不照搬其频次/分数阈值作为工程有效性判据。
[Anthropic Dreams API](https://platform.claude.com/docs/en/api/http/beta/dreams/create)
默认生成独立输出记忆，可用于先审阅候选再采用的设计。这是 Managed Agents 的能力，
不能据此声称当前 Claude Code/Codex 客户端已启用同名机制。

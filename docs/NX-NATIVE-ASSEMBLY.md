# 有源完整装配与当前规范

完整 NX 装配继续由 `oe-nx-worker` 的 Rust graph、单位、变换、几何和文件检查执行。canonical `specs/engineering.toml` 的显式 `oev2.design/2` 将 `modules/nx-native-assembly.toml` 与原完整 foundation、composition module 组成同一个 Design；所有原字段、约束、来源和验证义务经当前锁定 ggen 生成共享合同。旧 `oev2.design/1` 的 4MiB 上限与原入口保持。

原 `create_assembly_fixture` 使用严格 UF 路径。另版 `create_assembly_fixture_nxopen` 只接受 assembly params `/v2` 与明确 `nxopen_loaded_part_entire` construction profile；Rust 先核本任务 prototype、单位、fully-loaded 与 work/display。固定 SDK 薄 ABI 调用一次已有 NXOpen BasePart overload；只读临时 builder 的实际默认引用集，Destroy 不 Commit，随后设置并回读明确整个原型引用集。不设置全局加载或许可、不自动降级 UF、不凭 component tag 通过。

正常返回、status 存在、完整有界复制与一次释放、unloaded0、entire reference set、instance/prototype/direct parent 都是必要条件。完整 occurrence 树、重复实例与去重 prototype、mm/inch、原始矩阵和非交换变换、原型自身全部几何、原 tolerance、保存文件闭包及真正新 PID/创建时间的独立重开继续各自检查。合法 load logical 仅0/1；原3/201、失败、未知与旧原件不改签。

solid-type cycle 包含子对象。先核已安装头文件对应的 type/subtype、owning part 与 occurrence，再让明确 body subtype0 进入 body-kind 查询；已声明非body1–6可过滤，未知值、非法 logical、type/owner 查询失败或真实 body 查询失败仍拒。诊断样本有界，完整遍历和几何检查不减少。

写者恢复 `/3`、`/4` 和 `review-set/v1` 仅核具体旧 preload/role 失败及每份原 review、文件/目录、job/dispatch/source、退出及当前 OS 身份，准入不同新任务。它们不重派旧任务、不复写旧状态、不把未知转通过、不产生工程采用或 CAD 资格。

本次规范整合与 Mac 软件检查不能继承较早 N3 的 Windows worker/controller/shim、原生创建或保存结论。新完整源须独立 Windows 构建、SDK输入核验、当前 producer 准入、新原生任务及保存/重开取证。即使几何通过，物理功能、正确图纸/BOM/制造检验与同 Project 的必要验收仍另验。完整19/19/22/13494/55范围保持开放。

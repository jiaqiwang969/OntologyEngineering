# 完整编译器输入的原生执行 /7

工程本体给含义，注释规范经真实 ggen 生成合同，Rust 执行并保留完整证据，反馈另验改进。此合同不新增 Project、registry、预算或进程 owner。

显式 `versions supervise-compiler7-native`、`versions reproduce-compiler7-native` 接续同一选定构建上下文。内部 driver 的 `build-compiler7-native-budgeted` 使用选定的 `oe-native-loader7-linker`。编译库必须由完整当前源码、Cargo manifest 和实际 Rustc intent 独立确定，不能用调用者声明推导执行授权。

共同的 source/profile6、side/stage6、SDK4、loader6 与 process6 是原样来源、预算与过程数据。外层 request/capture/supervision/reproduction 使用 `/7`，artifact 使用 `semantica.rust-full-native-compiler-inputs/7`。旧 `/6` 执行拒绝仅供 `/7` 的 adapter，不把新模式包装为旧协议通过。

完整库调用保留原始导出文件、对象、archives、完整有序 argv、源码/输出关系、实际同一父进程、命令预算、输出与全部前后内容检查。文件选项映射到同一 call 的相对保留路径，完整原路径和原字节另存。输入检查的 content-only 状态不授予原生执行。

`CodeNativeInvocationEnvelope7` 逐项保留真实原 `/3` 调用或完整 `/7` 调用。全库存均需独立核验。normalizer 与 runner 的原生 debug/type/location/OSO/signature 检查继续依据各自真实 `/3` 产出调用；不能从 `/7` 的 base 子步骤伪造 `/3` 记录。

build-script 仍只能沿原来精确的 metadata-only 参数合同取得相应观察。库调用不能供应 build-script 二进制，也不授权它发起编译探测。新的探测域若确有必要，须另建来源绑定的合同及独立验收。

两次构建借用同一总 deadline，失败保留全部现有证据，第二次未执行就保持缺席。两份完整二进制逐字节比较，不剥离 debug 或签名，不改 golden，不绕过 policy4。完整原 13494/19/19/22 与工程采用、六书、实际项目图纸/制造/计量/现场仍各自待证。

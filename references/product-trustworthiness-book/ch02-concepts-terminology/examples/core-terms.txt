# ch02 范畴与身份判断防错卡
# 状态：与 PTW-PC-02 候选合同同步；不是 ch12 TBox 或真实项目台账。

一、名称与身份

- 同名是候选匹配线索，不是 Same 的证明。
- 异名不证明 Different；别名、来源限定 ID 和历史编号可能指向同一对象。
- 身份判断至少需要：对象类型、边界、持续条件、来源、桥接证据、冲突处置、范围与时段。
- 证据不足或冲突未决时返回 Unknown；不得把“没有 same link”推成 Different。

二、对象范畴

- product / system / physical individual：工程世界中的被设计、实现或运行对象，各有类型相容的身份判据。
- artifact：需求、模型、代码、构建、报告、记录等工程工件；可以描述、规定、实现或记录产品，但不是产品本身。
- class：可有多个实例的概念；individual：任务中的具体对象。类名相同不合并个体，个体同名也不等同。

三、ISO 26262 局部边界

- item（1-3.84）：ISO 26262 所应用、在车辆层实现功能或部分功能的 system 或 system 组合。
- system（1-3.163）：由 components/subsystems 构成，至少把 sensor、controller、actuator 关联起来。
- element（1-3.41）：system、component、hardware part 或 software unit 的统称；不是固定中间层。
- 这些术语留在 ISO 局部 adapter；通用类不能由删除 iso262: 前缀生成。

四、其他范畴

- function：要求对象提供什么能力。
- behavior：对象在输入、状态、时间和环境下怎样响应或被观察。
- concern：正在保护或评价哪一类价值/损失。
- measure：量、方法、单位、窗口、模型与不确定度绑定的观察。
- state：对象可进入和退出的条件，如 Candidate、Degraded、SafeState。
- role：对象相对活动/关系扮演的身份，如 DUT、ReferenceUnit、Reviewer。

五、禁止关系

- “工程工件 is-a 产品”（把描述物当被描述物）
- “DUT is-a 产品类型”（把活动角色当本质类型）
- “安全状态 is-a item 类型”（把状态当永久类型）
- “功能 is-a component”（把能力当实现对象）
- “可用性等价于可靠性”（把 concern 强等同）

正确方向是使用有类型关系：describes、specifies、implements、observes、playsRole、hasState、usesMeasure。

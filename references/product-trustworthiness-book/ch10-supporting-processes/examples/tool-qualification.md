# TCL2/TCL3 之后怎么办：工具资格认证四方法
# Tool Qualification Methods

来源：ISO 26262-8:2018 §11.4.6（Table 4/Table 5）+ §11.4.7（增强使用置信细则）+ §11.4.6.2（文档要求）。
接续 `tool-tcl-decision.txt`：TCL 判定决定适用 Table 4、Table 5，或在 §11.4.6.1 下无需 qualification methods；本文继续回答适用时如何选择方法。
本体对应 `ontology/tool-qualification-tables.ttl`（两表 32 推荐单元可查询）。

## 1. 四种方法，两张表（§11.4.6.1）

TCL3 按 **Table 4**、TCL2 按 **Table 5** 选方法（TCL1 无需认证方法）。四种方法均为备选条目（1a–1d），按 §4.3 组合规则选用并给理由：

| 方法 | 细则 | Table 4 (TCL3) A/B/C/D | Table 5 (TCL2) A/B/C/D |
|---|---|---|---|
| 1a 增强使用置信 | §11.4.7 | ++/++/+/+ | ++/++/++/+ |
| 1b 工具开发过程评估 | §11.4.8 | ++/++/+/+ | ++/++/++/+ |
| 1c 软件工具确认 | §11.4.9 | +/+/++/++ | +/+/+/++ |
| 1d 按安全标准开发 | （ISO 26262/IEC 61508/EN 50128/DO-178C 等） | +/+/++/++ | +/+/+/+ |

Table 4/5 的脚注明确限定：没有一项安全标准完整适用于软件工具开发，只能选择其中相关的要求子集。因此 1d 不能简化成“工具声称按某标准开发”即可。

**正确读法是“推荐画像”，不是“强度分数”**：
- TCL 先决定适用表：TCL3 使用 Table 4，TCL2 使用 Table 5；ASIL 再决定该表中四种备选方法各自的推荐等级。
- 1a–1d 是同一个备选条目组。§4.3 要求选择适当组合，推荐度较高的方法应优先；即使只选一种方法，也要论证该选择满足相应要求。单个 `++` 不等于该方法逐项强制，多个等级也不能求和成“认证强度”。
- 两表在 A/B 的四维画像相同，在 C/D 则以不同方式调整 1a–1d 的优先级。因此不能把 Table 4 与 Table 5 简化为一条可单调排序的强弱刻度，也不能仅凭 `++` 数量比较资格认证充分性。

## 2. 增强使用置信不是"用过就行"（§11.4.7.2）

主张该方法必须同时提供四类证据：**同一目的、可比使用场景、可比运行环境、相似功能约束**下的既往使用；充分且适当的数据；工具规格未改变；以及对既往开发中的故障和相应错误输出进行系统积累。
注意 NOTE 的显式切割：**Clause 14 的 proven-in-use 论证要求不适用于本节**——两者是不同机制，不可混引。
此外，§11.4.7.3 要求分析和评价既往使用经验所规定的信息，§11.4.7.4 将论证有效性限定在已评估的工具版本；“同型号工具曾经用过”本身既不充分，也不能跨版本继承。
（对照 ch10 已有纪律：教学假设不冒充标准结论；引用条款时 shall/should/NOTE 的力度必须如实。）

## 3. 认证要留下什么文档（§11.4.6.2 a–h）

工具标识与版本；最大 TCL 及其评估分析引用；所考虑用例下可能被直接违背的安全需求的最大/特定 ASIL；
**认证所覆盖的配置与环境**；执行认证的人/组织；所用方法；措施结果；识别出的使用约束与失效。

> 教学要点：d) 项把认证钉在**具体配置与环境**上——换版本、换配置、换环境都可能使认证失效，
> 与"TCL 属于 usage 而非工具品牌"（`SoftwareToolUsageDescription` 作用域纪律）同一逻辑的延伸。

## 4. EPS 教学案例的落点

- 代码生成器（TI2×TD3→TCL3）：按 Table 4 选法。教学场景设 ASIL D，1c 工具确认与 1d 按安全标准开发的推荐度高于 1a/1b；项目仍须选择适当组合。§11.4.6.2 要求记录所用方法和措施结果等 a-h 字段，项目还应另行保留 §4.3 要求的组合或单一方法选择理由。
- 静态分析工具（TI2×TD2→TCL2）：按 Table 5 选法。ASIL D 下应优先考虑 1c；若供应商能提供满足 §11.4.7 的使用历史，可将 1a 纳入候选组合，但仍要论证最终组合，而不能用等级求和代替判断。
- 两者的认证证据在本书 ABox 中**刻意未展开**（`exampleStatus` 已声明）——认证是真实工程活动，教学仓库只建"义务与方法选择"的结构。

## 5. 本体化视角

复用 ch07 的 method-table 模式，并用 `appliesToTCL` 把方法表绑定到 TCL 等级——
"哪张表管我"由 TCL 判定结果直接导出（TCL3→MT_8_4，TCL2→MT_8_5），一条 SPARQL 即可回答
"我的工具在 ASIL D 下哪些资格认证方法具有更高推荐度"。每个推荐单元还用 `recTable` 显式绑定所属表，防止两表中同条目号的方法串格。门禁守转录保真；项目组合是否充分仍须由工程证据和 §4.3 理由裁决。

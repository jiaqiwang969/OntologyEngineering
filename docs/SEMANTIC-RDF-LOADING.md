# 来源语义的 RDF 加载

本轮接续完整 Semantica Rust 迁移。工程本体规定来源和身份的含义，锁定 ggen 生成合同，Rust 实现执行并保留失败证据；开发回放用于判断本次改法，没有证明一般方法收益。原63项要求、所有格式/协议/平台与工程交付范围保留。

`vendor/oxttl` 是原已使用的0.2.4解析器，保留上游 MIT/Apache 许可证。默认严格解析继续使用原状态机和词法器。内部 `source-literal-internal` 由现有默认关闭的 `rdflib760-nullable-internal` 接通：在真实字面量构造处保存原始文本、显式 datatype 和语言大小写，按对象栈位置随每个实际 quad 输出。不得从已经折叠的 RDF1.1 对象反猜来源，不建立第二个 Dataset 或语义权威。

`DatasetSession` 的私有来源入口复用当前空白节点映射、图选择、来源规范化、core绑定、发布、revision和缓存。plain和显式xsd:string可以是两个来源对象而对应同一原生对象。语言标签的来源拼写保留，身份比较仍使用原规则。命名图及空白图被保留；来源查询原有默认图范围没有因此扩大。

输入容量、去重后的原生quad数量以及精确序列化数据集字节上限保持原口径。重复输出100001次不等于100001个对象。prefix展开产生的新原生对象用现有NQuads计数器提前检查，最终仍经过原publisher检查；失败不发布、不更改原版本或清掉温缓存。

独立原173步LU和53步LP观察完整保留；本轮仅接收显式列出的48项Turtle/TriG加载与快照，另有LD重复输入的两项原观察。原生空白标签允许全图一致的双射，字面量字段、图位置、对象重复关系不能被抹去，快照仍比较原完整字节和摘要。查询、ConstructDTO、其余格式和完整update不得凭加载子集计为完成。原更新可能部分写入再报错的已知失败保持，公开原子更新合同不被改签。

新增specs正本登记此解析器为已有semantic_runtime的实现子组件，未增加事实owner。公开query1–4保持原意，无profile5。六书资料、NX/SolidWorks/inCAD 及实际项目的专属精度验收继续是整体交付义务。


## RDF/XML 接续

`vendor/oxrdfxml` 接续原已锁定0.2.4，同一解析器把属性、文本、XMLLiteral和重化对象的来源事实显式传到每个实际三元组。事实随对象传递并核对原生投影，不按折叠后的字面量反查。语言来源保留原大小写，空语言在私有来源入口清除继承；普通原生严格/lenient语义保持。

独立新增60步XF原版观察完整保留，接收48项加载/快照；另外接收旧LU中的11项NT/NQ/XML加载/快照。比较完整DTO、变更数量、版本和原快照，空白标签只允许全图一致双射；失败还检查温缓存和原数据不变。方法是现有Project/work/Harness的实例，通用owner无新增，收益仍需后续任务评估。

这些结果增加已接收范围，未改签上一轮和原有失败。JSON-LD、TriX、ConstructDTO、命名图来源查询、完整update和公共wrapper仍有独立义务。继续遵循工程本体含义、specs正本、锁定ggen、Rust执行、冻结反馈比较的接续方式。

首次回放还揭示XML片段命名空间、相对datatype、CDATA/文本分段差异。私有来源路径保存原始datatype，并从同一XML事件流取得原版词法表达；每项事实与实际原生构造对象显式成对。原生数据保留自己的解析结果，来源映射保留原版表达，二者不因字符串不同而混淆。未知datatype和命名图的来源查询仍保留原有拒绝范围。


## JSON-LD 接续

私有来源入口沿用实际 `oxjsonld0.2.6` 解析器及原 DatasetSession。每次字面量构造保留原始 JSON 标量种类和实际原生值，按本次发射位置绑定。数字/布尔值复用既有 Python 表达能力，显式 datatype 不触发第二次词法转换；字符串沿用既有规范化。原版通过 Graph 解析并只遍历默认图，命名上下文在 override 之前过滤，不能摊平后声称等价。

实现前冻结 JL110 原动作，接收88项加载/快照及既有LU的3项；保留普通入口、旧预期与完整验收。上下文网络不可用属于当前明确离线权限，不能说成原解析器普遍不支持。嵌入JSON的非有限数、更多原版边界、其余格式、ConstructDTO、update及命名来源查询仍有独立义务。方法收益只由冻结质量/成本/曝光及后续任务评估，不由回放通过推断。


## TriX 与 ConstructDTO 接续及原生覆盖合同

在原 DatasetSession 的 source/core 绑定中明确保留“原生 RDF 1.1 无法表示”的空绑定，且只在严格构造确实失败时允许。原版 TriX 中的字面量主语、非 IRI 谓语、相对/空标识符仍作为来源数据完整保留；来源快照、计数和清除读取全部数据。需要完整原生表示的查询、更新、序列化、快照、验证和搜索入口先拒绝不完整覆盖。普通完整表示、既有公共合同及默认关闭的私有入口身份继续保留。

TriX 复用锁定 quick-xml 事件读取并移植原 RDFLib 状态转换，保留本地 xml:lang、datatype、Graph 标识符和显式空白节点；不把 base 拼到原版仍保留的相对标识符。ConstructDTO 先完成全部转换再提交，重载保留同一空白节点，零新增仍推进 revision。失败保留原状态与缓存；全来源字节和数量预算在原 publisher 检查。外部实体不读取文件或网络，内部简单文字实体按冻结观察接收；完整 DTD、编码与更广 Python DTO 类型仍为剩余验收，不能从本轮推出完整兼容。

实现前冻结 TC238，接收196个非重置动作和原LU12个动作，按完整原结果核对。一般探索仍沿 Project/work/Harness：本轮反例否定“每个原始来源项都能放入标准 RDF”的假设，验证明确覆盖合同及恢复，不删除原需求。软件回放、候选可行性、整体工程达成和方法收益分别评估。

原版 TC118/120/123/125 显示：非 IRI 谓语可以加载，但来源快照明确失败。当前移植保留这一失败边界和缓存不变，不把加载成功解释为所有消费者都可用；字面量主语的原快照则按原结果保留。


## 私有 source UPDATE 的整段准备

当前候选在既有 PEG、来源字面量 registry 和 SourceArena 中加入整段 UPDATE 准备；普通 native 原子更新及公开 profile1–4 保持原合同。操作顺序、各段 prologue、SILENT、WITH/USING、来源模板和空白节点构造分别保留；ADD/COPY/MOVE 不改写为普通 RDF 更新。WHERE 直接接续原 update 的 group 翻译，保留未简化的连接及尚不存在的 query 分析事实。解析成功前不会交付执行 AST；未解析前缀保留原词法记号并在整段解析后拒绝，不能作为可执行 IRI 泄漏。

独立原版104组/884个动作和102个翻译输入留在 source-update-original fixture。接收当前只覆盖95个成功翻译的操作与模板、5个 WHERE 结构、5个原异常构造，以及空请求/来源身份控制。随机空白节点按实际原版 parse 阶段构造记录回放，不据查询答案制造节点。原观察器的失败和第一次接收失败另有原件。

完整 source UPDATE 执行仍需接入同一 DatasetSession：原版的 union/default 图作用范围、空图历史、Variable/generalized 后端项、实际 WHERE 回读、局部写入后失败、缓存和 revision 边界、LOAD/USING 的显式资源授权与恢复均未因此完成。普通 native 更新的整批原子合同不能被改写。该开发回放不证明方法收益，也不表示全19模块、全部平台/公共 wrapper、工程验收或正式安装完成。

# 完整内容身份与 SHA256 执行后端

工程本体规定来源、对象、合同和构建证据所用的内容身份。ggen 生成约束与验证说明，Rust 执行完整字节校验；RRSI 依据实际反馈比较实现改进。本次改动不产生工程知识规则升级。

共享 SHA256 实现锁定为 RustCrypto `sha2 =0.10.9`，启用官方 `asm` feature，仍输出相同的 64 位小写十六进制摘要。原实现已经采用 dev opt-level 3，但 ARM64 上未启用 asm feature 时使用软件后端。启用后，原库中的 Rust ARM64 实现检测 CPU SHA2 能力，支持时使用硬件指令，否则回退到软件；没有增加调用方强制 CPU feature。[上游变更记录](https://docs.rs/crate/sha2/0.10.9/source/CHANGELOG.md)

一次直接升级到 0.11.0 的实际编译因返回值缺少原 LowerHex 格式化接口而失败，候选及其失败输出已保留。当前方案保持原调用方代码和 API；`sha2-asm0.6.4` 的上游汇编依赖经现有 cc 构建边界执行，其来源、完整静态库、编译和加载证据仍须在完整原生构建中验证。[上游汇编实现](https://github.com/RustCrypto/asm-hashes)

`oe-core::fingerprint_file` 的完整读取、大小上限、普通文件及符号链接边界、读取前后大小与修改时间检查保持原实现。大小或修改时间相同不能替代读取内容。调用方继续核对预期 SHA256 和随后再次打开的文件身份。wire、凭据、供应商、资料、模型、发布包和本体运行时的摘要调用使用共享依赖；API 和摘要含义保持一致。

独立固定预期包括空输入、abc、百万 a，以及 SHA padding 和 64 KiB 读取边界。文件检查覆盖大小上限、同大小同修改时间的内容变化、目录、叶路径与祖先符号链接，以及 Unix FIFO。私有实验保留改动前后相同输入、实际 Rust 程序、全部摘要与原始计时分布。局部哈希计时不能代替完整构建结果。

当前验收继续保留单阶段 1200 秒、同一 owner 的一份 3600000 ms pair 预算，以及两个完整原始镜像的字节、调试信息和签名检查。四个中立 Semantica crate 的传递依赖不得引入 oe；全库 13494、19 模块、19 协议、22 owner，前端、服务端、SDK、provider 和各平台范围保持原要求。当前宿主上的有限测试不证明其他平台已执行，也不证明六本书、实际工程项目交付或正式发布完成。

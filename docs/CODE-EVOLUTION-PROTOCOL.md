# Fixed local code comparison profile

Engineering ontology and Rust Semantica share the same system. This initial
protocol compares source-bound code artifacts; Project truth, package policy,
controlled version history and engineering adoption remain with their existing
owners. The skill user entry remains oev2; the additional executables are internal
build/replay assets.

The same annotated specs/engineering.toml produces engineering DTOs and ports
through the locked actual ggen tool. oe-evolution freezes the driver, external
evaluator, independent cases, full public source manifests, source-bound
normalizers, generated products, build conditions, tools and both runner binaries.
Each root builds its own normalizer and runner. Driver source validation always
uses its own compiled root, and candidate source changes do not rebuild or replace
the frozen driver/evaluator.

oe-code-evaluator links IO and generated contracts, with no semantica-runtime,
oe-kernel, oe-design, oe-evolution or runner dependency. The internal runner calls
the actual RDF query, SHACL and Datalog APIs. It receives generated invocations,
without expected outputs or scoring fields. A returned score has no authority.

First-profile runtime cases are synthetic development cases, and a preserved
original MINUS initial-binding one-row counterexample. They are a separate fixed
denominator from the 19 frozen protocol requirements. Missing/failed/partial slots
stay visible. Explicit unsupported may prevent a silent wrong answer while still
failing the original required behavior. Local elapsed time and output bytes are
observations; absent provider usage, total engineering cost and unmeasured
pre-execution resources remain unknown.

The comparator supports strict JSON and typed SELECT bags, retaining duplicate
multiplicity, projection names and unbound versus empty literal distinctions.
Graph isomorphism, domain unit normalization, randomized improvement, independent
industrial transfer and real native/backend execution are not covered. SHA
domains for source files, generated products, executable files, oracle bytes and
manifests remain separate.

Oracle assets live in a distinct read-only private directory. Executable/source/
input/oracle identities are checked before and after execution. This local
same-user process boundary is not an OS sandbox for hostile candidate code.
External crate source caches, transitive features, toolchain native libraries and
unlisted environment remain explicit closure gaps. A bounded manifest and
compiled-source match do not prove the full original Semantica migration.

Existing controlled-version code in the architecture closure is the sole owner
of version selection. This branch has no whole-code adapter to its select/use/
feedback/recover lifecycle. owner_connection returns not_connected for each;
comparison results grant no activation, package promotion or engineering adoption.
learning.rs executable/evaluator guards are unchanged. Failures and original
artifacts remain under private var maintenance records.

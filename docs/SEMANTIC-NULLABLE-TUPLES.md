# 同一查询执行器中的值与字段存在性

这是完整 Rust Semantica 的内部基础增量。它修改现有 spareval 执行器的 `InternalTuple`，让“字段缺失”“字段存在但为 None”“RDF 值”和“返回的错误对象”分别存在。没有增加第二个 Dataset、查询解释器或公开查询版本；正式支持范围仍以实际发行回执为准。

工程本体中的来源、条件和未知不能在程序执行时被悄悄合并。因此，规范在 `specs/modules/semantic-nullable-tuples.toml` 定义字段存在性、投影、连接、去重、初始参数和结果输出的边界；锁定 ggen 生成合同索引和检查映射，Rust 在原执行路径实现。实际测试与原始观察再用于检查改进是否有效。

| 已接入原执行路径 | 本增量的行为 |
|---|---|
| 元组及普通连接 | 比较完整字段值；相等项保留原算法选择的表示。右侧覆盖合并另有明确操作，不能当作原 RDFLib lazy join。 |
| 投影、UNION、DISTINCT、哈希键、MINUS | 保留实际字段集合；空行与含 None 字段的行不同。MINUS 同时检查字段交集和值兼容。 |
| 图模式赋值 | 空字段不能作为可任意覆盖的缺失字段。 |
| 旧表达式变量入口 | 只有缺失字段可以读取初始参数；显式 None 不会偷偷恢复成初始 RDF 值。 |
| SELECT 结果解码 | 先保留完整内部字段，再转到既有结果格式；旧 RDF-only 格式无法表达 None 或错误对象时明确拒绝。取消和数据集错误继续传播。 |

新增测试使用同一解析器、计划器和执行器，并在内部输入边界注入明确字段值。这证明选定执行边界能承载这些信息，不能当作用户已能运行完整 nullable 查询。源推导的有限表与原程序的查询观察分别保留。返回错误采用 Rust 对象身份；原程序异常的分配、文本和聚合行为尚不能据此判为一致。

后续[表达式与聚合增量](SEMANTIC-NULLABLE-EXPRESSIONS.md)以及[数值与 SourceAggregateV1 增量](SEMANTIC-NUMERIC.md)在同一执行器内分别接通返回/抛出错误、COUNT/SAMPLE、SUM/AVG、原始分组键与显式/隐式空组的有限合同，各自保留真实来源和测试身份。初始上下文 thaw/forget/remember、原算法的连接选择、全部函数和聚合、原始结果与 Semantica wrapper 的不同输出仍未闭合；不能把这些后续实现当作本文基础轮次的历史验收。全部闭合并对照独立原预期后，才开放完整 nullable profile；旧 `/1–4` 的合同和原观察不改签。

上游来源、许可证及前一版字节身份见 `vendor/spareval/NULLABLE-PATCH-PROVENANCE.json`。完整 13494 项迁移范围、19 模块/协议和工程采用条件不由这项基础增量关闭。

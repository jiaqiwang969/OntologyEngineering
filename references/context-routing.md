# 情景分析与能力协同

根入口负责把当前问题交给适用能力，并接回结果。选择从本轮要支持的决定和产出
推导，不能只按名词匹配。讨论“仿真记录”可能只需审查旧证据；提到“本体”也可能
只是在解释概念。用户已明确指定的方法与范围仍须遵守。

## 先形成有范围的问题

续接目标、当前对象与修订、所需功能、证据现状、未决主张、资源限制和已有决定。
新消息中的指代能由历史解析时直接接续；缺少关键上下文时保留未知并只问必要信息。
以前停止的工作不能因相关词再次出现而重新启动。

由当前差距推出下一项工作：是需要取得原生事实、解释证据、比较方案、组织验证，
还是需要澄清知识表示或修复语义接入？一个情景可同时需要几种能力；小任务也可由
根入口直接回答。没有选中专业模块，不等于用户任务不能处理。

## 按产出匹配能力

| 本轮需要的产出 | 起点与进一步选择 |
| --- | --- |
| 几何、图纸、装配或机构的原生结果 | [cad-agent](../skills/cad-agent/SKILL.md)；制造条件确实影响结构时才联动工艺 |
| 工艺路线、设备供应商、检验、资源成本或交期比较 | [manufacturing-process-cost](../skills/manufacturing-process-cost/SKILL.md)；保持对象、数量、费用与时段口径 |
| 对测量、模型、比较或来源支持范围的判断 | [engineering-evidence-methods](../skills/engineering-evidence-methods/SKILL.md)；把缺证、适用性和实物结论分开 |
| 概念解释、对象关系、CQ 或项目知识表示 | 根方法与两卷书的相关来源；先复用现有表达，项目事实留在私有工作区 |
| 运行已有语义检查，或准备/修复 Semantica 接入 | [统一合同](semantic-engagement-contract.md)；需要初始化方法链时读[初始化与采用](../docs/method-bootstrap.md) |
| 可复用表达或判据缺口的语义候选与治理 | [domain-ontology-loop](../skills/domain-ontology-loop/SKILL.md)；先确认实际缺口及完整增量，`no_delta` 可结束学习分支 |
| 编写新工程书，或修订已有书稿与示例 | 新书用 [standard-to-book](../skills/standard-to-book/SKILL.md)；两卷书修订使用完整版中的 `references/book-authoring-workflow.md` 及实际书源，其他书沿其受控来源；普通标准解释不必编书 |

表中是能力入口，不是完整任务枚举。内部能力不能满足具体工作时，从当前会话可用
skill 和工具中发现相应专长，读取其实际合同，再按需协同。不能因同名技能、旧缓存、
分发模板或归档副本存在，就把它们当作当前可执行入口；根目录下的维护正本是本地入口。
设备与软件是否可用、数据能否交给外部服务，另按当前任务的事实和授权核对。
完整版与核心版携带相同的路由实现、能力说明和 instruct；核心版省去两卷书源码。
指令文件中的 `method_sources` 保留方法出处，运行路由不需加载这些书稿；需要修订或
查证书内原文时取得完整版或受控书源，不能在缺失时声称已阅读。

匹配时分开保留：**需要此能力、已找到入口、具备输入与运行条件、获准执行**。
模型判断需要 CAD 不代表已取得图纸；能发现包不代表项目已采用它；工具缺失也不
自动证明任务不需要这项能力。只阻断依赖缺失条件的工作。

## 协同围绕交接组织

每项工作说明要解决的问题、输入对象与来源、输出证据、依赖和回到哪个决定。
例如盖板变形：工艺分析装夹条件 → CAD 比较结构或基准变化 → 证据方法检查对照与
适用性 → 更新工时和检验方案；实际已有的结果可以缩短或改变这个顺序。

模块间共享项目 ID、对象修订、条件和证据，不重复建立事实正本。不依赖前一结果的
读取或分析可并行；必须使用前一步输出的工作顺序执行。多模块协同不自动要求多 agent，
是否委派仍遵守当前会话规则。收到失败、反证、预算变化或新约束后，重审受影响的
交接和结论，保留未查明的依赖。

## 本体化与 Semantica 分层介入

- **方法与项目表示**：澄清功能、对象、身份、角色、关系和 CQ；整理项目 ABox 来源，
  不因多一条事实、别名或记录就产生行业包版本。
- **锁感知发现**：核对当前 source lock、runtime 与实际 package/capability。发现可用
  能力不构成项目检查通过；无须正式执行时保留原因与 `not_run`。
- **接入准备**：缺少或失效的 runtime、工作区、证据身份、task 或 binding 按实际缺口
  修复。日常使用已有正常审查不需要重新初始化；来源变了先保留快照，再准备当前输入。
- **正式执行**：用适用的已采用包及有界证据检查本轮主张；缺绑定、缺证据或能力不支持
  时，只阻断相应正式执行。查询、约束与规则的裁定仍全部在 Semantica。
- **行业本体演化**：确认是可复用语义缺口后才进入候选与治理。项目缺证、模型误判、
  资料提取失败及 skill 路由不当分别修正，不拿本体升级代替。

## Jev 的候选路由与效果测试

Jev 使用提前维护的[工程本体 instruct](context-routing-instructions.json)，每一项 Choice
都实际携带完整方法指令与该能力边界；不能只把方法写在供主 agent 阅读的文档里，
也不在运行时临时改写成关键词分类。指令从第一卷方法论与 Agent 回路、第二卷主张
与范围方法及共用工程证据方法提炼，来源列在同一文件中；这里是操作指令，没有新增
正式本体检查器。问题、能力说明和指令分别有摘要，调整后另起运行记录。

指令依次约束意图与 CQ、对象与情境、必要功能与机理条件、证据状态、ABox/TBox、
变化影响及能力交接。这些约束用于判断下一项工作需要什么；数学求解、完整机制推导
及最终工程决定仍交给对应工具和主 agent。任务只需概念解释或文案修订时，指令也须
允许根入口直接完成。

Jev 接受情景和明确问题，分别判断多项能力是否需要。每项保留“需要／不需要／
信息不足”，不把整项任务压成只能选一个 skill。情景必须含先前工作状态及最新请求，
不能只送最新一句话；每个能力附适用产出与边界，而不只给名称。

这是操作选择的候选判断，不构成新的工程语义裁定。主 agent 核对选择、上下文、
依赖、实际可用性和权限后执行；高分不能增加权限，“不需要”的误判仍可能漏掉义务。
已有批量接口的 P-ID/P-SCOPE 等是资料审查模式，不可直接改名成 CAD 或 skill 路由标签。

触发根 skill 后默认执行下节调用，主 agent 读取路由候选后组织实际工作；
[资料判断接口](../docs/judgment-intake.md)处理来源与主张的批量初判，两者按各自目的使用。
路由实验应单独冻结情景、能力说明、问题、精确模型、适配器与调用前的参考，
保存原始请求/响应、缺答、分歧及用量。参考答案不能进入模型输入，也不能在看到输出
后改成匹配答案再宣称盲测。未知输入、协同任务、停止指令和缺失能力都应被测到。

分别报告接口完成率、情景路由的漏选/误选、实际交接与产出质量。合成场景或 agent
参考只能用于开发诊断；真实项目质量、人工复核成本及独立准确率需另外取证。调整后
保留原失败记录，再用未参与调整的情景复验；不为测通接口改动 Semantica 的正式问题目录。

## 默认调用

由 agent 在私有任务工作区准备当前上下文，调用前删去不必要的私密细节；用户已禁止
资料外发时保持该边界。以下是输入结构，实际内容从当前任务续接，不让用户手填：

```json
{
  "schema": "ontology-engineering.context-input/v1",
  "task_id": "current-task-id",
  "context": "已有目标、对象版本、结果、停止指令和约束的必要摘要",
  "request": "用户本轮要解决的问题",
  "external_skills": []
}
```

```bash
python3 scripts/route_engineering_task.py \
  --input /private/task/context.json --output /private/task/routing-001
```

该入口仅用 Python 标准库及现有 Jev 适配器，即使正在准备 Semantica 安装，也可先
进行情景判断。凭据沿现有本地文件选择规则读取，不进入任务文件或日志。模型使用
[能力说明](context-capabilities.json)中的精确版本；每次保留上下文、问题、代码、
能力入口摘要及原始调用记录。能力说明属于操作路由元数据，不拥有工程语义裁定权。

需要外部专长时，从当前可用 skill 中选出相关条目，向 `external_skills` 增加
`id`、实际 `skill_path` 和描述本轮适用能力的 `capability`。入口核对文件存在并保留
摘要，只向模型发送情景与能力说明，不发送本机路径。若尚未发现外部入口，
`external_specialist` 候选提示主 agent 继续发现，不能当作已调用了具体外部 skill。

读输出 `routing.json`，按 `candidate_routes`、`uncertain_routes` 和各项 `routes`
核对所需输入、依赖、来源可用性及权限。实际采用的模块、先后关系和与模型不同的
决定记入现有任务记录；简单任务用几句话即可。然后进入对应入口执行并接回证据，
不止于列候选。没有专门模块被选中时，继续根入口的解释或当前工程工作。

`completed` 仅表示所有路由问题已返回，不表示选择正确或任务完成。`partial` 或
`unavailable` 保留未答问题，不把它们算成“不需要”；重试有界且只补未答项。
模型回答“信息不足”与服务失败分别记录。新上下文改变任务需求时用新输入及新目录
重新路由，旧记录留作历史；同一轮每个内部工具调用无需再次触发路由。

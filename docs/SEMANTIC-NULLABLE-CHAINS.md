# 保留算式的原始边界

这是接续[表达式与聚合增量](SEMANTIC-NULLABLE-EXPRESSIONS.md)的私有实现。它让同一解析器、计划器和 Rust 求值器保留“一串算式在哪里开始、在哪里结束、哪些部分被括号包住”。默认入口仍使用原来的解析和执行方式；没有新增公开 `/5`，本轮是否通过及是否安装以当前源码绑定的接收回执为准。

例如 `1 / 0 * 1` 和 `(1 / 0) * 1` 数学上都出错，但原 RDFLib 的程序行为不同：前者在同一个表达式边界内返回除零错误；后者先返回内层错误对象，外层再因为拿到的不是数值而返回类型错误。旧二叉算式会把这两个输入降成同一结构，之后无法可靠恢复。因此真实语法规则只在显式私有入口中保留非空的加减链、乘除链；括号里的非空算式保留为子链，单独的 `(?missing)` 仍是变量，不凭空增加错误捕获。

| 位置 | 本轮实现边界 |
|---|---|
| `spargebra` 解析器 | 非默认 `rdflib760-nullable-internal` feature 下的显式隐藏入口保留原顺序与括号。原 `parse_query`、现有兼容入口及 update 仍维持旧策略。 |
| `sparopt` 计划器 | 复用同一计划器，在两种代数之间逐项传递链、运算符和嵌套。新变体放在枚举末尾，避免扰动旧表达式哈希。遍历覆盖全部操作数。 |
| 表达式编译器 | 仍由原来一个 AST 分派编译；每条链只捕获一次 SPARQL 错误，内层链保持自己的边界。到达旧表达式编译器的链和手工空链明确拒绝。 |
| 数值计算 | 复用既有六个算术内核，保存一条链中间的有界整数及 Decimal 类型状态，最后形成结果值。来自已知算术子节点的整数值 Decimal 可以继续参与外层计算。 |
| 查询消费者 | 通过同一 COUNT/SAMPLE、Group、Extend、FILTER 和结果承载路径接收值或失败；不能把新解析结构当作上下文、连接或输出 wrapper 已全部完成。 |

求值顺序也属于语义：先读取并适配第一个操作数，再按顺序读取全部后续操作数，最后才进入数值运算。第一个变量抛出 NotBound 会直接停止；子表达式返回一个错误对象则会继续读取外层后续项。因此 `1/0*?fatal` 中，后续读取的真实执行失败可能先于除零计算出现。全部原始值取得后，各项数值检查随运算依次进行，不能提前把所有后续值都检查一遍。这些边界来自保留源码的推导，没有运行旧 Python 来制造新“原始通过”记录。

当前数值范围仍有限：直接输入只接通有界整数，除法的每个中间商都必须是整数；只有带编译器算术来源标记的整数值 Decimal 子结果可继续参与。直接的 `(2*3)+1` 可以计算；先 `BIND(2*3 AS ?v)` 再计算 `?v+1`，重读变量没有该来源标记，仍明确失败。外部 Decimal、浮点、日期、数值子类型与词法细节、Python 任意精度整数及 Decimal 的完整精度和舍入尚未完成。`1/2*2` 会在中间分数处拒绝；溢出明确失败；需要保留负 Decimal 零的 `0*(-1)` 等计算也明确拒绝。裸写 `-9223372036854775808` 的当前语法路径同样尚未接通，不能据内部有界整数说所有 i64 源码写法都受支持。这些是暂时的实现缺口，不能包装成原程序的限制或最终公开兼容规则。

私有接收路线通过非默认 feature 显式接通 runtime → spareval → spargebra，并跳过整个查询优化器。计划器的单个 chain 分支原样返回、类型推断保守返回 ANY，只能防止局部误改；整个优化器仍可能移动或消除其他求值，不能因为有这两个保护就重新启用。例如普通 prepared query 的死分支可能在编译前被消除，所以“到达旧编译器时拒绝链”不等于“普通 prepared AST 一出现链就整体拒绝”。

`sparopt 0.3.7` 从锁定原始 crate 保留到 `vendor/sparopt`，版本和依赖图不因此升级。原包摘要、上游提交及两份许可证见其 `UPSTREAM-PROVENANCE.json`；本地改动的前一版源码、来源和限制见[本轮 provenance](../vendor/spareval/NULLABLE-CHAIN-PROVENANCE.json)。源码模块 `semantic_query_planner` 是现有 `semantic_evaluator` 的子组件，不增加另一套事实或决策权威。它的文件、来源及检查进入同一编译来源与真实 ggen 映射；旧回执保持原身份，不能替新源码背书。

这仍遵循“工程本体论规定含义 → ggen 生成合同 → Rust Semantica 执行 → 根据反馈检验改进”。本轮补的是不能丢失的程序含义及来源关系。原上下文 thaw/forget/remember、完整连接及分组语义、完整数值和函数、原始结果与 Semantica wrapper、13494 项完整迁移和工程采用仍分别验收。

# 读透高价值资料，筛选对话中的有效信息

先问“这条信息会帮助判断什么”。优先读能补全未知、约束方案、纠正假设或支持决定的内容；一条简短补充也可能比整份介绍更有价值。文件格式、篇幅、排版和发送次数不决定重要性。客户提供的原件往往包含外部检索找不到的订单条件、实际资源、工时与费用边界。

本规范用于资料取舍和知识获取；不建立自动评分器，不把筛选结果当事实批准。先查已有材料和历史答复，再问仍影响决定的缺口。

## 对话怎么筛

| 信息情况 | 处理 | 必须保留的区别 |
| --- | --- | --- |
| 寒暄、纯重复表述、与当前决定无关的转发 | 不进入本轮工程摘要；原对话按项目留存方式保留 | 暂无工程影响，不等于原记录应删除 |
| 同一附件反复转发 | 核内容与版次后合并引用，保留接收来源 | 转发次数不增加独立证据；同名文件可能已变更 |
| 新要求、数量、交期、预算、交付范围或能力线索 | 提取具体条目，链接对象及受影响决定 | 区分原话、解释、估算和已确认范围 |
| “只是粗估”“按旧图算的”等限定或纠正 | 与被限定的原主张绑定，重查依赖 | 很短的消息也可能使旧结论降级或重开 |
| 冲突、异常值、否定、犹豫或含糊指代 | 标为冲突或待澄清，保留双方来源与语境 | 证据可信度低仍可能有重要调查价值；不当噪声丢弃 |
| “收到”“好”“已发”及沟通状态 | 按语境更新接收或发送状态 | 不扩展成方案接受、技术通过或问题全部关闭 |
| 当前无影响但可能改变后续采购、量产或验收的信息 | 留在后续线索，注明适用阶段与重新查看条件 | “暂缓处理”与“已无效”不同；决定改变后重新筛选 |

一条消息可同时包含寒暄、事实、条件和提问，按内容拆分，不整条丢弃。说话人、回复对象、引用上下文、时间和版次用于判定含义；不能只抽数字和肯定句。跨会话沿用已经确认且仍适用的答复，避免重复追问。

“无效”要有具体理由：与本轮决定无关、已核实重复、或某结论已被有依据地替代。旧版及其失效原因仍可用于追溯。不能按职位、语气、消息长短或是否符合当前方案判断有效性；商业、排产、责任和沟通变化也可能改变工程选择。

## 哪些资料值得先读透

| 资料所含关键内容 | 能帮助判断什么 | 深读时查什么 |
| --- | --- | --- |
| 客户要求、问题回复、图纸和变更说明 | 做哪个版本，交付什么，怎样验收 | 原始要求与转述、回复覆盖的子项、尚未批准的解释 |
| 明细成本、工装清单、制造节拍 | 哪项费用主导，小批量自制是否划算 | 单位、数量基数、一次性/每批/每件、公式、包含项、估算与实测 |
| 设备盘点、加工记录、检验记录 | 哪些资源可复用，还要验证什么 | 身份、状态、适配条件、可调配与已验证能力的边界 |
| 工艺总结、流程图、经验记录 | 哪项要求驱动哪道工序，旧经验何时适用 | 对象状态、制造依赖、检验阶段、例外与返修路径 |
| 供应商调研、报价及技术答复 | 采购什么，谁可能能做，同范围下多少钱 | 宣传/承诺/实绩、图纸版次、币税单位、有效期、交付及排除项 |
| 方案、评审意见、现场回填 | 什么改变了，原判断是否成立 | 针对的版本和条目、实测条件、受影响输出、剩余未决项 |

高价值是相对于当前决定的优先级，可信度和适用性另行判断。某份报价不能支持最终金额，仍可能揭示之前漏算的必需工装；一份过时流程也可能暴露本次迁移需要核实的前提。

## 读透到什么程度

1. **定位原件。** 保留文件身份、版本、来源和适用对象；文档日期、接收时间、要求生效时间分别记录。原件缺失时注明转述，继续可支持的部分分析。
2. **检查决定相关的细节。** 表格核对明细、公式引用、单位、税口径和汇总关系；按需查看备注、隐藏表及外链。演示文稿还要查看包含文字或流程的图片、图例、箭头、注释及相关备注；纯文本提取可能漏掉关键工艺。缺附件、外链或无法读取的区域明确列出。
3. **关联和核实。** 将关键内容接到要求、产品/版次/状态、工序、检验、设备、供应商或费用项。用其他原件、历史答复和已有结果交叉核对。汇总与明细不符时保留源值并单独复算，不静默修原件。
4. **说明它改变了什么。** 写清新增事实、被证实/限制/推翻的假设、工艺及成本等下游影响，以及仍无法确定的部分。已有结论得到支持而无需修改，也要说明支持范围。
5. **把下一问缩小。** 只问现有资料没有回答、且会改变当前决定的问题。附上已有理解和需要确认的具体边界；普通业务语言即可。

数字按具体参数追到原始来源或显式假设；同一公式链中的多份表和报告不构成独立印证。提取到的公式、缓存与本次复算结果分别标识，成本的批次和区间处理见[估算依据](estimate-basis.md)。

按本轮决定选用深读范围，不为穷尽所有附件而停住方案工作。尚未读的部分留下定位，不能在只读了摘要时写成“全部核完”。收到补充后先做差异比较，再重查受影响的链。

## 怎样进入记录与迭代

复用 [发现记录](../assets/templates/discovery-record.json) 和 [修订记录](../assets/templates/revision-record.json)，不为每个文件另造一套表。最小结果是一条可追溯的关系：

> 来源及页/表/单元格/消息位置 → 原话或值及条件 → 对象与版本 → 支持或限制的判断 → 工艺/资源/成本/交付影响 → 待核问题及后续触发条件。

已消化资料按具体主张续用：记它已支持/限制哪些判断、哪些部分尚未处理及何时重查。同一附件可以部分采用、部分待核；再次转发不等于新增独立证据。新信息先定位受影响工序、资源、费用与未决项，再读相关增量。资料处理的成果是[工艺和成本判断的推进](requirements-process-cost.md)，不以逐文件重新分析为目标。

`gap.already_searched` 记录已查范围；`response` 留原话、解释、证据及冲突；`update` 留支持/反证与下游影响；变化进入修订记录。历史对话和私有原件不迁入通用 skill；高价值不等于可公开。

方法效果看重要遗漏是否减少、重复询问是否减少、方案修正是否有依据。信息数量、读了多少页、删了多少消息都不能单独证明有效。

## 脱敏实践模式

以下承接 [连续演变案例](case-evolution.md)，只保留真实实践的资料作用，不携带原始产品、参数、身份或报价。

| 后来取得的资料或反馈 | 原先尚不清楚的事情 | 由此推动的工作 | 仍不能据此确定 |
| --- | --- | --- | --- |
| 工艺总结及其流程图片 | 旧经验里的控制为何存在，是否适用本次情境 | 按要求、对象状态和检验阶段重新解释流程 | 不能直接沿用全部参数，也不能仅据情境差异删掉检验 |
| 产品清单、模型及报价 | 产品能否对应，价格指向哪一范围 | 建立身份对应，逐项核版次与交付边界 | 编号相同不能证明报价已覆盖当前版本 |
| 明细成本与内部设备盘点 | 粗估如何形成，哪些环节可自制 | 拆出费用、节拍、工装及资源线索，细化条件预算 | 机器在册或可调配不证明质量能力和真实节拍 |
| 对旧估算可靠性或顺序含义的补充 | 原结论是否用错了证据等级或“检测”的含义 | 降级或重开相关结论，定位对象和状态后再修订 | 不把一句含糊反馈扩展为所有产品的通用规则 |

正常对照：同版原件中已回答的税口径，应直接复用并引用。反例：若新版报价排除了某道必需工序，沿用旧版总价比较会遗漏成本，即使文件名称没变也需要重查。两者用于检查方法，具体项目仍取其自身证据。

理论锚点：第一卷第 3 章将业务表单、工艺规程与专家叙述作为知识获取来源，并强调保留原话、补全条件、回读确认；第二卷的主张、身份、变化和依赖镜头帮助界定证据能支持什么。路径见 [书源锚点](theory-anchors.md)。本轮明确资料处理方法，沿用已有证据与依赖语义，未新增行业工艺规则。

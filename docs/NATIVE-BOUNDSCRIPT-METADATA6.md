# Current build-script metadata domain

Explicit policy `cargo_1_95_and_current_bound_build_script_metadata_f2d3ce0bd/3` adds a separate actual wrapper admission branch. The original direct-Cargo compiler/native-link domain is unchanged. The wrapper observes the living parent with libproc, checks the current locked package source and original `package.build`, and associates the parent with a unique completed native invocation from this same stage. The actual Cargo-created `build-script-build` path and separately named linker output must have equal current bytes and mode; no mapped-image/startup attestation is inferred.

Only complete vectors `--version`, `-vV`, `--version --verbose`, and `--verbose --version` are supported. A metadata intent records `metadata_only_before_exec`; it is not an exit receipt, compiler/native link permission or owner observation. Actual compilation probes in original proc-macro2/autocfg build scripts remain a separate required domain and are refused by this branch. Original PAIR06 lacked the rejected wrapper's live PID/complete argv because the historical guard preceded recording; later source observations cannot backfill that evidence.

The final full capture checks all retained metadata bindings against their current source/stage/process records, without querying or reviving historical PIDs. Full two-sided five-stage artifacts, complete bytes, debug, signature and original deadline remain required. Source checks and OS exec are not atomic; synchronous I/O/CPU and hard return time remain unknown.

Native6 now pins the complete original `-o` image in the producer's typed process binding immediately after successful actual native process return. Metadata admission compares the living parent and Cargo-named output against that earlier producer pin and binds its complete record reference. Two later equal files are insufficient. Failed links and archive indexing have no image pin. This records physical file content at a concrete return point, without declaring mapped-process equivalence or OS-atomic lifetime protection.

For this explicit new policy, a full capture also checks every retained pre-admission raw entry has its matching unchanged compiler intent. A build script catching an unsupported wrapper request cannot make that unresolved refusal disappear from full execution closure. Before-exec entries still do not establish independent metadata exit or complete loader/startup attestation.

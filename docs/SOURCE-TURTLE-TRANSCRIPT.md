# Turtle 全文、读取过程与状态的对应

本增量接续既有实现，在原 source Memory、命名空间与 Turtle Writer 内记录实际读取。完整 Rust Semantica、原 63 项、Project/work/Harness、CAD、制造检验和最终计量义务继续保留。

`SemanticSourceTurtleWitness4` 是显式内部见证。它绑定完整序列化请求摘要、准备阶段实际三元组次序、命名空间准备前/准备后/写出后状态、Rust 资源记账、完整读取记录与正文摘要。`SemanticSourceTurtleRead4` 区分模式扫描、原始节点比较、真值和字面值缓存判断；不从规范化 RDF 重新推断缓存。共享结构由 specs 经锁定 ggen 生成。

执行使用同一 DatasetSession 和 source Memory。写出器通过读取接口调用原值和索引；排序继续调用原 CPython 排序实现。接收仅重放读取记录，使用同一个写出器及命名空间算法，逐次核对请求的参数、全部模式匹配内容、完整正文及状态关系。命名空间副本只用于检查，没有创建或登记第二个权威 Dataset。

外部提供的完整 source quads 用于核扫描覆盖；其来源必须另行绑定。子模式的原索引次序、比较和缓存事实不能仅由三元组集合证明。一致改写来源、记录与正文可能通过内部关系检查，因此实际请求、程序、原始结果流和来源身份仍是公共进程接收的必要门槛。内部检查不授予工程采用或 RRSI 收益。

每次捕获最多 32 MiB，沿用原写出/深度/工作量限制，并接收已有绝对截止时间。失败或捕获不完整时不返回成功的完整见证；已发生的命名空间变化保留，不伪造回滚。公共批次对失败过程的完整表达、步骤前后/观察后状态绑定，仍需显式公共 `/4` 接续。原 `/1–3` 的 NT/NQ 准入不变。

验证使用此前已冻结的原版全文和错误，不以自生成结果充当独立预期。另核正文、请求、读取顺序/参数/覆盖/答案、命名空间及预算的篡改拒绝，验证一致替换的证明边界。Mac、Windows、实际 host/CLI、新根安装、正式选用分别取证；以私有维护回执为准。当前代码没有启用公共 `/4`，正式入口继续从维护状态核对。

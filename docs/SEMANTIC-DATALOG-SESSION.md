# 连续规则推理与失败后的状态

`kernel datalog-session --input REQUEST.json [--output RESULT.json]` 在一次请求内使用同一个 Rust `DatalogReasoner`，按顺序添加事实或规则、导入图快照、推导、查询、清空和观察。它用于核对“前一步留下了什么，下一步基于什么继续”；调用结束后不保留引擎，不更新 Project，也不批准工程结论。

输入身份为 `semantica.datalog-session-request/1`。`actions` 中每个动作包含唯一的 `action_id`、`operation`，以及对应输入：

| operation | 输入 | 行为与原始依据 |
|---|---|---|
| `add_fact` | `fact`，字符串或字典 | 新事实令推导状态失效；重复事实或不认识的字典不改变它。`inserted` 是 Rust 对实际新增的观察，原 Python 方法返回 None。 |
| `add_rule` | `rule`，字符串 | 添加原有限安全语法的规则；重复规则仍按原库保留，推导状态失效。 |
| `load_graph` | `graph`，字典节点/边快照 | 先边后节点，逐条加入；后面一条失败时，前面已加入的事实仍保留。导入会累加，不自动替换旧图。 |
| `derive` | 无 | 调用原有界推导器；`derived` 只有实际到达固定点才为 true。既有 Rust 资源失败保持事务性，不宣称复刻原库无界执行中断状态。 |
| `query` | `query`，pattern 和 bindings | 按原库顺序，先按需推导，再检查查询语法。因此查询失败也可能留下已完成的推导。无规则的查询不强制设置 `derived`；完全无变量的结果 `[]` 不作为 ASK。 |
| `clear` | 无 | 清除全部事实、规则、索引和推导统计；不重置本请求输入限额。 |
| `snapshot` | 无 | 读取事实集合、规则数量和实际推导标志；观察本身不触发推导。 |

请求还包含原 `SemanticDatalogBudget` 和明确的 `on_error`：`continue` 记录失败后继续后续动作；`stop` 记录失败，并将余下动作标为 `skipped`。每一步都返回真实的 `state_before` 和 `state_after`，失败另附结构化错误。成功记录失败过程不等于该动作成功，`all_actions_succeeded` 单独说明全部动作是否完成。

CLI 对全部动作完成返回 0；包含动作失败或跳过时返回 1，同时保存完整历史；非法请求或输出超限返回 2，不发布截断历史。当前接口没有自动重试、外部服务或跨请求持久化。

现有 `kernel datalog`、`kernel datalog-graph` 的协议和一次性失败语义保持。原库导入和查询的状态时机由同一算法 owner 的显式方法承担；原 `load_from_graph` 的事务性导入和 `query` 的先校验方法仍保留。事实解析、数值符号、索引、规则和推导均复用原实现。

完整请求最多 1 MiB、32 个动作、合计 4096 条事实/图记录和 256 条规则。动作只能携带其对应输入，图记录必须是字典，动作 ID 为 1–64 字节的 ASCII 字母、数字、下划线或连字符。原下调预算分别约束每次推导与每次查询，不能解释为累计匹配次数或墙钟期限。完整历史连同最终状态和换行最多 16 MiB；结果过大时明确拒绝。

修改前按锁定原版冻结并核对 22 组历史、94 个动作，包括清空、重复、自动推导、失败后状态和停止/继续。原始输出及错误保留；事实和绑定按原集合语义比较，动作顺序与状态标志精确比较。实际源码、生成、构建、安装和平台资格按维护回执分别核对。

工程使用仍需来源与条件。例如更换依赖图时，先保留旧查询结果，再明确 `clear`、导入新图并重建规则；不能将旧事实残留当作新版依赖，也不能把给定关系的推导闭包当作关系完整或工程采用的证明。完整 Semantica、动态图对象、跨请求存储、原工程验收与 RRSI 收益继续分别验证。

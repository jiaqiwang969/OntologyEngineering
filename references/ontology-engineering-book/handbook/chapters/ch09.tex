\begin{introbox}
\textbf{【导读】}
最后一章把前八章的能力组装成一个可运行的系统。
建议的学习方式是「跑通—修改—扩展」：先按指引跑通 Java 与 Python 两侧，

\section{系统全景}

系统是经典三层：\textbf{本体层}（\texttt{manufacturing.owl}，Manchester 语法的
制造领域 TBox + SWRL 规则）、\textbf{查询服务层}（Java/Jena，
回答第 3 章那组能力问题）、\textbf{推理引擎层}（Python/owlready2 + Pellet，
一致性检查与冲突检测）。Java 与 Python 加载的是\textbf{同一份本体文件}——
知识只有一个权威源，两种技术栈只是两个消费端，这正是第 1 章理念的落地。

本体层的核心是约束公理与规则。设备类层次之外，
文件用注释形式完整记录了描述逻辑约束——它们就是系统的「物理定律」：

\section{跑通它}

Java 侧需要 Maven 引入 \texttt{apache-jena-libs} 4.10+，
编译后运行 \texttt{QueryService}；
Python 侧 \texttt{pip install owlready2}（Pellet 需要 Java 8+ 环境），
直接 \texttt{python src/reasoner.py}。
两侧都跑通后，做两个实验最能加深理解：
在 \texttt{manufacturing.owl} 里新增一台设备实例，观察哪些查询结果变了；
故意制造一个冲突（给运行中的设备派任务），看推理器如何当场抓住它。

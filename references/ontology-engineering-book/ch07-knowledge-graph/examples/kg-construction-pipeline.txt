# 知识图谱构建流水线 - 制造领域
# Knowledge Graph Construction Pipeline for Manufacturing
#
# 目标：把分散在台账、工艺文件、维修日志中的知识
#       统一到本体约束下的知识图谱中

# ==============================
# 1. 数据源盘点
# ==============================
# 结构化数据（最容易，优先做）：
#   设备台账（Excel/MES数据库）—— 设备、型号、功率、位置
#   BOM/工艺路线表             —— 产品、工序、先后关系
# 半结构化数据：
#   工艺规程文件（Word/PDF表格）—— 参数、约束条款
# 非结构化数据（最难，价值高）：
#   维修日志、班组交接记录      —— 故障现象、原因、处置

# ==============================
# 2. 流水线总览
# ==============================
# 数据接入 → 映射/抽取 → 实体对齐 → 本体校验 → 入库 → 增量更新
#    │           │            │           │         │
#    │           │            │           │         └ 三元组库/属性图
#    │           │            │           └ SHACL形状校验（见 kg-quality-shacl.ttl）
#    │           │            └ 同名归一（见 entity-resolution.txt）
#    │           └ 结构化:R2RML映射 / 非结构化:NER+关系抽取
#    └ CDC订阅台账变更、文档批量解析

# ==============================
# 3. 结构化数据：映射式构建
# ==============================
# 台账表 equipment_ledger：
#   id    | name      | model   | power_kw | workcell
#   E0117 | 3号数控车床 | CK6140  | 15.5     | A区

# R2RML/自写脚本映射为三元组：
#   mfg:Lathe_003  rdf:type         mfg:CNCLathe ;
#                  mfg:hasSerialNumber "EQ-2023-0117" ;
#                  mfg:hasPower     "15.5"^^xsd:float ;
#                  mfg:locatedIn    mfg:WorkCell_A .

# 映射要点：
#   行 → 个体（IRI由稳定主键生成，禁止用易变的名称做IRI）
#   列 → 数据属性；外键列 → 对象属性
#   代码表（如状态枚举）→ 受控词表个体

# ==============================
# 4. 非结构化数据：抽取式构建
# ==============================
# 维修日志原文：
#   "3月21日，3号车床主轴异响，检查发现轴承磨损，更换轴承后恢复运行。"

# 实体抽取（NER）：
#   [3号车床]→Equipment  [主轴]→Component  [异响]→Symptom
#   [轴承磨损]→FaultCause  [更换轴承]→RepairAction

# 关系抽取（RE）：
#   (Lathe_003, hasComponent, Spindle)
#   (FaultEvent_0321, occursOn, Lathe_003)
#   (FaultEvent_0321, hasSymptom, AbnormalNoise)
#   (FaultEvent_0321, hasCause, BearingWear)
#   (FaultEvent_0321, resolvedBy, BearingReplacement)

# 抽取技术选型：
#   规则/模板  —— 高精度低召回，适合格式固定的日志
#   NER模型    —— 需标注数据，适合大批量同类文本
#   LLM抽取    —— 零样本能力强，但必须经本体校验后入库（第8章详述）

# ==============================
# 5. 入库前的本体校验闸门
# ==============================
# 每批待入库三元组必须通过三道检查：
#   (1) 词汇检查：类与属性必须在本体中已定义
#       （抽取结果出现 mfg:SuperLathe → 拒绝，进人工复核队列）
#   (2) 公理检查：不得违反不相交、函数性等公理
#       （同一设备两个序列号 → 违反函数性 → 拒绝）
#   (3) 形状检查：SHACL校验必填项、取值范围、格式
# 通过 → 写入；不通过 → 隔离区 + 告警 + 人工裁决

# ==============================
# 6. 增量更新与版本管理
# ==============================
# 全量重建仅用于初始化；日常采用增量：
#   台账变更（CDC）→ 生成三元组补丁（INSERT/DELETE）
#   文档新增 → 抽取 → 校验 → 追加
# 版本策略：
#   本体（TBox）变更走发布流程（语义版本号 + 变更日志）
#   实例（ABox）变更记录到具名图，支持时间切片回溯（见第5章时态推理）

# 工程经验：
#   先打通"台账→图谱"的结构化主干（两周可见效），
#   再逐步纳入非结构化抽取——避免一开始陷入NLP精度泥潭
